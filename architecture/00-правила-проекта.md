# Правила проекта

## Продукт в одной строке

SaaS-тренер для покеристов микролимитов: загрузи HH-файл GGPoker → парсер считает метрики детерминированно → LLM проводит сократовский диалог. Подписка $12/мес.

## Что нельзя сломать

| # | Критическая поломка | Последствие |
|---|---|---|
| 1 | Потерять оплаченную подписку пользователя | Финансовый ущерб + потеря доверия |
| 2 | LLM вычислит числа вместо парсера и ошибётся | Один скриншот в Discord — репутационная смерть продукта |
| 3 | API-ключ Anthropic попадёт в репозиторий | Финансовые расходы на тысячи долларов без контроля |
| 4 | Сократовский вопрос «почему» убран или обойдён | Продукт превращается в трекер — нишевое преимущество исчезает |
| 5 | HH-файлы с никнеймами пользователей утекут | Доверие в маленьком покерном сообществе уничтожено |

## Всегда делай

### Правило 1 — Парсер считает числа, LLM только объясняет — и самопроверяется там, где парсер не может её прикрыть

Все покерные метрики (VPIP, pot odds, SPR, позиция, потери в фишках, тип раздачи) вычисляет только парсер. Результат передаётся в LLM как готовый структурированный JSON. Промпт содержит явную строку:

> «Все числа уже рассчитаны парсером и переданы тебе. Не вычисляй метрики самостоятельно.»

Это закрывает только половину риска. Сам стратегический вердикт «что было бы оптимально» (поле `hands.analysis`) — суждение, которое парсер в принципе посчитать не может: он не GTO-солвер (сознательно отвергнут — [[06-внешние-сервисы]] раздел 10). Здесь источник ошибки — не арифметика, а покерная логика, и числовая защита её не ловит. Поэтому промпт обязан содержать вторую явную строку из принципа №6 ([[../idea/principles]]), которая раньше существовала только на уровне идеи и не дошла до архитектурного правила:

> «Если не уверен в своей рекомендации — не выдавай её как категоричный совет. Сформулируй как уточняющий вопрос игроку (что за оппонент, что происходило за столом до этого) вместо готового вердикта.»

**Проверка:** `grep -r "import.*anthropic\|new Anthropic"` возвращает файлы только из `adapters/llm/` или `infrastructure/llm/`. Нет ни одного числа, которое идёт в LLM напрямую из бизнес-логики без прохождения через парсерный модуль. Промпт `GENERATE_HAND_ANALYSIS`/`GENERATE_VERDICT` без строки про самопроверку при неуверенности — деплоить нельзя, по аналогии с запретом 2 ниже.

---

### Правило 2 — Сократовский вопрос всегда предшествует оценке

В state-машине диалога нет перехода напрямую из исходного состояния в состояние «показать разбор». Каждая критическая раздача проходит: `idle → question → user_answer → evaluation`. Ни один путь (пользовательский, API, тест) не пропускает стадию `question`.

**Проверка:** в коде диалога нет пути `idle → evaluation`. Состояние `evaluation` недостижимо без предшествующего `user_answer`.

---

### Правило 3 — Бизнес-конфиг живёт только в конфиге или базе

Цены ($12, $30–40), лимиты тиров (20 турниров/мес), имя LLM-модели, шаблоны промптов — только в `.env`, конфигурационных файлах (`config/`) или таблице настроек БД. Никогда в бизнес-логике.

**Проверка:** `grep -rn "1200\|12.*month\|claude-sonnet\|claude-opus" src/` не даёт hits в файлах бизнес-логики. Только в `config/` и `infrastructure/`.

---

### Правило 4 — Каждый внешний сервис подключается только через сменный адаптер

LLM (Anthropic), платёжная система (Stripe), хранилище HH-файлов (локально или S3) — за интерфейсом в `adapters/`. Бизнес-логика не импортирует SDK напрямую. Адаптер можно заменить без изменений в бизнес-коде.

**Проверка:** `grep -rn "from 'anthropic'\|from 'stripe'\|require('aws-sdk')"` даёт hits только в `adapters/` или `infrastructure/`.

---

### Правило 5 — Каждое архитектурное решение фиксируется строкой в журнале решений

Формат в разделе «Журнал решений» ниже: `ГГГГ-ММ-ДД | Решение | Откуда выросло`.

## Спроси разрешения, прежде чем

| # | Действие | Почему требует разрешения |
|---|---|---|
| 1 | Подключить новую внешнюю библиотеку или платный сервис | Может изменить лицензию, добавить уязвимость или создать скрытые расходы |
| 2 | Изменить схему базы данных | Затрагивает данные пользователей: история турниров, профиль, подписка — неправильная миграция = потеря данных |
| 3 | Изменить место хранения HH-файлов | HH-файлы содержат никнеймы пользователей; смена хранилища — риск утечки |
| 4 | Изменить цены, тиры или лимиты подписки | Бизнес-решение; неосторожное изменение может нарушить действующие подписки |
| 5 | Изменить LLM-промпты в продакшне | Промпты — это продукт; изменение влияет на качество разборов для всех пользователей без возможности быстро откатить |

## Запрещено

### Запрет 1 — Никаких секретов в коде и репозитории

API-ключ Anthropic, Stripe secret key, строка подключения к БД — только в `.env`. Перед каждым коммитом: `git status` не должен показывать `.env`, `.env.local`, `.env.production` или любые файлы с паттерном `*.key`, `*.pem`.

**Механическая защита:** `.gitignore` в корне проекта содержит `.env`, `.env.*`, `*.key`, `*.pem`. В репозиторий попадает только `.env.example` с фиктивными плейсхолдерами.

---

### Запрет 2 — LLM не вычисляет покерные метрики

Промпт без строки «не вычисляй метрики самостоятельно» деплоить нельзя. Одна ошибка в расчёте pot odds или SPR, сфотографированная и отправленная в Discord — репутационная смерть в маленьком покерном сообществе.

---

### Запрет 3 — HH-файлы пользователей не попадают в репозиторий

`/uploads/` и `/storage/` в `.gitignore`. `git status` перед коммитом не должен показывать ни один файл из этих папок. HH-файлы содержат игровые никнеймы, которые идентифицируют пользователя в покерном сообществе.

---

### Запрет 4 — Нет деплоя без рабочего детерминированного парсера

Публичный деплой только при выполнении условия: парсер вычисляет VPIP, количество рук, результат турнира, классифицирует тип раздач — и тесты на это проходят. Нельзя выходить в продакшн с LLM-угадайкой вместо парсера.

---

### Запрет 5 — Нельзя удалять подписку или историю рук без двойного подтверждения

Любое destructive-действие над подпиской или историей турниров реализуется как soft delete с флагом (`deleted_at`, `is_active: false`), а не прямым `DELETE`. Физическое удаление только через явную административную команду с подтверждением. Потеря оплаченной подписки = потеря доверия.

---

### Запрет 6 — Нет инфраструктурного кода продукта до подтверждения спроса живыми деньгами

Разработка кода продукта (база данных, очередь, адаптеры к внешним сервисам, фоновые воркеры) не начинается, пока не зафиксированы факты, описанные в [[../idea/vision]]: показ бумажного прототипа 20+ незнакомым игрокам и не менее 3 подтверждённых оплат на месте (не «интересно», не «подумаю»). Это самое дорогое допущение продукта — [[../idea/risks]] риск №1 — и пока оно не проверено деньгами, любой написанный код рискует оказаться кодом для рынка, которого нет.

**Проверка:** «Этап 0» из [[10-план-реализации]] зафиксирован как обязательное условие входа в «Этап 1» (а не как пункт списка), с явным критерием стоп/вперёд: меньше 3 оплат на месте — проект закрывается или меняет фрейминг ([[../idea/vision]], «Зеркало к золотой сцене»), а не переходит к написанию инфраструктуры.
