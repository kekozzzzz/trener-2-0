# Итог дня — сводный чертёж и журнал решений

Один экран со всем, что собрано в `architecture/00`–`10`. Если завтра нужно вспомнить «что мы строим и почему» за минуту — читать этот файл.

## Что строим (1 абзац)

Сократовский тренер для микролимитного турнирного игрока GGPoker: загружаешь файл истории рук одного турнира → детерминированный парсер считает VPIP, число рук, итог и стилевой диагноз → продукт показывает карточку с ~10 раздачами трёх уровней (критические / сильные / средние), и по критическим — не готовый вердикт, а сначала вопрос «почему ты так сделал?», ответ, и только потом разбор. Подписка $12/мес. Цель года — 300–500 платящих незнакомцев ([[../idea/vision]]).

## Главные 5 архитектурных решений

1. **Парсер считает числа, LLM только объясняет** — и самопроверяется уточняющим вопросом, если не уверена в стратегическом вердикте (Правило 1, [[00-правила-проекта]]). Одна ошибка в покерной логике, ушедшая скриншотом в Discord, убивает репутацию в маленьком сообществе раньше, чем продукт наберёт первую сотню.
2. **Сократовский вопрос физически не может быть пропущен** — состояние диалога `idle → question → user_answer → evaluation` хранится явным полем в БД, переход напрямую к вердикту недостижим (Правило 2, [[03-база-данных]]). Это и есть единственное отличие от конкурентов.
3. **Весь стек — в России**: Yandex Cloud (хостинг + Postgres + Object Storage), ЮKassa вместо Stripe, Unisender вместо зарубежных email-сервисов — потому что в HH-файлах никнеймы оппонентов делают продукт оператором персональных данных граждан РФ по 152-ФЗ ([[05-стек]], раздел 0).
4. **Каждый внешний сервис — за сменным адаптером**: Anthropic, ЮKassa, Yandex Object Storage, Unisender, Telegram. Домен зовёт порт («сгенерируй разбор», «прими оплату»), не вендора — смена поставщика - это новый файл адаптера и ноль правок в бизнес-логике (Правило 4, [[08-структура-кода]]).
5. **Ни строчки кода продукта, пока спрос не подтверждён живыми деньгами** — Запрет 6, добавленный сегодня по итогам обратного аудита провала ([[09-риски]]): в прошлый раз чертёж тянул код вперёд теста, и деньги так и не пришли. Порог: 3+ оплаты от незнакомцев на демонстрации — иначе код продукта не пишется вообще.

## Что НЕ делаем (в первой версии)

Другие румы кроме GGPoker, кэш-игры, GTO-солвер, геймификация, несколько тарифов, B2B, массовый импорт истории, автоматический мониторинг папки — список целиком в [[01-что-строим]]. И главное: **никакого кода продукта** (экраны, база, очередь, адаптеры, воркеры) до 3+ оплат от незнакомцев на демонстрации.

## Главный риск

**Спрос так и не подтвердится деньгами** ([[09-риски]], причина №1). Это единственное по-настоящему дорогое допущение продукта — «микролимитчик заплатит $12 за правду о своей игре» — и единственное, что убило проект в прошлый раз именно потому, что осталось строчкой черновика, а не физическим барьером. Сегодня барьер поставлен (Запрет 6); план реализации ([[10-план-реализации]]) построен так, чтобы упереться в этот барьер на второй неделе, а не через полгода.

## С чего начинаем завтра

Пишем минимальный детерминированный парсер метрик GGPoker MTT — чистую функцию «файл → числа», вне периметра Запрета 6. Используем его как живой демонстрационный материал: показываем незнакомому игроку, как инструмент при нём, на его собственном файле, за секунды считает реальные цифры — это единственное, что снимает подозрение «разводка» у холодной аудитории (вывод из разговора с автором). Код продукта — экраны, база, очередь, адаптеры — только после того, как минимум 3 человека заплатят $12 на месте. Промт для старта — раздел 5 в [[10-план-реализации]].

## Общий журнал решений дня (сводка по всем файлам, 2026-06-07)

- **Правила проекта:** добавлена самопроверка LLM при низкой уверенности в Правило 1; добавлен Запрет 6 — нет кода продукта до 3+ оплат от незнакомцев → [[00-правила-проекта]]
- **Сущности:** «Сессия» переименована в «Турнир» по всему проекту — слово «сессия» в языке игрока означает другое (вечер из нескольких турниров) и оставлено свободным под будущую сущность → [[02-сущности]]
- **База данных:** семь таблиц + append-only журнал платежей; режим удаления выбран осознанно по каждой таблице (анонимизация / физическое удаление / soft delete / без своего флага); профиль пересчитывается заново простым усреднением, не скользящим средним → [[03-база-данных]]
- **Потоки данных:** очередь — таблица в Postgres с `FOR UPDATE SKIP LOCKED`, не отдельный брокер; вебхук ЮKassa + суточная сверка; идемпотентность платных LLM-вызовов через проверку «результат уже сохранён»; дневной потолок расходов с авто-стопом → [[04-потоки-данных]]
- **Стек:** TypeScript/Next.js/PostgreSQL/Prisma целиком в Yandex Cloud; Claude Sonnet 4.6 за адаптером; ЮKassa вместо Stripe; добавлена 4-я ежедневная метрика — средняя стоимость LLM на турнир → [[05-стек]]
- **Структура кода:** раскладка «сначала путь данных (приём → фичи → ядро → внешние сервисы → фон → база)»; карта владения на 4 параллельных окна разработки → [[08-структура-кода]]
- **Риски:** обратный аудит провала через год — десять причин, для каждой смертельной добавлена защита прямо в чертёж (самопроверка LLM, Запрет 6, метрика юнит-экономики) → [[09-риски]]
- **План реализации:** порядок недель построен вокруг Запрета 6 — сначала парсер (как демонстрационный материал и техническое ядро одновременно), затем тест спроса на реальных цифрах незнакомца, и только при GO — пять недель кода продукта → [[10-план-реализации]]
