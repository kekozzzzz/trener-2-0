# Источники переходов (GipsyTeam, Telegram) — 2026-07-19

**Задача:** Артёму нужно знать, сколько людей приходит по ссылкам, размещённым на GipsyTeam и в Telegram, и сколько из них регистрируется. Ссылки должны быть постоянными, с копированием одной кнопкой в админке; список источников будет расти по ходу разговора.

**Как решал:**
- Уточнил объём задачи двумя раундами вопросов (где видеть метрики → потом Артём уточнил: именованные ссылки + копирование + счётчики в /admin, не просто Яндекс.Метрика).
- Изучил существующий код: `/admin` уже считает похожее (страна по IP при регистрации, `auth_events`) — взял этот паттерн за образец.
- Спросил разрешение на смену схемы БД отдельным сообщением (правило проекта) — получил его.
- Реализовал: `/go/<source>` (Route Handler, не middleware — избежал Edge/Prisma проблемы), cookie первого касания, новая таблица `landing_visits`, `auth_events.utm_source`, блок «Источники» в `/admin` + переименование «Статистика» → «Админ».
- Уткнулся в известный дрейф миграций (документирован в памяти project_admin_stats) — `prisma migrate dev` просил `migrate reset`, который в deny-листе. Обошёл: миграцию написал руками, применил `prisma db execute` + `prisma migrate resolve --applied`, отдельно для dev и test баз.
- Проверил вручную: поднял dev-сервер, curl на `/go/gipsyteam` — cookie встала, заход записался в БД; повторный переход по другой ссылке cookie не перезаписал (первое касание работает).

**Решил:** Да, полностью. Тесты (1229) и билд зелёные.

**Что лучше:** Обходной путь с дрейфом миграций стоило бы закрыть раз и навсегда (переписать историю миграций načисто), а не обходить каждый раз заново — сейчас это ручная операция при каждой новой миграции.

**Как стало:** Два источника на старте (GipsyTeam, Telegram) в `config/acquisition-sources.ts` — добавление нового источника Артёмом словом в разговоре = одна строка в файле. Не задеплоено, ждёт команды.
