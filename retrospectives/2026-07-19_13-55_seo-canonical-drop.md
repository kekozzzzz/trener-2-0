# Ретро: выпадение из поиска — canonical

## Задача
Артём: «Глянь, куда мы делись из поисковика?» Уточнил: в Google по имени/домену
whygrid.app не находит, по полному `https://whygrid.app` — находит.

## Как разбирал
- Прочитал память (MEMORY.md, project_seo_metadata.md): модель индексации —
  «белый список», по умолчанию noindex, открыты точечно /, /pricing, /legal.
- Проверил код индексации: robots.ts (пускает), sitemap.ts, lib/seo.ts,
  layout.tsx (default index:false), все indexable-страницы, middleware.ts
  (только кука языка, поисковику не мешает), next.config.ts (нет X-Robots-Tag,
  redirects только по юр-подстраницам). Регресса в коде нет.
- Живой прод из облака недоступен: прокси среды не пускает на whygrid.app (403 —
  политика песочницы, не сам сервер; перепроверил через __agentproxy/status).
- Нашёл настоящую дыру: тега `<link rel="canonical">` в коде НЕТ вообще. Есть
  metadataBase, но Next сам canonical не выставляет. Без него Google размывает
  сигналы между http/https/www-версиями — ровно симптом Артёма.

## Решил: да (код-часть)
Добавил indexablePage(path) в lib/seo.ts (robots + alternates.canonical),
проставил на 5 публичных страницах (/, /pricing, /legal, /charts,
/how-to-export). Дозакинул /how-to-export в sitemap (была indexable, но не в
карте). Билд зелёный. Коммит c1d8596, ветка claude/search-visibility-drop.

## Что лучше в следующий раз
- Из облака нельзя закрыть вопрос до конца: что реально отдаёт прод и что в
  Search Console — видно только с релея / у Артёма. Часть диагноза остаётся за
  ним.
- canonical надо было завести ещё при настройке метаданных 06-23 — тогда дублей
  бы не было.

## Осталось (не в коде)
- Артём: Search Console → «Индексирование страниц», глянуть статус главной и нет
  ли «Мер, принятых вручную».
- После деплоя — переотправить sitemap в GSC; выдача обновляется дни-недели.
