# Ретроспектива: админ-вкладка со статистикой продукта

**Дата:** 2026-07-02, ~13:00–16:40
**Задача:** личная вкладка владельца «всё-всё-всё»: регистрации сегодня/вчера,
страны, входы, пробники, подписки, деньги, загрузки, расходы ИИ.

## Как решал

1. Прочитал схему БД, правила, структуру кода, дизайн-систему; выяснил, что админ-доступ
   (isAdminEmail) и отчёт расходов ИИ уже есть, а входы/страны никто не пишет.
2. Согласовал с Артёмом два решения: новая таблица журнала входов + локальная
   GeoIP-библиотека (страна без хранения IP); «входы» = входы в аккаунт.
3. Выбрал `geoip-country` (8 МБ, база обновлена вчера) вместо geoip-lite (115 МБ)
   и мёртвого fast-geoip (2022).
4. Схема `AuthEvent` + миграция; запись событий во всех 4 точках входа (пароль,
   волшебная ссылка, обе регистрации, неудачные попытки — предписание 07-безопасность).
5. Сборщик `features/admin/stats.ts` (сутки по МСК, всё одним Promise.all),
   страница `/admin` по дизайн-системе, ссылка в шапке только владельцу, словари ru/en.
6. Тесты (12 шт.) + полный прогон (568) + tsc + build; живая проверка через браузер:
   регистрация → журнал → 404 для не-админа → вкладка с цифрами под владельцем.

## Решил? Да (локально; деплой не делался — по команде)

## Что мешало / что выучил

- **Журнал миграций локальных баз годами жил в рассинхроне** с фактическим состоянием:
  колонки добавлялись мимо миграций, одна миграция висела failed с 17 июня. Из-за этого
  `prisma migrate dev` требовал сброс базы, а сброс запрещён deny-листом. Выровнял
  через `migrate resolve --applied/--rolled-back` + точечные `db execute` без потери
  данных. Урок: после каждой фичи со схемой проверять `prisma migrate status` локально.
- **Prisma генерирует в новую миграцию «починку» ручных partial-индексов** (drift от
  `WHERE deleted_at IS NULL`, которые Prisma DSL не умеет). Сгенерированный SQL нужно
  чистить руками, иначе миграция упадёт и локально, и на проде. В этом проекте это
  СИСТЕМНОЕ свойство: любую новую миграцию смотреть глазами перед применением.
- Тестовые auth-тесты бьют в реальную trener_test — ей тоже нужны миграции (применил).
- Скриншот-проверка через Playwright поймала то, что юнитами не видно: старая кука
  в браузере + занятый email маскировали «регистрация не записалась» — цифры на
  странице позволили это заметить и довести проверку до реальных событий в базе.

## Как стало

Вкладка «Статистика» в шапке (только у владельца), `/admin` отдаёт: регистрации и
входы по периодам и по дням (график), страны за 30 дней, пробник и конверсию,
подписки по тарифам, деньги по валютам, загрузки/ошибки/нераспознанные, активность
диалогов и чата, расходы ИИ (24 ч / 30 дней, топ игроков), очередь задач.
Остаток на деплой: проверить проброс X-Forwarded-For на КЗ-релее, иначе страны
будут пустые/KZ.
