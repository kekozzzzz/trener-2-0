# Ретроспектива: парсер — снимок раздачи + результат в фишках

## Задача

Фундамент для разметки раздач по важности и сократовского диалога: парсер разбирает каждую раздачу турнира (где Hero получил карты) на обезличенный структурированный снимок стола (`tableSnapshot`) + чистый результат Hero в фишках (`chipResult`). Без классификации важности и стилевого диагноза — это отдельная задача.

## Как решал

1. Получил от пользователя реальный анонимизированный HH-файл турнира (110 раздач) — выбрал 6 раздач для новой фикстуры `__tests__/fixtures/ggpoker_mtt_rich.txt`, покрывающих разные сценарии: олл-ин клэш с полным разворотом борда, сайд-пот/сплит-пот, фолд на флопе, выигрыш без вскрытия, непоследовательные номера мест за столом.
2. Добавил типы `Street`, `TableAction`, `Seat`, `TableSnapshot`, `ParsedHand` в `parser/types.ts`, поле `hands: ParsedHand[]` в `ParsedTournament`.
3. Новый файл `parser/ggpoker/hand.ts` — разбор одной раздачи: места/позиции (BTN/SB/BB определяются из заголовка стола и постов блайндов, остальное — `OTHER`), карты Hero, борд, обезличенные действия по улицам, банк, `chipResult`.
4. `parser/ggpoker/index.ts` — для каждой раздачи с `Dealt to Hero` вызывает `parseHand`, собирает `hands[]`.
5. 10 новых тестов в `__tests__/parser/ggpoker.test.ts`: точные значения `chipResult` (вручную сверены по каждой раздаче), позиции, обезличивание (реальные никнеймы не попадают в JSON).
6. Журнал решений — строка в `architecture/08-структура-кода.md`.

## Решил (да/нет/частично)

Да, полностью. `npm test` — 20/20, `tsc --noEmit` — 0 ошибок.

## Что лучше — на будущее

- **Посты анте/блайндов идут в HH-файле ДО `*** HOLE CARDS ***`.** Первая версия `chipResult` считала действия только с `*** HOLE CARDS ***` и теряла анте + блайнды Hero — все 5 проверок `chipResult` упали с разницей ровно на сумму потерянных постов. Зафиксировано как комментарий в коде (`hand.ts`). Если будущая доработка парсера снова будет резать раздачу на секции — проверять, что посты не попали «до начала» окна.
- **Семантика `raises X to Y` в GGPoker:** `Y` — абсолютная итоговая ставка игрока на этой улице, `X` — приращение поверх *текущей ставки на столе* (не поверх собственного предыдущего вклада игрока). Для подсчёта вклада Hero достаточно брать `Y` и игнорировать `X` — этим избежали отдельной поулично-игровой логики накопления ставок других игроков.
- Подход «дать `parseHand` независимо вычислять `chipResult` через свой проход по тексту (не через `actions[]`)» оказался удачным — позволил держать `actions[]` простым (с коллапсом call/bet/raise в `ALL_IN`) без потери точности для денежного расчёта.

## Как стало

`ParsedTournament.hands: ParsedHand[]` — по одной записи на раздачу Hero, готов как материал для следующей фазы (классификация важности + стилевой диагноз, алгоритм «сложности решения» — пока не решён, см. журнал `architecture/00-правила-проекта.md` 2026-06-11).
