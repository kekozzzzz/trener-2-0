# Ретро: надёжность разбора — устойчивость к релею, вечная крутилка, сторож тишины, оценка времени

**Дата:** 2026-07-10 01:10
**Длительность:** ~сессия (вечер 09.07 → ночь 10.07)
**План:** без отдельного плана; выросло из доделки удалённой работы по зависаниям + запросов Артёма по ходу

## 1. Задача

Доделать начатую удалённо работу по зависаниям разбора и довести систему до состояния «когда Артёма нет за компьютером — всё работает само, чинить руками не надо»; попутно вылечить вечную крутилку, поставить сторож тишины на дайджест, ужать таймаут LLM и показать игроку оценку времени разбора при загрузке.

## 2. Как решал

- **Поднял контекст:** синхронизировал локальный master с origin (3 облачных коммита от 08.07: таймаут LLM + `resilientFetch` + фидбек тестера), прочитал память проекта — инцидент 08.07 описан детально.
- **Доделал надёжность сводки:** тот же `resilientFetch` для Telegram-пути + честный `sent/failed` в крон-роуте (был всегда «sent», даже когда не дошло — точь-в-точь инцидент 25–26.06).
- **Аудит 3 параллельными сканерами** (устойчивость вызовов через релей / фоновые задачи и очередь / молчаливые сбои и алертинг) → приоритизированные списки дыр.
- **Read-only заход на релей и ВМ** — сверил живую инфраструктуру: всё крепче, чем в заметках (автодеплой применяет миграции, шлёт ошибки прямо в Telegram мимо релея; серт авто-продляется; мост жив; `NODE_EXTRA_CA_CERTS` цела).
- **Пакет устойчивости:** таймаут запасного Claude, независимый жнец в кроне, health ловит зависшие PROCESSING, таймауты ЮKassa/ЦБ/email/S3/Telegram-моста — всё в конфигах (правило 3).
- **Вечная крутилка:** модуль `features/queue-recovery/` (детектор POISONED + retry), поле `failed` в статус-роутах, «повторить» в 3 wait-клиентах + капы; формулировки — по обзору UX-практик (вина «на нашей стороне»).
- **Сторож тишины:** пульс дайджеста в коде + `digest-watchdog.timer` на релее (systemd, независимый Telegram).
- **По ходу от Артёма:** таймаут 90→45с; оценка «≈ N минут» при старте разбора по реальному среднему (`features/tournaments/estimate.ts`).
- **Security-review** отдельным агентом-скептиком → без находок. Три выкатки через автодеплой, каждую отслеживал фоновой слежкой (state + health 200).

## 3. Решил?

- [x] **Да, полностью.** Всё задеплоено и подтверждено (health 200 после каждой выкатки). 780+ тестов зелёные, tsc чист, next build ок, security чисто. Отложен сознательно только **второй релей** (Артём — до первых пользователей).

## 4. Что можно было лучше

- **`tsc` пропустил чужую ошибку сборки** (незавершённый parser-WIP Артёма в `made-hand.ts`) из-за инкрементального кэша — поймал только `next build`. Вывод: перед пушем гонять именно `next build`, а не только `tsc`; при чужих правках в дереве проверять `git status` заранее.
- **Флейк тестов на общей `trener_test`** мешал читать результат полного прогона (падения «уходили» в изоляции). Стоит наконец изолировать тестовую БД — давний тех-долг.
- Живьём клик «повторить» на сайте не проверял (дорого воспроизвести POISONED в деве) — приёмка после выката.

## 5. Как было / как стало

- **Было:** зависший релей вешал разбор на 5–15 минут; сводка молча терялась (и рапортовала «отправлено»); при сбое шага игрок видел «готовим…» вечно; настоящий сбой прода был невидим владельцу; запасной Claude мог висеть до часа.
- **Стало:** икота релея незаметна (доли секунды); настоящий отказ — потолок ~45с, дальше повтор или кнопка «не получилось, повторить»; сводка честная + сторож тишины бьёт тревогу независимым каналом, если она пропадёт; монитор ловит зависший воркер → письмо мимо релея; при старте разбора игрок видит «≈ N минут».
