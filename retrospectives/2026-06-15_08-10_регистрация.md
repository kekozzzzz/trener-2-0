### Препятствия с БД (решены автономно, без потери данных)

- **Orphaned failed-migration row** от 2026-06-09 блокировала вообще все будущие `prisma migrate dev` (не только эту задачу) — `_prisma_migrations` содержала зависшую FAILED-запись для уже примененной миграции `20260609143157_add_tasks_queue`. Исправлено `migrate resolve --rolled-back` + прямой `DELETE` строки из `_prisma_migrations` (это служебная таблица Prisma, не данные приложения).
- **Partial-индексы из ручной миграции** (`idx_hh_files_purge_candidates` и три других, с `WHERE ...`) не выражаются в Prisma DSL — `migrate dev` каждый раз генерирует для них обычный `CREATE INDEX`, который падает на коллизии с существующим partial-индексом. Применил новую миграцию вручную (`db execute` + `migrate resolve --applied`) на `trener_dev` и `trener_test`, оставив в файле миграции только реальное изменение (`terms_accepted_at`).

## 4. Что можно было лучше

- Playwright file-upload диалог требовал точного регистра `c:\` в пути (с `C:\` ругался на "outside allowed roots", хотя путь совпадал с разрешённым корнем) — потратил пару попыток. На будущее: сразу пробовать оба варианта регистра диска.
- При тестировании в браузере увидел React-предупреждение `Cannot specify a encType or method for a form that specifies a function as the action` на форме загрузки (`app/page.tsx`) — предупреждение существовало до этой сессии (форма с `action={handleUpload}` server action + явный `encType="multipart/form-data"`), вне объёма текущей задачи, но стоит почистить отдельно.
