# Ретроспектива: вывод по открывашкам + кликабельные руки в обзоре

**Дата:** 2026-06-25 14:01

## Задача
Артём: в общей картине турнира хочется (1) вывод по открывашкам («такие руки
открываешь слишком широко») и (2) чтобы упомянутые в выводе руки («JT») были
кликабельными ссылками на разбор раздачи.

## Как решал
- Уточнил два решения через вопросы: открывашки называем конкретными руками
  (не общей пометкой), только заметно шире нормы; ссылка = карты руки в тексте,
  ниже список «любую открыть» остаётся.
- План в `plans/2026-06-25-открывашки-и-ссылки-в-обзоре.md`.
- Открывашки — детерминированно: RFI-чарт (baseline Артёма) в `config/poker/`,
  детектор «открылся первым» в `parser/open-raise.ts`, порог «заметно шире» =
  открытие вне чарта И вне полосы допуска (+1 шаг). Числа/сверку считает код,
  LLM только формулирует (Правило 1/2). Стек <20bb не судим (пуш-фолд).
- Ссылки — токены `{{h:N}}` от LLM → шаг очереди меняет на `{{h:handId|карты}}`,
  карты из снимка парсера (модель карты не пишет). UI рендерит инлайн-ссылки,
  «моменты» убраны.
- Проверка на реальном HH из `Test/`: из 19 открытий помечено 6 (QJo/JTo/A9o с
  ранней, Q7s с CO, T6o/64o/J5s с BTN), граничные (ATo, A8o) корректно смолчали.
- Security: ужесточил regex ссылок до строгого UUID (модель не подсунет свой
  токен); никнеймы не текут (tableData анонимизирован Hero/Player N ещё парсером).

## Решил
Да (код + тесты + проверка на реальных данных). НЕ задеплоено: промпт обзора ждёт
показа Артёму (правило №5), он его видел в чате — нужен явный «ок» перед деплоем.

## Что лучше в следующий раз
- A9o с ранней — пограничный флаг из-за склейки EARLY=UTG. Когда дойдут руки,
  возможно стоит для EARLY брать допуск шире (MP-вариант), а не самый тайтовый.
- `TOLERANCE_STEP`/`OPEN_MIN_STACK_BB` сейчас в конфиг-файле; при появлении
  таблицы настроек БД — вынести туда (правило №3).

## Как стало
Загрузка турнира теперь даёт честный вывод по открывашкам (детерминированно) и
кликабельные руки прямо в тексте обзора. 18 тестов зелёные, tsc чист.
