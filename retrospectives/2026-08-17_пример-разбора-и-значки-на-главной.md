# Ретро: страница-пример полного разбора + значки на главной

**Дата:** 2026-08-17
**Длительность:** ~одна длинная сессия
**План:** `plans/2026-08-17-публичный-пример-разбора.md`

## 1. Задача

Скриншот реакции реальных игроков на GipsyTeam (не верят заявлению «числа считает алгоритм» на слово,
просят показать внутреннюю логику) превратить в конкретную пользу: бейджи доверия под CTA на главной +
публичная страница с ПОЛНЫМ настоящим разбором одной раздачи, доступная без регистрации.

## 2. Как решал

Цепочка: разобрал скриншот форума → зафиксировал сигнал в `.business/audience/objections.md` и
`marketing/gipsyteam.md` → нашёл реальную раздачу скан-скриптом по `Test/` (детектор `lucky-win.ts`,
фильтр по среднему банку) → прошёл сократовский диалог по этой раздаче ВМЕСТЕ с Артёмом вживую (я —
тренер, он отвечал голосом) по правилам `dialogue-question.ts`/`verdict.ts` → собрал страницу `/example`
из компонентов дизайн-системы → добавил бейджи-значки под CTA на главной.

## 3. Решил?

- [x] Да, полностью — обе части сделаны, протипчекано, собран билд, проверено в браузере Playwright'ом
      (стол, числа, диалог, вердикт, переключение языка, раскрывающийся исходный HH-файл).

## 4. Что можно было лучше

Дважды ошибся и оба раза поймал не я, а Артём:

1. **Диалог не проверил на живом дубле.** Собирал ответ/вердикт по кусочкам из голосовых реплик Артёма
   (диктовка регулярно искажала слова — «тус» вместо «туз», «откололи» вместо, видимо, «остались»/
   «заколлировали»), и один раз домыслил смысл неправильно («выбить тузов» вместо «получить оплату от
   тузов» — Артём поправил дважды подряд). Раз пунктуация/смысл дошли до меня через STT — надо было
   ЧАЩЕ переспрашивать короткими да/нет-вопросами по каждому спорному месту, а не собирать большими
   кусками и потом дорабатывать по правкам постфактум.
2. **Скопировал не тот визуальный образец.** Взял стиль иллюстративной превьюшки с главной (окно-рамка
   с путём, цветные пузырьки диалога) вместо того, чтобы СНАЧАЛА прочитать реальный код настоящей
   страницы разбора (`app/tournament/[id]/hands/[handId]/page.tsx`) и скопировать один в один оттуда.
   Артём поймал глазами: «оно же так не будет по факту». Это прямое нарушение духа design-system.md
   («не рисуем того, чего нет в продукте») — я решил, что раз есть готовый компонент на сайте, можно
   его переиспользовать, не проверив, что он вообще из другого контекста (маркетинг, не продукт).
   **Урок на будущее:** для любой страницы, которая обещает «вот как это выглядит по-настоящему» — перед
   вёрсткой читать код РЕАЛЬНОЙ страницы продукта, а не reuse ближайшего похожего компонента с сайта.

## 5. Как было / как стало

- **Было:** скриншот форумного скепсиса без дальнейшего действия; на главной — одна строка текста под
  CTA («Без карты — первый разбор бесплатно»); нет ни одной страницы с честным полным разбором,
  доступной сторонним скептикам напрямую.
- **Стало:** сигнал закреплён в бизнес-документах (усиливает приоритет уже существующей идеи в бэклоге);
  на главной — три кликабельных значка-бейджа (без пароля / без карты / первый разбор бесплатно), ведущие
  на регистрацию; страница `/example` — один в один как настоящий разбор, с реальными числами (эквити
  18.5%, итог +14 398 фишек), настоящим пройденным диалогом и раскрывающимся сырым HH-файлом для полной
  проверяемости.
