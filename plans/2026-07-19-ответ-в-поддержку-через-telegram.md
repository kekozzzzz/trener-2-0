# Ответ в поддержку прямо из Telegram

## Задача

Сейчас форма `/support` шлёт сообщение владельцу в Telegram (`@whygrid_bot`), но
ответить пользователю можно только вручную на почту (если он её оставил). Нужно
добавить второй, более быстрый путь: человек пишет боту `@whygrid_bot` напрямую в
Telegram → Артём видит сообщение → отвечает Reply прямо в Telegram → ответ уходит
человеку в тот же чат с ботом.

Решение принято в диалоге 2026-07-19:
- Бот — существующий `@whygrid_bot` (тот же, что шлёт дайджест и форму поддержки),
  третий бот заводить не стали.
- Ответ уходит **в Telegram**, не на почту — работает только для тех, кто написал
  боту напрямую (у веб-формы telegram-чата нет, там остаётся email-путь как есть).
- Вход в чат с ботом — ссылка «Написать в Telegram» рядом с веб-формой на `/support`
  (оба пути живут параллельно, форму не убираем).

## Как технически

Пересылка чужих сообщений админу уже есть (`infrastructure/posting/webhook.ts`,
`handleMessage`) — работает для комментариев под постами в канале. Расширяем её:

1. В пересылаемый Артёму текст зашиваем numeric id отправителя (`(id 12345678)`) —
   без него ответ некуда будет адресовать, а отдельного хранилища заводить не хотим.
2. Новая ветка: если сообщение пришло от Артёма (`isAdmin`) И это Reply на чьё-то
   сообщение — вытаскиваем id из текста цитаты (`reply_to_message.text`), шлём этот
   текст этим же ботом человеку с этим chat_id, подтверждаем Артёму «✅ доставлено»
   или сообщаем о сбое (человек мог не запускать бота / заблокировать его).
3. Ничего не исполняем из чужого текста — тот же принцип, что и раньше (правило
   инъекций, см. комментарий в `features/support/actions.ts`).
4. БД не трогаем: вся привязка «кому отвечать» живёт в самом тексте сообщения в
   Telegram (Telegram хранит цепочку Reply сам), сервер ничего не хранит.

Работает поверх уже настроенного `TELEGRAM_BOT_TOKEN`/`TELEGRAM_ADMIN_CHAT_ID` —
новых env-переменных не требуется.
