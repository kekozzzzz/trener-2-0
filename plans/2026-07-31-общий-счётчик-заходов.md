# План: общий счётчик заходов на сайт в /admin

**Дата:** 2026-07-31
**Автор:** Клод
**Статус:** завершён

## Цель

В /admin показать, сколько всего заходов на whygrid.app было сегодня и за 30 дней — не только через меченые /go-ссылки (блок «Источники») и не только вход в аккаунт (блок «Повторные входы»).

## Контекст

Артём видел страны повторных входов и регистраций, но не общее число заходов на сайт вообще — прямой трафик (по адресу, из закладок) нигде не считался. Блок «Источники» считает только клики по /go/<code>; «Повторные входы» — только вход в аккаунт (сессия живёт 30 дней, большинство заходов её просто используют без нового события).

## Фазы

### Фаза 1. Хранение
- [x] Новая таблица `site_visits` (id, created_at) — Prisma-модель `SiteVisit`
- [x] Миграция `20260731000000_add_site_visits` (обходной путь через `db execute` + `migrate resolve` — известный дрейф старой миграции `add_auth_events`), применена к `trener_dev` и `trener_test`

### Фаза 2. Учёт заходов
- [x] `app/api/track-visit/route.ts` — POST-роут, пишет строку в `site_visits`, фильтрует ботов через `isBotUserAgent` (config/acquisition-sources.ts)
- [x] `components/site-visit-tracker.tsx` — невидимый клиентский компонент, один fetch на монтирование
- [x] Подключён в `app/layout.tsx` (корневой layout не перемонтируется при переходах между страницами → один заход = одна запись, не за каждый клик)
