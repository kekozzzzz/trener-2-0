# План: пакетная загрузка турниров

Дата: 2026-06-28

## Задача

Сейчас турнир грузится строго по одному: поле выбора одиночное, обработчик читает
ровно один `file`, парсит синхронно, создаёт один турнир и редиректит на его страницу.
Игрок, который играет много, хочет закинуть пачку (десятки-сотня HH-файлов) разом.

## Решение (с Артёмом, 2026-06-28)

- Поле выбора файлов — множественное. Обработчик идёт циклом по файлам.
- **После загрузки:** один файл → сразу на страницу этого турнира (как сейчас);
  два и больше → на «Мои турниры» (`/tournaments`), где все идут списком со своими
  статусами («в очереди / разбираем / готов»), фоновая обработка уже есть (очередь).
- **Лимит-абуз:** часовой лимит загрузок (15/час) считаем не по файлу, а по «закиду»
  (один клик = одна единица). Плюс потолок файлов за пачку — настраиваемый, выбран по
  замеру производительности. Пять метров на файл сохраняется.
- **Производительность:** разбор оставляем синхронным в запросе (одиночная загрузка
  не теряет в скорости). Пачка растёт линейно; потолок ставим там, где время запроса
  ещё комфортно. Если 100 тормозит — режем до 40-50 (заранее согласовано).
- Платный гейт разбора не трогаем: грузить можно сколько угодно, разбор по-прежнему
  открыт только у первого бесплатного / по подписке (parse-tournament.ts).

## Фазы

- [x] **Замер.** Реальный HH (110-111 раздач, ~190 КБ) парсится ~3 мс; 100 файлов ≈
      0.3 с чистого парсинга. Парсинг не тормоз → потолок 100, резать не пришлось.
- [x] **Конфиг.** `config/usage-limits.ts`: `getUploadMaxFilesPerBatch()` (env
      `USAGE_UPLOAD_MAX_FILES_PER_BATCH`, дефолт 100). `next.config.ts`:
      `experimental.serverActions.bodySizeLimit = "50mb"` (пачка пробивает дефолтный 1 МБ).
- [x] **UI.** `components/upload/file-input.tsx`: проп `multiple`, счётчик + список
      выбранных файлов. Поле на `/analyze` — `multiple`, копирайт под пачку.
- [x] **Обработчик.** `app/analyze/page.tsx` `handleUpload`: квота один раз на пачку,
      `formData.getAll("file")`, потолок+срез, отсев >5 МБ, `uploadTournamentsBatch`,
      редирект (1 файл → турнир/дубль/ошибка как раньше; ≥2 → `/tournaments` со сводкой).
- [x] **Ядро.** `features/tournaments/actions.ts`: `uploadTournamentsBatch` (цикл по
      `uploadTournament`, сбор `uploaded/duplicates/failed/firstTournamentId/singleResult`).
- [x] **Сводка.** `/tournaments`: баннер по query (`uploaded`/`dup`/`failed`/`capped`).
- [x] **Тесты.** 3 приёмочных кейса пачки (2 файла→2 турнира, дубль, не-MTT).
      `tsc` чисто, `vitest` 364 зелёных, `next build` собирается.

## Итог

Сделано в коде, НЕ задеплоено. Один файл грузится ровно как раньше (скорость не
изменилась). Пачкой — до 100 за раз, фоновая обработка через очередь, посадка на
«Мои турниры» со сводкой. Осталось: показ Артёму + hardening-проход (особенно
`bodySizeLimit` 50 МБ как поверхность абуза) перед деплоем.

## Ограничения

- `uploadTournament` (ядро) не меняется — батч просто зовёт его в цикле; одиночные тесты целы.
- Перемешанная пачка (часть дубли / не-MTT) не падает: каждый файл обрабатывается
  отдельно, итог идёт в баннер-сводку; список показывает реально созданные турниры.
- Сверхпорог файлов в пачке — берём первые N, остальное отсекаем, в сводке помечаем `capped`.
