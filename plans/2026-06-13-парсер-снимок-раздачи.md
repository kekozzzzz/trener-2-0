# Парсер: снимок раздачи + результат в фишках

> **Статус:** в работе. Фаза 1 из более крупной задачи «разметка раздач по важности + стилевой диагноз» ([[../architecture/02-сущности]], [[../idea/mvp]]).

---

## Контекст

Следующий шаг по приоритету из решения о запуске (оплата+регистрация → диалог → дизайн) — ядро продукта: сократовский диалог по критическим раздачам. Диалогу и классификации важности (`HandImportance`) нужен материал — структурированные данные по каждой раздаче. Сейчас парсер (`parser/ggpoker/index.ts`) считает только агрегаты по всему турниру (`handsCount`, `vpipPercent`, `resultBuyins`) и не разбирает раздачи по отдельности.

Классификация важности и стилевой диагноз — отдельная content-задача (алгоритм «сложности решения» прямо помечен как нерешённый в журнале `architecture/00-правила-проекта.md`, 2026-06-11). Делаем её отдельно, когда на реальных снимках можно проверить эвристику. Сегодня — только фундамент: парсер разбирает каждую раздачу турнира на обезличенный структурированный снимок + результат в фишках для Hero.

## Контракт (новый)

`parser/types.ts`:

```typescript
type Street = "PREFLOP" | "FLOP" | "TURN" | "RIVER";

type TableAction = {
  street: Street;
  actor: string;       // "Hero" | "Player <seat>"
  action: "POST_ANTE" | "POST_SB" | "POST_BB" | "FOLD" | "CHECK" | "CALL" | "BET" | "RAISE" | "ALL_IN";
  amount?: number;      // фишки, для ставок/коллов/постов
};

type Seat = {
  label: string;        // "Hero" | "Player <seat>"
  position: "BTN" | "SB" | "BB" | "OTHER"; // точные позиции (UTG/CO/HJ...) — будущая доработка под методичку диапазонов
  startingStack: number;
};

type TableSnapshot = {
  seats: Seat[];
  heroCards: string[];   // ["Ah","Kd"]
  board: string[];       // карты флопа+тёрна+ривера, [] если фолд префлоп
  actions: TableAction[];
  potTotal: number;
};

type ParsedHand = {
  chipResult: number;       // чистый результат Hero в фишках за раздачу
  tableSnapshot: TableSnapshot;
};
```

`ParsedTournament` получает новое поле `hands: ParsedHand[]` (по одной записи на каждую раздачу, где Hero получил карты — как и сейчас в `handsCount`). Существующие поля (`handsCount`, `vpipPercent`, `resultBuyins`) не трогаем — реструктуризация в `metrics: {...}` (по чертежу 08-структура-кода) откладывается до фазы со стилевым диагнозом, чтобы не плодить churn в двух местах подряд.

**Обезличивание (правило 1, [[../architecture/05-стек]] раздел 0):** Hero остаётся `"Hero"`, любой другой игрок становится `"Player <номер места>"`. Тест проверяет, что ни одна строка из списка реальных никнеймов исходного файла не встречается в JSON снимка.

**Позиции:** BTN/SB/BB определяются однозначно из заголовка («Seat #N is the button») и строк постов слепых — это надёжно при любом размере стола. Все остальные места помечаются `"OTHER"`. Точные имена (UTG/CO/HJ и т.п.) — доработка под будущую методичку диапазонов открытия, не блокирует эту фазу.

## Итог

Готово полностью. `parser/ggpoker/hand.ts` разбирает каждую раздачу Hero в `ParsedHand` (`chipResult` + `tableSnapshot`: места/позиции BTN/SB/BB/OTHER, карты Hero, борд, обезличенные действия по улицам, банк). Новая фикстура `__tests__/fixtures/ggpoker_mtt_rich.txt` — 6 раздач из реального файла пользователя (олл-ин клэш с полным разворотом борда, сайд-пот/сплит, фолд на флопе, выигрыш без вскрытия, непоследовательные места). 10 новых тестов покрывают `chipResult` (сверен вручную по каждой раздаче), позиции, обезличивание (реальные никнеймы не попадают в JSON). `npm test` — 20/20, `tsc --noEmit` — 0 ошибок.

Найденная и решённая по ходу сложность: посты анте и блайндов в HH-файле идут **до** `*** HOLE CARDS ***` — на это завязан и `chipResult`, и `actions[]` (включены `POST_ANTE`/`POST_SB`/`POST_BB`).
