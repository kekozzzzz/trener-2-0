# План: задание на сессию — тренер даёт цель, лик-трекер проверяет

Дата: 2026-07-03. Фундамент: plans/2026-07-02-лик-трекер.md (задеплоен).

## Замысел

Продукт даёт игроку ОДНО конкретное задание на следующую игровую сессию (вечер = игровой
день лик-трекера): «В эту сессию — ни одного опен-лимпа». После загрузки турниров вечера —
детерминированная проверка тем же счётчиком ликов: выполнено (лайм) / не выполнено.
Замыкает цикл удержания: сыграл → увидел динамику → получил цель → вернулся проверить.
Идея Артёма 2026-07-03 («задание на сессию лучше задания на неделю» — короче петля,
совпадает с единицей лик-трекера, два касания продукта за вечер).

## Решения

- **v1 без LLM и без миграции БД.** Задание = самый частый активный лик окна
  (leakDynamics уже сортирует по priorTotal). Оно ДЕТЕРМИНИРОВАННО вычисляется из
  истории: задание для сессии X = топ-лик по окну дней ДО X. Хранить нечего — та же
  функция отвечает и «какое задание на следующую сессию», и «выполнено ли в прошлой»
  (счётчик лика в дне X равен нулю → выполнено). Правило 1 цело.
- **UI-термин — «Цель на сессию»**, не «задание» (правка Артёма 2026-07-03: за задание
  люди привыкли что-то получать; «рекомендация» отвергнута — слишком мягко, вызов
  умирает; «цель» — язык живого тренера, «цель достигнута ✓» — сама себе награда,
  накопительная награда позже — стрик, Фаза 4). В коде имена SessionGoal остаются.
- **Задание ровно одно** — фокус, не список дел. Формулировка действием из словаря по
  LeakKind («не открывай лимпом», «не открывайся шире чарта с ранних» и т.п.).
- **Задание честно только вместе с эталоном** (замечание Артёма 2026-07-03: «если давать
  задания типа „не открывайся широко" — надо давать точные чарты»). Игрок должен ДО
  сессии видеть, какая норма: задание кликом ведёт на страницу эталонного чарта этого
  спота. Сейчас «Твои чарты» — только зеркало игрока, эталон не показан нигде. Данные
  эталонов в проекте уже есть: RFI (config/poker/rfi-chart.ts, в коде), пуш-фолд,
  защита BB, vs-опен, изоляция (собраны, не зашиты). Показ эталона — учебный материал
  ВНЕ игры (не realtime, GG-безопасно). Детекторы флагают только ЗАМЕТНО шире нормы
  (допуск) — на странице эталона честно показать «норма + мягкая граница».
- **Глубина стека (вопрос Артёма 2026-07-03 «50bb и 100bb — как усредним?»):** отдельные
  чарты по глубинам НЕ делаем (перегруз для микролимитника; три таблицы = GTO Wizard).
  Система уже консервативна к глубине: <20bb открытия не судятся вообще (там пуш-фолд
  по стек-бэндам), ≥20bb — якорный чарт ~40bb с допуском, флагается только «мусор на
  ЛЮБОЙ глубине». На странице эталона подпись: «норма от 20bb; глубже 60bb края можно
  чуть шире — зелёная зона это допускает». Если позже захотим точнее — механика бэндов
  из пуш-фолда переносится на открытия без ломки. Решение согласовано 2026-07-03.
- **Нет активных ликов** → блок «чистая сессия — держи планку» (или скрыт, решить на
  показе формы).
- Терминология UI: «сессия» = вечер игры (язык игрока); в коде остаётся gameDayKey.
  Сущность «Сессия» из architecture/02-сущности.md НЕ заводим — расчёт на лету.
- **Двуязычно** (RU/EN, namespace в messages).
