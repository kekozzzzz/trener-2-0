# План: загрузка без блока, разбор первого бесплатно, остальные под замком

Дата: 2026-06-25
Решение Артёма: грузить можно сколько угодно турниров; у всех показываем
бесплатные метрики (VPIP, руки, результат), но полноценный **разбор**
(сократовский диалог, обзор, разборы раздач) делается только у первого
бесплатного. Остальные лежат «под замком» — метрики видны, разбор закрыт с
предложением подписки; открываются после оплаты.

## Как сейчас (факт по коду)

- Загрузка: `features/tournaments/actions.ts → uploadTournament`. При включённом
  гейте (`isSubscriptionGateEnabled`) вызывает `assessAiAccess` и на не-первом
  турнире возвращает `PAYWALL` — файл **вообще не загружается**.
- Парсер считает метрики синхронно при загрузке (бесплатно, без ИИ).
- Шаг `PARSE_TOURNAMENT` (воркер): пишет `status=PARSED` + все руки + помечает
  ~10 раздач `selectedForCard` и ставит на каждую `GENERATE_HAND_ANALYSIS`.
- Вся платная ИИ-цепочка растёт отсюда: `GENERATE_HAND_ANALYSIS` → (диалоги/
  вердикты) → когда все готовы → `status=CARD_READY` + `GENERATE_TOURNAMENT_SUMMARY`
  + `GENERATE_PLAYER_CHARACTERISTIC`.
- Значит **единственная точка гейта разбора** — ставить или нет
  `GENERATE_HAND_ANALYSIS` в шаге парсинга. Не поставили → ничего платного не бежит.

## Ключевые решения (деньги — правило №1)

1. **Гейт переезжает с загрузки на разбор.** Загрузка всегда разрешена (формат +
   часовой лимит `checkUploadQuota` остаются). Парсинг (метрики) — всегда.
2. **Решение «разбирать или запереть»** принимается в шаге парсинга через
   существующий `assessAiAccess(db, playerId, { tournamentId })`:
   - admin / активная подписка с остатком бюджета / это самый старый
     (первый бесплатный) турнир → **разбираем** (ставим задачи);
   - иначе → **запираем** (задачи не ставим).
   Логику не дублируем — переиспользуем `assessAiAccess`.
3. **Разблокировка — по требованию, в рамках бюджета. НЕ массовая.**
   При оплате НЕ запускаем разбор всех запертых турниров скопом — иначе игрок
   зальёт 50 файлов бесплатно, оформит Базовый ($4 бюджет) и мы уйдём в минус
   (нарушение правила №1). Вместо этого запертый турнир у подписчика открывается
   по кнопке «Разобрать», и каждый такой запуск проходит обычный бюджетный гейт
   (`assessAiAccess` → `LIMIT_REACHED`, если бюджет периода исчерпан).

## Фазы

### Фаза 1 — схема БД  ⚠️ требует разрешения Артёма (изменение схемы)
- [ ] `Tournament.analysisUnlocked Boolean @default(true) @map("analysis_unlocked")`.
      По умолчанию `true` — обычный поток и выключенный гейт не меняются.
      Запертый турнир получает `false` в шаге парсинга.
- [ ] Миграция. На проде накатывать вручную (как прежние — там дрейф миграций,
      см. memory project_payments_yookassa). Локально — на trener_dev и trener_test.

### Фаза 2 — загрузка без блока
- [ ] `uploadTournament`: убрать ветку, возвращающую `PAYWALL`/`LIMIT_REACHED`
      на загрузке. Оставить проверку формата и `checkUploadQuota`.
- [ ] Текст ошибки `PAYWALL` на `/analyze` больше не нужен для загрузки
      (останется для совместимости/других мест) — проверить, не сломалось.

### Фаза 3 — гейт на разборе (шаг парсинга)
- [ ] В `parse-tournament.ts`: после `createMany(hands)` решить доступ через
      `assessAiAccess(tx, playerId, { tournamentId })` (только если гейт включён;
      выключен → считаем unlocked). playerId взять из турнира.
- [ ] Разрешено → как сейчас (ставим `GENERATE_HAND_ANALYSIS`, `analysisUnlocked=true`).
- [ ] Запрещено → НЕ ставим задачи, `analysisUnlocked=false`. Турнир остаётся
      `PARSED` (метрики есть, разбора нет).

### Фаза 4 — UI турнира (locked vs unlocked)
- [ ] `app/tournament/[id]/page.tsx`: если `!analysisUnlocked` — показываем
      метрики + список раздач (с фишками/BB как сейчас), но вместо «Общая картина»
      и блоков разбора — карточка-замок: «Разбор этого турнира откроется после
      подписки» + кнопка «Посмотреть тарифы →» (для гостя/без подписки) ИЛИ
      «Разобрать этот турнир» (для подписчика — Фаза 5).
- [ ] Список раздач у запертого турнира: показываем (метрики/результат), но ссылки
      на разбор раздачи ведут на тот же замок (страница раздачи запертого турнира
      не должна 404-ить, а показывать предложение подписки).
- [ ] `app/tournament/[id]/hands/[handId]/page.tsx`: для раздачи запертого турнира
      (нет analysis/dialogue) — вместо `notFound()` показать замок/предложение.

### Фаза 5 — разблокировка по требованию
- [ ] Server action `unlockTournamentAnalysis(tournamentId)`:
      `assessAiAccess(tournamentId)` → если allowed: `analysisUnlocked=true` +
      поставить `GENERATE_HAND_ANALYSIS` на `selectedForCard` руки (идемпотентно —
      не дублировать, если analysis уже есть/задача стоит). Если `LIMIT_REACHED` —
      честное сообщение про бюджет периода; `PAYWALL` — на тарифы.
- [ ] Кнопка «Разобрать этот турнир» на странице запертого турнира для подписчика.

### Фаза 6 — тесты + hardening
- [ ] Тесты: (а) загрузка не-первого турнира больше не PAYWALL, турнир создаётся;
      (б) parse запирает не-первый без подписки (нет задач, analysisUnlocked=false);
      (в) первый/подписчик — разбирается; (г) unlock ставит задачи и уважает бюджет
      (LIMIT_REACHED не запускает разбор).
- [ ] Правило №1: ни одного пути, где ИИ бежит без allowed. Проверить, что
      запертый турнир не порождает ни одной платной задачи.
- [ ] Hardening-проход по деньгам/доступу перед деплоем (feedback_hardening_before_deploy).
