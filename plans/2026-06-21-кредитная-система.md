# План: кредитная система (невидимый лимит потребления + стена)

**Дата:** 2026-06-21
**Задача:** ограничить потребление платных ИИ-действий по подписке так, чтобы человек НЕ видел счётчик («сколько турниров осталось»), пользовался свободно, а при исчерпании получал мягкую стену «лимит на месяц исчерпан, обновится …» — как у Claude/ChatGPT. Защищает от убытка на «китах», не вызывая тревоги счётчика.

## Концепция (согласовано с Артёмом 2026-06-21)
- **Кредиты внутренние, человеку не видны.** Метр — по РЕАЛЬНОЙ себестоимости: `LlmUsage.costUsd` уже пишется на каждый вызов по игроку.
- **Лимит = месячный бюджет себестоимости ИИ на подписчика.** Старт: тариф ~990 ₽ → бюджет ~$5.5 (≈525 ₽) → в среднем ~25 разборов турниров. (Пропорция: разбор турнира ≈ 11 вызовов ≈ 11 «кредитов», каждый вопрос диалога/чата = 1.)
- **Стена:** когда сумма расходов игрока за период ≥ бюджета → блок платных ИИ-действий + сообщение со сроком обновления. Счётчик не показываем; (опц.) тихое предупреждение под конец.
- **Кит сам упирается раньше** → в минус не уходим by design.
- **Бесплатное ядро** (детерминированное: парсер, метрики, тренажёр) + первый турнир-разбор — БЕЗ лимита. Лимит — только на платные ИИ-действия.
- **Владелец (Артём)** — без лимита ([[project_owner_comp_access]]).

## Что уже есть (переиспользуем)
- `LlmUsage` — стоимость каждого вызова по игроку (готово, [[project_llm_cost]]).
- `Subscription` — план (`planCode`) + `currentPeriodStart` (схема есть; активация по ЮKassa-вебхуку готова, [[project_payments_yookassa]]).
- `features/usage/limit.ts` (`checkUploadQuota`) — пример гейта (rate-limit), рядом добавим гейт лимита.

## Зависимость
Полный гейт опирается на подписочный гейт (кто на каком тарифе). Платежи: порт/адаптер/вебхук/активация готовы, но «гейт+UI» в бэклоге. Метрику потребления можно строить уже сейчас на `LlmUsage`; саму стену — когда понятен тариф игрока (Subscription или бесплатный дефолт).
