# План: ускорение разбора турнира + живая страница

Дата: 2026-06-27
Задача из разговора с Артёмом: разбор на проде «долго думает». Нужно: ответ в диалоге — секунды,
весь турнир — ~10 сек. Плюс живая страница (общая картина наверху, раздачи всплывают по очереди) и
понятные подписи раздач (критические vs сильные/средние).

## Диагноз (почему медленно)

1. **До 15 сек простоя на пустом месте.** Воркер очереди просыпается только по крону (раз в ~15с).
   После `enqueue` его никто не будит — задача лежит, пока крон не проснётся.
2. **Последовательная обработка.** Воркер берёт по одной задаче. Турнир = ~8 разборов раздач подряд
   по 4-6с = 40-60с.
3. **Страница не живая.** После статуса PARSED главная страница рендерится один раз сервером и больше
   не обновляется — новые раздачи и общая картина не всплывают без ручного обновления.

Сам Claude и парсер — не узкое место.

## Что делаем

### Пункт 1 — мгновенный «пинок» воркера
- Новый общий прогон очереди с single-flight + trailing-флагом: `infrastructure/queue/kick.ts`
  (`kickWorker(db)` — фоновый, не дожидаемся; если прогон уже идёт — ставим флаг «повторить»).
- Зовём `kickWorker` после: загрузки турнира (`features/tournaments/actions.ts`) и после ответа в
  диалоге (`features/dialogue/actions.ts`).
- Крон `run-tasks` и админ-экшен `status/actions.ts` переводим на тот же общий прогон (один замок —
  не дублируем параллелизм). Крон каждые 15с остаётся страховкой.

### Пункт 2 — параллельный воркер + живая страница
- `drainQueue(db, concurrency)` в `worker.ts`: N воркеров параллельно, каждый крутит `runWorkerOnce`
  пока очередь не пуста. Безопасно: `claimTask` уже на `FOR UPDATE SKIP LOCKED`.
- Конкурентность в конфиге: `config/queue.ts` → `QUEUE_CONCURRENCY` (по умолчанию 5). Правило 3.
- Живая страница:
  - Статус-эндпоинт `/api/tournament/[id]/status` отдаёт `{status, summaryReady, handsReady, handsTotal}`.
  - Клиент `live-refresh.tsx` опрашивает раз в ~1.5с и делает `router.refresh()` при изменении;
    останавливается, когда `CARD_READY && summaryReady`.
  - Страница турнира: «Общая картина» наверху (плейсхолдер «собираем…» пока summary нет),
    под ней метрики, ниже раздачи. Раздачи всплывают по мере готовности (refresh ре-рендерит сервер).
- Подписи раздач:
  - «Критические раздачи» — решающие моменты, тренер сам задаёт вопрос.
  - «Сильные и средние раздачи» — тоже важные руки, разбор готов, можешь спросить.

### Пункт 3 — быстрый диалог
- `kickWorker` после ответа (см. пункт 1) → следующий вопрос считается сразу.
- Поллинг ожидания вопроса `wait-client.tsx` 3000 → 1200мс; парсинг-ожидание 3000 → 1500мс.

## Неприкосновенное
- Правило 1: числа — парсер, LLM не пересчитывает. Не трогаем.
- Правило 2: сократовский вопрос раньше вердикта. State-машина диалога не меняется.
- Промпты не правим.
- Не деплоить до явного «деплой».
