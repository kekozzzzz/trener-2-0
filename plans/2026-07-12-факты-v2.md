# Факты-v2: парсер отдаёт готовым всё, на чём ИИ «думает»

**Дата:** план написан 2026-07-11 вечером, работа — с 2026-07-12.
**Замысел.** Аудиты 11.07 показали: все места, где модель без размышлений небрежничает, — это места, где ей не хватает готового факта, и она вычисляет сама. Отдаём эти вычисления парсеру (правило 1 расширяется), чтобы быстрый режим (reasoning off, 8–9 с) догнал по точности вдумчивый (low, 21–34 с). Всё детерминированно: наши конфиг-чарты + движок эквити (range-equity, Монте-Карло кулеров) + перебор. Никакого солвера, никаких «оценок из головы модели».

**Критерий приёмки всего плана:** контрольная восьмёрка + полный турнир на GLM-off больше не показывают классов небрежностей из прогона 11.07 (перепутанное фолд-эквити, потерянная механика излишка, «нокаут-фактора нет», гадание «вероятно сет» при вскрытых картах).

## Фаза 1 — Эквити против чартового диапазона [x]

Самый большой эффект. В спотах, где диапазон соперника формализован нашими чартами (опен-пуш → чарт пуш-фолда; рестил → чарт рестила; колл vs пуш; опен позиции → RFI-чарт), парсер перебором считает эквити руки Hero против этого диапазона и отдаёт строкой с готовым сравнением:

> «Эквити ATo против чартового диапазона опен-пуша HJ ≤10 BB: ≈47% — выше порога колла ≈8% с большим запасом.»

- [x] хелпер: коды чарта → эквити (переиспользован preflopEquityVsRangeFast — мгновенная таблица класс×класс; чарты отдают коды через pushRangeCodes/callVsRestealRangeCodes/rfiOpenRange);
- [x] строки в renderHandFacts (новый parser/chart-equity-fact.ts) для спотов: колл vs пуш, рестил (эквити при колле по чарту колл-vs-рестил), ре-джем поверх пуша (тот же детектор колл-vs-пуш, heroJammed), защита BB vs опен;
- [x] в промпт: «эквити против чартового диапазона — из парсера; свои проценты не выводи» (правило 1 COACH_FRAMEWORK);
- [x] тесты (__tests__/parser/chart-equity-fact.test.ts): ATo vs широкий пуш CO ≈54% (диапазон шире → выше плановых 47-50, корректно), рестил A5s + фолд-эквити, защита BB QJs vs BTN.

## Фаза 2 — Готовое фолд-эквити по чартам [x]

Обе половины пуша — фактами: доля опен-диапазона позиции (по RFI-чарту), которая продолжает против пуша (по чарту колла), остальное — фолд:

> «По эталонным чартам: опен LJ ≈13% рук; из них колл против пуша 17 BB ≈5% → сбрасывает ≈2/3 диапазона.»

- [x] подсчёт долей комбо грида (combosOf/percentOf из hand-grid — те же, что /charts);
- [x] строка в facts для рестил-спота (ре-джем поверх пуша сюда НЕ идёт: короткий уже в олл-ине, его не выбить — это Фаза 3; фолд-эквити рестила = доля опен-диапазона опенера ∩ его колл-vs-рестил диапазон, остальное фолд);
- [x] тест: фолд-доля в разумных границах (совпадает по конструкции с гридом /charts).

## Фаза 3 — Геометрия олл-инов и ре-джемов [x]

Арифметика, которую быстрый режим теряет, а старая модель путала всегда:

> «Ре-джем 29.2 BB поверх олл-ина 12.6 BB: излишек возвращается, если никто не заколлирует шире, — эффективный риск 12.6 BB. Покрывают тебя: SB 28.8 BB. Мёртвые деньги в банке: 4.1 BB.»

- [x] детектор (новый parser/allin-geometry.ts): Hero ALL_IN поверх чужого олл-ина → эффективный риск (мин своего и стека вошедшего), возврат излишка, список живых позади с флагом «покрывает», мёртвые деньги = банк до шова − вклад вошедших;
- [x] отдельная пометка «короткий уже в олл-ине — его не выбить, фолд-эквити только против живых позади» (в строке факта и в промпте);
- [x] тесты (__tests__/parser/allin-geometry.test.ts): ре-пуш 29.2 поверх 12.6 → эффективный 12.6, излишек 16.6, мёртвые 1.8; плоский колл и опен-шов → null. (Синтетические снимки вместо #0/#25 из Test/ — те вне git, недоступны в CI.)
