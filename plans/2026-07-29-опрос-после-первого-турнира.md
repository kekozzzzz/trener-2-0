# План: опрос после первого турнира

Дата: 2026-07-29

## Задача

После того как игрок впервые открыл готовый разбор своего первого турнира (страница
`/tournament/[id]`, разбор уже не в процессе), один раз показать модальное окно:
короткое вступление «мы только в начале пути, твоё мнение может повлиять на продукт»
+ опрос из 10 вопросов (4 обязательные оценки 1–5 + 6 необязательных текстовых полей)
про контент разбора, тон/стилистику тренера и качество сократовских вопросов.
Показывается один раз навсегда — независимо от того, ответил игрок или закрыл окно.

Решения по формату утверждены с Артёмом (см. диалог сессии):
- Триггер: первый турнир игрока, после того как разбор готов (не во время processing).
- Хранение ответа: новая таблица в БД (не просто текст в Telegram, как у `/support`) —
  структурированные оценки нужны для анализа позже. Разрешение на смену схемы БД получено.
- Повтор: один раз навсегда, даже если закрыл не ответив.
- Формулировки вопросов утверждены как есть, без правок.
- UI: один длинный скролл в модалке, без пошагового визарда.

## Реализация

### 1. Prisma-схема
- `Player.introSurveyShownAt: DateTime?` — флаг «уже показывали» (ставится и при
  отправке ответа, и при закрытии без ответа).
- Новая модель `IntroSurveyResponse`: 4 обязательные Int-оценки (usefulness/tone/
  questions/recommend) + 6 опциональных текстовых полей + связь с Player и Tournament.
- Локальная миграция (`prisma migrate dev`), прод не трогаем.

### 2. Server actions (`app/tournament/[id]/actions.ts`)
- `submitIntroSurveyAction` — валидирует 4 оценки (1–5, обязательны), создаёт запись,
  ставит `introSurveyShownAt`, шлёт сводку админу через уже существующий
  `safeNotifyAdmin` (без новой инфраструктуры, переиспользуем notify-адаптер).
- `dismissIntroSurveyAction` — закрытие без ответа: просто ставит `introSurveyShownAt`.

### 3. UI-компонент (`app/tournament/[id]/intro-survey.tsx`)
Мирроринг паттерна `self-level.tsx` (авто-открытие один раз, `Dialog` из
`components/ui/dialog.tsx`, `useActionState` как в `support-form.tsx`). Радио-группы
1–5 для обязательных оценок, `Textarea` для опциональных полей.

### 4. Точка показа (`app/tournament/[id]/page.tsx`)
Считаем `isFirstTournament` через `prisma.tournament.count` (единственный турнир
игрока без учёта удалённых), берём `introSurveyShownAt` вместе с существующим
запросом `me`. Показываем компонент, когда `isFirstTournament && !processing &&
!me.introSurveyShownAt`.

### 5. Переводы
`messages/ru.json` / `messages/en.json` — новый namespace `IntroSurvey`.

## Итог

Реализовано полностью, статус `[x]`:

- Схема: `Player.introSurveyShownAt` + таблица `intro_survey_responses` (4 обязательные
  оценки 1–5 + 6 опциональных текстовых полей). Миграция `20260729120000_add_intro_survey`
  написана вручную (не через `prisma migrate dev` — известная особенность репо: он лезет
  чинить ручные partial-индексы старых миграций) и применена и на `trener_dev`, и на
  `trener_test`.
- `submitIntroSurveyAction`/`dismissIntroSurveyAction` в `app/tournament/[id]/actions.ts`:
  сохраняют ответ, ставят флаг показа, шлют сводку владельцу в Telegram через уже готовый
  `safeNotifyAdmin` (без новой инфраструктуры).
- UI — `app/tournament/[id]/intro-survey.tsx`, паттерн один в один с `self-level.tsx`
  (`Dialog` из `components/ui/dialog.tsx`, `useActionState` как в `support-form.tsx`).
  Один длинный скролл, радио-группы 1–5 как квадраты с рамкой (стиль `border-primary`
  из design-system), 6 текстовых полей необязательны.
- Триггер в `page.tsx`: показывается один раз, когда у игрока нет других (неудалённых)
  турниров кроме текущего и разбор уже не в processing.
- Найден и закрыт конфликт: на первом турнире строчка «Ориентир» (self-level) тоже
  авто-открывает свой диалог — стек из двух модалок разом. Решено клиентской проверкой
  той же localStorage-метки `wg_selflevel_seen`: если self-level ещё может показаться
  в этом браузере, опрос уступает очередь и пробует на следующем подходящем визите
  (турнир остаётся «первым», пока не загружен второй) — сервер показ не отмечает, ответ
  не теряется.
- Переводы (`messages/ru.json` + `en.json`): namespace `IntroSurvey`, плюс два ключа в
  `Errors`.
- Проверено: `tsc --noEmit` чисто, `npm run build` чисто, `npm test` — 1343/1344
  (единственный красный тест не связан с задачей, про Instagram-источник трафика,
  падал и до этой сессии), дев-сервер поднимается без ошибок.

Что дальше (не в этой сессии): посмотреть реальные ответы после того как наберётся

## Правка по ходу (после первого показа скриншотов)

Артём посмотрел первую версию (тихая строка текста + кнопка без рамки, модалка с
повторным вступлением) и попросил переделать:

- Приглашение — не строка текста, а полноценная карточка (стиль `StartHereCard`/
  `SessionDoneCard` из `components/tournament/focus-slot.tsx`, `border-primary bg-card`):
  шапка «Пройти опрос», текст «мы только в начале пути», кнопка «Пройти опрос».
- Само окно опроса — без повторного вступления, сразу заголовок «Опрос» и вопросы.
- Добавлено место, где видно уже собранные ответы: секция «Опрос после первого
  турнира» на `/admin` (последние 50 ответов, свежие сверху, оценки + все заполненные
  текстовые поля). Данные берутся тем же путём, что остальная админ-статистика —
  `features/admin/stats.ts` → `buildAdminStats` → `AdminStats.surveys`.
- Мок БД в `__tests__/features/admin/stats.test.ts` дополнен стабом
  `introSurveyResponse.findMany` (упавший тест был не про опрос, а про отсутствующий
  метод в моке).

Проверено повторно: tsc, `npm run build`, `npm test` (те же 1343/1344, красный тест
не связан с задачей), скриншоты обоих состояний (карточка закрыта / открыт опрос)
сверены с Артёмом и одобрены.

## Ревизия 2026-08-05 — пересмотр вопросов

Обсудили с Артёмом формулировки после недели в проде: посмотрели практику по
онбординг-опросам (тайминг события, длина формы) и добавили тест Шона Эллиса на
product-market fit — прямой измеримый сигнал под Запрет 6 (CLAUDE.md), которого раньше
не было в опросе вообще.

Изменения по содержанию (было 10 полей → стало 9):
- Новый обязательный вопрос: «Как бы ты себя почувствовал, если бы больше не мог
  пользоваться Whygrid?» — три варианта (сильно расстроился / расстроился бы, но
  пережил / не расстроился бы), не шкала 1-5, отдельный компонент `PmfChoiceGroup`.
- Объединены две пары текстовых вопросов, которые по сути спрашивали одно и то же:
  «непонятно/пропущено» + «чего не хватило» → «Что было непонятно или чего не хватило?»;
  «что изменить в подаче» + «больше/меньше деталей» → «Что бы изменил в подаче — тон,
  объём деталей, что-то ещё?».
- Порядок вопросов пересобран: сначала лёгкая оценка полезности и позитивный открытый
  вопрос («что зацепило»), тон/вопросы тренера, затем объединённые текстовые, PMF-тест,
  «посоветовал бы» и свободный комментарий в конце.
- Тайминг показа не менялся — уже соответствовал практике (событие «разбор готов», не
  таймер, не во время processing).
- Шкала «посоветовал бы» осталась 1-5 (не переведена на стандартный NPS 0-10) — мы не
  сверяемся с другими компаниями по этому числу, важен только свой тренд, а 1-5 держит
  визуальную консистентность с остальными оценками.

Реализация (аддитивно, без потери уже собранных ответов):
- `prisma/schema.prisma` — `IntroSurveyResponse.pmfReaction: String?` (новая колонка).
  `unclearText`/`styleChangeText` переиспользованы под новые объединённые формулировки.
  `missingText`/`moreDetailText` оставлены в схеме как legacy — новые ответы их больше
  не пишут, старые записи не тронуты (никакого DROP/RENAME колонок).
- Миграция `20260805120000_add_pmf_reaction_to_intro_survey` — только
  `ALTER TABLE ... ADD COLUMN "pmf_reaction" TEXT`, применена вручную (тем же способом,
  что и первая миграция опроса) на `trener_dev` и `trener_test`, отмечена applied через
  `prisma migrate resolve`.
- `app/tournament/[id]/actions.ts` — `submitIntroSurveyAction` требует `pmfReaction`
  наравне с 4 оценками (одна из трёх строк, иначе ошибка), перестал читать/писать
  `missingText`/`moreDetailText`, сводка в Telegram дополнена строкой «Без Whygrid: …».
- `app/tournament/[id]/intro-survey.tsx` — новый компонент `PmfChoiceGroup` (три
  radio-кнопки текстом, не шкала), новый порядок полей, текстовые поля под непонятно/
  подачу и moreDetail/missing убраны из формы.
- Переводы `messages/ru.json` + `en.json`: `IntroSurvey` (новые/переформулированные
  ключи), `Errors.introSurveyMissingRatings` (текст под 5 обязательных полей вместо 4),
  `Admin.surveys*` (три новых ключа для подписей PMF-вариантов, `surveysMoreDetail`/
  `surveysMissing` помечены «(устар.)» — историческая витрина, не новый ввод).
- `features/admin/stats.ts` + `app/admin/page.tsx` — `SurveyResponseRow.pmfReaction`
  прокинут в запрос и показ; старые текстовые legacy-поля по-прежнему отображаются на
  исторических записях (условный рендер по `!= null`, логика не менялась).
- Тесты не потребовали правок (`introSurveyResponse.findMany` в моке `stats.test.ts`
  уже возвращал пустой массив). Проверено: `tsc --noEmit` чисто, `npm run build` чисто,
  `npm test` — 1350/1350 (15 пропущенных, не связаны с задачей).
