# План: бот-сторож в Telegram (тревоги + дайджест)

**Дата:** 2026-06-18
**Автор:** Клод (по запросу Артёма)
**Статус:** черновик

## Цель

Служебный Telegram-бот шлёт администратору (Артёму) на телефон мгновенные тревоги о поломках на проде и утреннюю сводку состояния продукта — чтобы узнавать о проблеме сразу, а не когда заметит пользователь.

## Контекст

Описан в `architecture/06-внешние-сервисы.md` раздел 2.2: адаптер `adapters/notify/telegram/`, порт «сообщи администратору о событии». В коде ещё нет ни адаптера, ни cron-задач (есть только `adapters/llm/`).

**Связь с другим ботом:** это НЕ мост `@kekoz_bot` (управление Клодом с телефона, крутится на ПК Артёма). Это отдельный служебный бот на сервере.

**Сетевое ограничение (проверено 2026-06-18):**
- VM в Yandex Cloud (РФ) до `api.telegram.org` **не достаёт** — таймаут, КОД:000 (та же стена, что и с Claude).
- Казахстанский релей `92.60.75.87` до Telegram **достаёт** — ответ 401.
- Вывод: тревоги с VM идут через тот же релей, что и Claude.

## Фазы

### Фаза 1. Адаптер + тревога «задача в карантине» (ядро сторожа)

**Релей (на VPS `92.60.75.87`, делаем вместе — команды даю, Артём запускает):**
- [ ] Добавить в nginx проход для Telegram: `location /tg/ { proxy_pass https://api.telegram.org/; proxy_ssl_server_name on; }` с той же проверкой `x-proxy-secret`.
- [ ] **Отключить access_log для `/tg/`** — токен бота Telegram лежит в адресе запроса, в логи попасть не должен (защита секрета).
- [ ] Проверить боевым `curl` через релей с реальным токеном, что сообщение доходит в Telegram.

**Бот (делает Артём):**
- [ ] Создать бота у `@BotFather`, получить токен. Узнать свой `chat_id`.
- [ ] Вписать в `.env.production` на VM: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_ADMIN_CHAT_ID`, `TELEGRAM_BASE_URL` (релей). Клод файлы `.env*` не трогает.

**Код (Клод) — СДЕЛАНО 2026-06-18:**
- [x] `config/notify.ts` — чтение токена/chat_id/base_url/секрета из env; флаг `isNotifyConfigured`.
- [x] `infrastructure/adapters/notify/` — порт `NotifyPort` (`notifyAdmin`), `telegram.ts` (HTTPS POST на `<релей>/bot<токен>/sendMessage` с `x-proxy-secret`, серт через уже настроенный `NODE_EXTRA_CA_CERTS`), `noop.ts` (бот не настроен → молчит), `index.ts` (выбор адаптера + `safeNotifyAdmin` — мягкая отправка).
- [x] Тревога в `infrastructure/queue/worker.ts`: `POISONED` → `safeNotifyAdmin(...)`. Мягко: падение Telegram не роняет воркер (статус уже сохранён).
- [x] Тесты: `__tests__/adapters/notify/telegram.test.ts` (запрос/URL/секрет, default-URL, ошибка, глушение); `__tests__/queue/worker-notify.test.ts` (POISONED зовёт, DONE — нет). 134 теста зелёные, tsc и build чистые.

**Решение по боту (2026-06-18):** используем того же `@kekoz_bot` (chat_id 440359604). Для отправки тревог это не мешает мосту — мост только принимает сообщения (getUpdates), сторож только шлёт (sendMessage), конфликта нет. При необходимости позже заведём отдельного.

**Готово, когда:** на проде упавшая задача → пуш в Telegram за секунды.

### Фаза 2. Утренний дайджест + тревога «очередь стоит»

- [ ] `infrastructure/jobs/daily-digest.ts` — сборка сводки по доступным данным: **Пользователи** (регистрации/загрузки/активные диалоги за сутки), **Очередь** (ждут / в карантине / среднее время). Один вызов `notifyAdmin`.
- [ ] cron-маршрут `app/api/cron/daily-digest` (защита `CRON_SECRET`, как у `run-tasks`), на VM — cron в 9:00.
- [ ] Тревога «очередь не разгребается»: задача висит в `PENDING` дольше нормы → сигнал (в дайджесте или отдельным алертом).
- [ ] Тесты на сборку дайджеста.

## Критерии готовности (Фаза 1)

- [ ] Адаптер `notify/telegram` реализует порт, секреты только из env.
- [ ] Релей форвардит Telegram, токен не пишется в логи.
- [ ] POISONED-задача на проде шлёт пуш; падение Telegram не роняет воркер.
- [ ] Тесты зелёные, tsc и build чистые.

## Риски

- **Релей = единая точка отказа** (уже отмечено для Claude). Теперь и тревоги зависят от него. Если релей лежит — и LLM, и сторож молчат. Запасной канал тревог (email самому себе) — когда появится email-адаптер.
- **Токен в адресе запроса** — закрываем отключением логов на `/tg/`; в самом приложении токен только из env, в код/git не попадает.
