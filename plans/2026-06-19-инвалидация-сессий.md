# Инвалидация сессий при смене пароля + «Выйти на всех устройствах»

**Запрос:** смена пароля должна гасить старые сессии (сейчас stateless HMAC-cookie живёт 30 дней
независимо ни от чего). Плюс кнопка «Выйти на всех устройствах». Показать в кабинете дату
последней смены пароля.

**Решение (одобрено Артёмом 2026-06-19):**
- Дата `passwordChangedAt` — для показа в кабинете (ставится только при смене пароля).
- Служебная метка `sessionsValidFrom` — по ней реально гасятся куки: cookie несёт `iat`
  (момент выдачи), сессия валидна если `iat >= sessionsValidFrom`. Бьётся при смене пароля
  И при «выйти на всех устройствах».
- «Выйти на всех устройствах» гасит ВСЕ сессии включая текущую → редирект на /login.
- Проверку `iat >= sessionsValidFrom` встраиваем в WHERE уже существующих запросов трёх точек
  авторизации (`requireSession`, `getCurrentPlayer`, `authorizeHand`) — без новых обращений к БД.

## Фазы

- [x] 1. Схема + миграция: `password_changed_at` (nullable), `sessions_valid_from` (NOT NULL
      default now()). Бэкфилл существующих → `created_at`. Применена к dev и test вручную
      (`db execute`+`migrate resolve`) из-за давнего drift.
- [x] 2. `session.ts`: `iat` в payload; `getSession` возвращает `{playerId, iat}`; `requireSession`
      — фильтр `sessionsValidFrom <= iat`.
- [x] 3. `queries.getCurrentPlayer` + `ownership.authorizeHand` — тот же фильтр.
- [x] 4. `actions.ts`: `changePassword` ставит `passwordChangedAt`+`sessionsValidFrom`=now и
      обновляет cookie текущего устройства; новый `logoutEverywhereAction` (гасит всё, включая
      текущее, → /login).
- [x] 5. UI кабинета: кнопка «Выйти на всех устройствах» + показ даты смены пароля.
- [x] 6. Тесты: session.test обновлён; инвалидация проверена через changePassword (старая кука
      гаснет, текущая остаётся) и logoutEverywhere; passwordChangedAt.
- [x] 7. tsc + 168 тестов + build зелёные. Журнал решений в `architecture/03-база-данных.md`.

## Итог

Сделано полностью, локально проверено. **В прод не выкачено** — жду явного «деплой».

Главное по ходу: всплыл реальный баг округления времени — `sessions_valid_from` при регистрации
ставила БД (`@default(now())`, TIMESTAMP(3) округляет вверх), а `iat` куки — JS (округление вниз).
В пределах одной мс метка могла превысить `iat`, и `requireSession` выкидывал бы только что
вошедшего на /login. Лечится постановкой `sessions_valid_from` при регистрации из JS-времени
(createSession берёт `iat` уже после create — он не меньше). Без фикса флак ловился только в
сквозном прогоне тестов.

`logout-everywhere`. Журнал — в `03-база-данных.md`.
