# Чат по раздаче (свободные вопросы после вердикта)

**Дата:** 2026-06-15
**Статус:** в работе

> Реализует «Сообщение чата» из [[../architecture/02-сущности]] и [[../architecture/03-база-данных]] (`chat_messages` — таблица и индекс уже в схеме, миграции не требуются). Последний кусок продуктового цикла из [[../architecture/10-план-реализации]] (Неделя 5): «по любой разобранной раздаче можно задать свободный вопрос в чате и получить ответ в контексте этой руки».

---

## 0. Решения по объёму (без согласия — нет смены схемы/промптов в проде)

- **Где открывается чат:** на странице раздачи `/tournament/[id]/hands/[handId]`, только для CRITICAL-раздач после `dialogue.state === "VERDICT_SHOWN"`. Это единственная существующая страница раздачи; STRONG/MEDIUM раздачи сейчас вообще не имеют своей страницы (не входят в `handsForDialogue` на странице турнира) — показ чата для них требует отдельной задачи «страница разобранной раздачи» и сюда не входит.
- **Почему после VERDICT_SHOWN, а не сразу:** правило 2 защищает именно `Dialogue` (вопрос раньше оценки). Чат — отдельная сущность и формально его можно не гейтить, но открывать его до того, как сократовский диалог закончен, даёт игроку обходной путь спросить «а как правильно» напрямую — открываем чат только когда вердикт уже показан.
- **Цикл «вопрос → ответ»:** как и весь остальной LLM-конвейер — через очередь (Task/worker), не синхронный вызов из server action. Один открытый вопрос игрока за раз: если последнее сообщение в треде от PLAYER без ответа SYSTEM — новое сообщение не принимается (та же идемпотентная защита, что в `submitAnswer`, без новых полей в БД).
- **Новый промпт `config/prompts/chat-reply.ts`** — формально подпадает под «Спроси разрешения №5», но фича ещё не в проде (как и diалог раньше — см. прецедент в `2026-06-13-dialog-multiround.md`), риск для живых пользователей нулевой.

## 1. LLM-порт и промпт

### `infrastructure/adapters/llm/types.ts`

```ts
export type ChatMessageSummary = { author: "PLAYER" | "SYSTEM"; text: string };

export type ChatReplyRequest = {
  history: ChatMessageSummary[]; // вся история треда, включая последнее сообщение игрока
  analysisSummary: string;       // как сыграл / оптимально / итоговый вердикт диалога
  chipResult: number;
  tableSnapshot: TableSnapshot;
  tournament: TournamentContext;
};

export type ChatReplyResult = { reply: string };
```

`LlmPort` — новый метод `generateChatReply(request: ChatReplyRequest): Promise<ChatReplyResult>`.

### `config/prompts/chat-reply.ts` (новый)

Системный промпт — те же обязательные строки правила 1 («не вычисляй метрики самостоятельно», «если не уверен — уточняющий вопрос, а не категоричный совет») + тон сократовского тренера, разговорный русский, термины без метафор (как в `verdict.ts`/`hand-analysis.ts`).

Пользовательский промпт: контекст турнира + снимок стола (`renderTableSnapshot` из `hand-analysis.ts`) + `analysisSummary` (что уже разобрано по раздаче) + вся история чата (`Игрок: ...` / `Тренер: ...`) → просит ответ на последний вопрос игрока.

Схема ответа: `{ "reply": "ответ игроку" }`.

### `fake.ts` / `anthropic.ts`

- `fake.generateChatReply` — детерминированный текст, упоминающий последний вопрос игрока (без сети).
- `anthropic.generateChatReply` — `callClaude(CHAT_REPLY_SYSTEM_PROMPT, buildChatReplyPrompt(request))`, валидация `{ reply: string }`.

## 2. `analysisSummary` — сборка краткого контекста разбора

Небольшой helper (в `features/chat/queries.ts` или рядом) собирает текст из `hand.analysis` (`played`/`optimal`/`note`) и `dialogue.verdict` (для CRITICAL — финальный вердикт диалога, не `draftVerdict`):

```ts
function buildAnalysisSummary(hand, dialogue): string {
  const a = hand.analysis as { played: string; optimal: string };
  const parts = [`Как сыграл Hero: ${a.played}`, `Оптимальная линия: ${a.optimal}`];
  if (dialogue?.verdict) parts.push(`Итоговый вердикт после диалога: ${dialogue.verdict}`);
  return parts.join("\n");
}
```

## 3. Очередь — `GENERATE_CHAT_REPLY`

`infrastructure/queue/steps/generate-chat-reply.ts`, по образцу `generate-verdict.ts`:

- Загружает `hand` (+ `tournament`, `dialogue`) и все `chatMessage` по `handId`, по возрастанию `createdAt`.
- Идемпотентность: если сообщений нет ИЛИ последнее сообщение не от `PLAYER` — выход без действий (ответ уже дан или нечего отвечать).
- Гейт: `dialogue?.state !== "VERDICT_SHOWN"` → ошибка инварианта (карантин) — `sendChatMessage` не должен ставить эту задачу раньше.
- Собирает `ChatReplyRequest` (история + `analysisSummary` + метрики турнира/раздачи из `tournament`/`hand`, как в `generate-verdict.ts`), вызывает `getLlmAdapter().generateChatReply(...)`, создаёт `ChatMessage{author: SYSTEM, text: reply}`.

Регистрация в `bootstrap.ts`: `registerStep("GENERATE_CHAT_REPLY", generateChatReplyStep)`.

## 4. Фича `features/chat/`

### `queries.ts`

```ts
export type ChatMessageView = { author: "PLAYER" | "SYSTEM"; text: string; createdAt: Date };
export type ChatView = { available: boolean; awaitingReply: boolean; messages: ChatMessageView[] };

export async function getChat(handId: string): Promise<ChatView | null>
```
`available` = `dialogue` существует и `state === "VERDICT_SHOWN"` (для STRONG/MEDIUM без диалога — `false`, см. раздел 0). `awaitingReply` = последнее сообщение от `PLAYER`.

### `actions.ts`

```ts
type SendChatMessageResult =
  | { ok: true }
  | { ok: false; error: "HAND_NOT_FOUND" | "CHAT_NOT_AVAILABLE" | "EMPTY_MESSAGE" | "AWAITING_REPLY" };

export async function sendChatMessage(input: { handId: string; text: string }): Promise<SendChatMessageResult>
```
Проверяет гейт (раздел 0), идемпотентно отклоняет, если последнее сообщение — от `PLAYER` без ответа; иначе создаёт `ChatMessage{PLAYER}` + `enqueue("GENERATE_CHAT_REPLY", { handId })` в одной транзакции.

## 6. UI

На странице `app/tournament/[id]/hands/[handId]/page.tsx`, в блоке `dialogue.state === "VERDICT_SHOWN"`, под вердиктом — секция «Чат»:

- `chat-thread.tsx` — список сообщений (PLAYER — справа/выделено `bg-card`+border, SYSTEM — обычный текст, как вопросы диалога).
- `chat-form.tsx` (client, `useActionState`, по образцу `answer-form.tsx`) — `Textarea` + `Button`, отключена/скрыта если `awaitingReply`.
- `chat-wait-client.tsx` — поллинг `/api/chat/[handId]` каждые 3с при `awaitingReply`, по образцу `wait-client.tsx` (включая кнопку «Запустить воркер» через существующий `triggerWorkerAction`).
- Новый server action `sendChatMessageAction` в `app/tournament/[id]/hands/[handId]/chat-actions.ts`, аналог `submitAnswerAction`.

Если `available === false` (STRONG/MEDIUM или диалог не завершён) — секция «Чат» не рендерится.

(`GENERATE_CHAT_REPLY`), как и весь остальной LLM-конвейер. Гейт `VERDICT_SHOWN` и

завершён. STRONG/MEDIUM раздачи без своей страницы — вне объёма (раздел 0), отдельная
задача «страница разобранной раздачи».
