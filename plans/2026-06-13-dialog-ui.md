## 1. Что видит игрок

На странице турнира (`app/tournament/[id]`) — список раздач, по которым открыт диалог (`CRITICAL`-раздачи с `Dialogue`), с прогрессом по раундам и ссылкой на экран раздачи.

На экране раздачи (`app/tournament/[id]/hands/[handId]`):
- контекст раздачи: что произошло (`hand.analysis.played`) и итог в фишках (`hand.chipResult`) — без этого вопрос «почему ты так сделал?» висит в воздухе;
- история отвеченных раундов: вопрос + ответ игрока, по порядку;
- если есть открытый (неотвеченный) вопрос — он и форма ответа;
- если игрок только что ответил и ждём следующий шаг (фон ещё не сработал) — статус ожидания + кнопка «запустить воркер» (как на `/status`);
- если диалог завершён — итоговый вердикт.

## 2. `getDialogue` — контракт и реализация

Новый файл `trener/features/dialogue/queries.ts`:

```ts
export type DialogueRoundView = {
  roundNumber: number;
  question: string;
  answer: string | null;
};

export type DialogueView = {
  handId: string;
  state: DialogueState;          // QUESTION_ASKED | ANSWER_RECEIVED | VERDICT_SHOWN
  totalRounds: number;           // getDialogueRoundsPerHand()
  rounds: DialogueRoundView[];   // отсортированы по roundNumber asc
  verdict: string | null;
  hand: {
    chipResult: number;
    played: string | null;       // hand.analysis.played, если есть
  };
};

export async function getDialogue(handId: string): Promise<DialogueView | null>;
```

Реализация: один `prisma.dialogue.findUnique({ where: { handId }, include: { rounds: {orderBy: {roundNumber: "asc"}}, hand: true } })`, `null` если диалога нет. `hand.played` достаётся из `hand.analysis as {played?: string} | null` (правило 1 — никаких вычислений, только чтение готового JSON). `totalRounds` — через `getDialogueRoundsPerHand()` из `config/dialogue.ts`.

## 3. Маршруты и страницы

### `app/tournament/[id]/page.tsx` (доработка существующей)

Добавить секцию «Раздачи для разбора»: `prisma.hand.findMany({ where: { tournamentId: id, dialogue: { isNot: null } }, include: { dialogue: { include: { rounds: true } } } })`. На каждую — ссылка `/tournament/{id}/hands/{handId}`, рядом badge состояния и `раунд X/N` (X = число раундов с заполненным `answer`, либо `rounds.length`, N = `getDialogueRoundsPerHand()`).

### `app/tournament/[id]/hands/[handId]/page.tsx` (новый)

Серверный компонент:
1. Проверка владения: `hand.tournament.id === id`, `tournament.playerId === DEMO_PLAYER_ID`, `!tournament.deletedAt` — иначе `notFound()` (по образцу текущей `app/tournament/[id]/page.tsx`).
2. `getDialogue(handId)` — если `null`, `notFound()`.
3. Рендер: контекст раздачи → история раундов → текущее состояние (см. таблицу ниже) → ссылка `← К турниру`.

### `app/tournament/[id]/hands/[handId]/answer-form.tsx` (новый, серверная форма)

Инлайн server action в самой странице (или соседний файл с `"use server"`):
```ts
async function submitAnswerAction(formData: FormData) {
  "use server";
  const answer = String(formData.get("answer") ?? "");
  const result = await submitAnswer({ handId, answer });
  if (result.ok) revalidatePath(`/tournament/${tournamentId}/hands/${handId}`);
}
```
Форма — `<textarea name="answer">` + кнопка «Ответить». Ошибка `EMPTY_ANSWER` — показать текст под полем (без `alert`).

### `app/tournament/[id]/hands/[handId]/wait-client.tsx` (новый, клиентский)

Для состояния «ответ принят, ждём фон» — переиспользует паттерн `app/status/status-client.tsx`: опрос каждые 3 сек через новый `app/api/dialogue/[handId]/route.ts` (тонкая обёртка над `getDialogue`, по образцу `app/api/status/route.ts`), кнопка «запустить воркер» — реэкспорт `triggerWorkerAction` из `app/status/actions.ts`. При смене состояния — `router.refresh()`.

## 4. Состояния экрана раздачи

| `dialogue.state` | Последний раунд отвечен? | Что видит игрок |
|---|---|---|
| `QUESTION_ASKED` | нет (это и есть открытый раунд) | История прошлых раундов + текущий вопрос + форма ответа |
| `ANSWER_RECEIVED` | да, ждём `GENERATE_DIALOGUE_QUESTION`/`GENERATE_VERDICT` | История + «Ответ принят, готовим следующий шаг...» + `wait-client` (опрос/кнопка воркера) |
| `VERDICT_SHOWN` | да (раунд N) | Вся история + `verdict`, форма не показывается |

Инвариант (правило 2) уже гарантирован backend — экран не должен сам решать, когда показывать вердикт, он просто отражает `dialogue.state`.
