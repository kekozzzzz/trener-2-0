# План: вывод по открывашкам + кликабельные руки в обзоре турнира

**Дата:** 2026-06-25
**Откуда выросло:** запрос Артёма — на общей картине турнира хочется (1) вывод по
открывашкам («такие руки ты открываешь слишком широко, их открывать не надо») и
(2) когда в выводе упоминается рука (напр. «валет-десять»/«JT») — само её
название кликабельно и ведёт на разбор именно этой раздачи. Ниже по странице
любую раздачу и так можно открыть (уже есть).

---

## Решения и привязка к правилам

| Решение | Почему |
|---|---|
| Открывашки считает **парсер детерминированно**, не LLM | Правило 1/2 — «попадание руки в чарт» это число; ошибётся LLM = катастрофа. В `facts.ts` это и было отложено «до источника чартов». Источник появился — утверждённый baseline RFI-чарт. |
| RFI-чарт живёт в **конфиге** (`config/poker/`), не в коде логики | Правило 3 — покерные диапазоны/лимиты только в конфиге/БД. |
| Называем только руки **заметно шире** диапазона, граничные пропускаем | Прямое требование Артёма: «не по шаблону, граничные не пиши, пиши сильно шире ренжа». |
| LLM получает готовый список рук-открывашек как **факты**, только формулирует | Тот же паттерн, что `renderHandFacts` — числа от парсера, LLM объясняет словами. |
| Инлайн-ссылки только на **раздачи карточки** (у них есть страница разбора) | Раздача-открывашка часто маленький фолд без разбора → страницы нет. Ссылки нужны на «руки, принёсшие поражение» — это и есть раздачи карточки. |
| Карты руки в ссылке рендерит **наш код** из снимка, не LLM-текст | LLM указывает только ГДЕ сослаться (индекс), подпись-карты берём из парсера → нельзя переврать карты (правило 2). |
| Блок отдельных карточек-«моментов» под обзором **убираем** | Дублирует инлайн-ссылки; «любую раздачу кликнуть» уже даёт список ниже. |
| Миграция БД **не нужна** | Всё считается на лету из `Hand.tableData`; обзор лежит в существующем `tournament.summary` (JSON). |

## Часть A — Вывод по открывашкам

### A1. RFI-чарт в конфиг `[x]`
- Файл `trener/config/poker/rfi-chart.ts`: открытые диапазоны по позициям
  EARLY / HJ / CO / BTN / SB (baseline из `plans/2026-06-20-режим-тренировка.md`,
  утверждён Артёмом 2026-06-20). BB не открывает.
- Представление: для каждой позиции — множество классов рук (`"AKs"`, `"T9o"`,
  `"77"`), развёрнутое из «+»-нотации в полный набор 169-сетки.
- Этот же чарт потом переиспользует режим «Тренировка» (один источник правды).

### A2. Детектор «открылся первым» в парсере `[x]`
- Новый модуль `trener/parser/open-raise.ts` (рядом с `facts.ts`).
- Из снимка раздачи: Hero сделал префлоп-рейз, и **до него** никто добровольно
  не входил (все до Hero — фолд; только посты блайндов/анте). Лимперы или рейз
  впереди → это не открытие, пропускаем.
- Возвращает: позиция Hero + класс руки (`"K7s"`) или `null`.
- Карты → класс: ранги + suited/offsuit/пара (детерминированно из `heroCards`).

### A3. Порог «заметно шире» `[x]`
- Из открытого чарта детерминированно строим «допуск» — диапазон на один шаг
  шире (каждый suited/offsuit-ряд продлеваем на 1 ранг вниз; пары не трогаем).
- Рука-открывашка попадает в вывод, только если она **вне даже этого допуска** →
  это «сильно шире», а не граница. Ширина допуска — параметр в конфиге, подкрутим
  на реальных турнирах.
- Граничные (в допуске, но вне открытого) — молчим.

### A4. Сбор утечки по турниру `[x]`
- В `generate-tournament-summary.ts`: пройти по **всем** раздачам турнира
  (`Hand.tableData`), собрать открывашки-нарушители, сгруппировать по
  позиция+класс (без повторов), оставить N самых ярких примеров.
- Если нарушителей нет — блок открывашек не показываем (правило: не натягивать
  ошибку).

### A5. Передать факты в LLM и оформить промпт `[x]`  ⚠️ правило-разрешение №5
- Расширить `TournamentSummaryRequest`: поле `openLeak?: { position, hand }[]`.
- В `TOURNAMENT_SUMMARY_SYSTEM_PROMPT` — инструкция: если есть `openLeak`,
  отдельной фразой сверху сказать про открывашки, **используя только эти руки**,
  ничего не выдумывая; граничных нет — список уже отфильтрован парсером.
- Промпт — продуктовый контент → **показать Артёму перед применением**.

## Часть B — Кликабельные руки в тексте обзора

### B1. Токены ссылок в overview `[x]`
- Каждой раздаче карточки в запрос уже идёт `index`. Просим LLM, когда
  ссылается на раздачу в тексте, ставить токен `{{h:INDEX}}` (без своей подписи).
- Пост-обработка (как сейчас фильтр moments): `INDEX` вне диапазона → токен
  удаляем; валидный → подставляем `handId` и канонические карты руки из парсера.
- Хранимый вид `overview` — строка с токенами `{{h:HANDID}}`; подпись-карты
  рендерит UI из данных раздачи.

### B2. Рендер инлайн-ссылок на странице `[x]`
- На `app/tournament/[id]/page.tsx` разобрать `overview` на сегменты
  текст / ссылка; токен → `<Link href="/tournament/{id}/hands/{handId}">JT</Link>`.
- Старый блок `summary.moments` (карточки под обзором) убрать.
- Совместимость: старые турниры без токенов рендерятся как обычный текст.
