# Вертикальный срез — один вечер

> **Контекст:** этот срез — первый кирпич Недели 3, выполняется только при исходе GO (≥3 оплат от незнакомцев на Неделе 2). Реализация заблокирована Запретом 6 до прохождения теста спроса.

---

## Срез вечера

**Когда пользователь загружает HH-файл GGPoker MTT, продукт парсит его, сохраняет одну запись турнира в базу и показывает обратно три числа: VPIP, количество рук, итог в бай-инах.**

---

## Что входит

- Одна страница — форма загрузки файла (без авторизации, без стилей, без логотипа)
- Вызов готового парсера из Недели 1 на полученном файле
- Запись одной строки `Tournament` в базу: `id`, `vpip`, `hands_count`, `result_bi`, `created_at`
- Редирект на `/tournament/[id]` — страница с тремя числами и больше ничего

## Что НЕ входит сегодня (явно отрезано)

- Авторизация и аккаунт пользователя
- Подписка и оплата
- Хранение самого HH-файла в S3 (только метрики в строке БД)
- Отбор и разметка раздач по важности
- Сократовский диалог
- LLM / Claude
- Стилевой диагноз
- Сравнение «вчера · средний · оптимально»
- Чат по раздаче
- Обезличивание никнеймов (снимок стола)
- Фоновая очередь — парсинг синхронный, в одном запросе

---

## Сценарии приёмки

### Главный путь

1. Пользователь открывает страницу загрузки
2. Выбирает HH-файл GGPoker MTT из локальной папки, нажимает «Загрузить»
3. Через несколько секунд попадает на `/tournament/[id]` и видит три числа:
   - **VPIP:** 24%
   - **Рук сыграно:** 47
   - **Итог:** −1.8 бай-ина
4. В базе данных появилась одна строка `Tournament` с этими значениями
5. Числа совпадают с ручным подсчётом по этому же файлу

### Сценарий ошибки

1. Пользователь загружает файл кэш-игры или экспорт из PokerStars
2. Парсер возвращает явную ошибку «неподдерживаемый формат»
3. На странице — сообщение: **«Загрузи MTT-турнир GGPoker»**, никаких частичных или приблизительных чисел
