# План: визуальная схема стола в разборе раздачи

Дата: 2026-06-25

## Задача

На странице разбора (`/tournament/[id]/hands/[handId]`) над каждым вопросом диалога
показать схему стола: позиции всех игроков и их **последние действия** на момент
разбираемого решения. По ходу диалога (новая улица/действия) стол перерисовывается.

## Решение (кратко)

- Привязка к КОНКРЕТНОМУ ДЕЙСТВИЮ (точке решения), а не к улице: на одной улице бывает
  несколько решений (рейз→3-бет→пуш→колл) — показать надо ровно ту точку, к которой
  относится вопрос (напр. пуш соперника, под который Hero коллит).
- LLM отдаёт номер действия `tableActionIndex` (действия в промпте пронумерованы `[N]`),
  код ставит метку `{{table:N}}` в текст вопроса (по образцу `{{range}}`). Модель только
  выбирает номер — **числа стола считает парсер из снимка** (Правило 1).
- `tableStateUpTo(snapshot, actionIndex)` — состояние до этого действия включительно;
  место точки решения помечено `isCurrent` (подсветка «▸»). Без миграций.
- Старые диалоги/простые раздачи без метки → fallback: стол на последнем действии.

## Ограничения

- Точность — на уровне отдельного действия: вопрос привязан ровно к одной точке решения
  (номеру действия). Это покрывает кейс «несколько решений на одной улице» (рейз→пуш→колл).
- Корректность номера зависит от LLM: ошибётся номером — стол покажет чуть другой момент,
  но не неверное число (все числа из снимка, Правило 1). Некорректный/вне границ номер
  зажимается рендером, стол не падает.
- Стол-перед-вопросом — только у новых диалогов; старые используют fallback.
