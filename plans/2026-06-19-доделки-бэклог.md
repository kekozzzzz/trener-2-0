## 1. Денежный результат турнира (summary-файл GG)

Идея Артёма: дать опционально загружать GG **summary-файл** рядом с hand history,
чтобы показать реальные деньги (место + нокауты-баунти), которых в HH нет.

- **Опционально:** без summary продукт работает как сейчас; с ним — показываем деньги.
- **Деньги ≠ правильность:** тренер должен уметь сказать «выиграл, но в 9 из 10 повёзло —
  это дисперсия, а не твоя заслуга». Разводим денежный результат и качество решений
  (Правило: решение — навык, результат — случайность).
- **Где:** на странице турнира (`/tournament/[id]`), вне разбора раздач.
- **Переименовать «Итог: N бай-ина»** → денежный результат («+/− $X», сколько выиграл/проиграл).
- **Мультирум:** «источник денежного результата» — отдельной абстракцией. GG: из summary
  (два файла). Другие румы: один файл показывает всё. Не завязываться на GG-специфику.
- **Связь файлов:** summary ↔ hand history по `Tournament #` (тот же ключ, что в дедупликации).
- **Схема БД:** новое поле в `Tournament` или сущность `TournamentSummary` → миграция,
  спросить разрешения (CLAUDE.md «Спроси разрешения» №2).
- **Формат summary (образец в `Test/`, турнир #291235125):**
  `Buy-in: $4.17+$0.71+$4` (приз+рейк+баунти), `You received a total of $2` —
  на руки $2 при бай-ине $8.88 → чистыми −$6.88. Парсить: бай-ин (сумма трёх частей),
  место, полученное всего. Чистый = получено − бай-ин.

## 2. Дозаполнить `name` у демо-турнира в seed

`prisma/seed.ts` создаёт демо-турнир без `name` → на сайте показывается «Турнир»
вместо названия. Парсер и боевая загрузка имя сохраняют корректно — это только демо-данные.
Мелкая правка для опрятного демо.

**(б) Доступ к сайту — закрыто.** Сайт live на постоянном `https://whygrid.app`

`project_deploy_status`.

**(а) LLM-связь / секрет релея — ЗАКРЫТО 2026-06-19.** Был временный IP-обход в
`/etc/nginx/sites-enabled/anthropic-relay` (для VM-IP `81.26.186.177` `x-proxy-secret`
не проверялся). Корень: после ротации секрета 18.06 процесс `trener` держал старый
секрет в памяти, хотя `.env.production` был синхронен. Закрыто: оба секрета на VM
(`ANTHROPIC_PROXY_SECRET`, `TELEGRAM_PROXY_SECRET`) сверены с релеем (совпадают),
`pm2 restart trener --update-env`, удалены обе строки IP-обхода (бэкап
`anthropic-relay.prebypass-removal.*`), `nginx -t` + reload. Проверено: без секрета
оба пути (`/`, `/tg/`) → 403, с секретом → проходят; сайт 200, логи чистые. Доступ к
шлюзу теперь только по секрету.

**(б) Доступ к сайту — ПОЧИНЕНО.** Был эфемерный quick-туннель `*.trycloudflare.com`,
`pm2 restart all` его убил, а РФ-VM не могла зарегистрировать новый. Реализован **план Б**:
сайт пущен через КЗ-релей (он из РФ достижим). Cloudflare (A-запись `whygrid.app →
92.60.75.87`, SSL Flexible) → nginx на релее (vhost `whygrid.app` → `127.0.0.1:8080`) →
реверс-SSH-туннель `relaytunnel` (pm2 на VM: `ssh -N -R 8080:localhost:3000 root@92.60.75.87`)
→ приложение на VM:3000. `pm2 save` сделан. **НЕ делать `pm2 restart all`** — рестартить
только `trener`; `relaytunnel` трогать осторожно (рестарт на пару секунд роняет сайт).
Старый дохлый pm2 `tunnel` (cloudflared) — удалить.

**После восстановления связи:** оживить карантинные задачи на проде —
`UPDATE tasks SET status='PENDING', attempt=0, run_after=now() WHERE status='POISONED';`
