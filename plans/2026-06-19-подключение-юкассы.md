# План: подключение ЮKassa (приём платежей по подписке)

> Создан 2026-06-19. Фаза 1 платёжной стратегии (`architecture/06-внешние-сервисы.md`, журнал 2026-06-17): РФ, ЮKassa, деньги на РФ-счёт. Stripe — позже отдельным адаптером за тем же портом.

## Решения по задаче (согласовано с Артёмом 2026-06-19)

- **Ключи:** сначала оформляется самозанятость (НПД) → боевой магазин ЮKassa → боевые ключи. Тестовый магазин не используем. Код пишем сейчас, живой сквозной тест — после оформления НПД (см. Фаза 5).
- **Модель оплаты:** автоплатёж (рекуррент). Карта сохраняется при первой оплате (`save_payment_method: true`), дальше ЮKassa списывает по `payment_method_id` каждый период.
- **Тарифы:** все три — Базовый / Средний / Максимальный (сейчас $12/$27/$40, в рублях — уточнить точные числа перед Фазой 1).

## Что уже есть

- Таблицы `subscriptions` и `payments` мигрированы (init). Схема грамотная: `external_payment_id` уникален (защита от двойного списания, правило проекта), `payments` append-only, деньги — `Int` в копейках, soft-delete (`deleted_at`).
- **Кода нет вообще:** ни порта, ни адаптера, ни конфига цен, ни гейта доступа, ни вебхука. Цены сейчас захардкожены в `app/pricing/page.tsx` (в долларах) — это надо вынести в конфиг (правило 3) и считать в рублях.

## Архитектурные решения

- **Порт** `PaymentsPort` (`infrastructure/adapters/payments/types.ts`) — вендоронезависимый. Методы: `createCheckout` (первый платёж + сохранить карту → `confirmation_url`), `chargeSaved` (автосписание по `payment_method_id`), `getPayment` (для сверки и верификации вебхука), `parseWebhookEvent`. Бизнес-логика знает только порт (правило 4).
- **Адаптер** `infrastructure/adapters/payments/yookassa.ts` — на `fetch` (Basic-auth `shopId:secretKey`, заголовок `Idempotence-Key`), **без новой библиотеки** (адаптер тонкий, дополнительная зависимость не нужна). `fake.ts` для тестов, `index.ts` — выбор по `PAYMENTS_PROVIDER` (как у `adapters/llm`).
- **Верификация вебхука:** не доверяем телу запроса — по событию заново читаем платёж через `getPayment` (GET /payments/{id}) и работаем по реальному статусу из API ЮKassa. Плюс проверка по IP-аллоулисту ЮKassa.
- **Идемпотентность активации:** вставка `Payment` через `ON CONFLICT (external_payment_id) DO NOTHING`; повторный вебхук не создаёт вторую проводку и второе продление (заложено в схеме и `04-потоки-данных`).
- **Конфиг цен** `config/pricing.ts`: план-коды, суммы в копейках рублей, валюта, месячный лимит турниров на тариф. Бизнес-числа — только в конфиге/env (правило 3). `app/pricing/page.tsx` начинает читать отсюда.
