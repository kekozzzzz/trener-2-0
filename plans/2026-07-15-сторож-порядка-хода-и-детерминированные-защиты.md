# План: сторож порядка хода + детерминированные защиты против галлюцинаций Flash

**Дата:** 2026-07-15
**Контекст:** Инцидент на раздаче 5♦4♦ (Hero SB, флоп K♦5♥J♥, чек-чек-чек). Тренер (Gemini
2.5 Flash) написал «после того как CO и BTN чекнули, ты тоже чекнул» — перевернул порядок
хода. Парсер записал правильно (Hero чек ПЕРВЫМ, потом CO, потом BTN) и явно передал это в
промпт («ты ходишь первым»), но Flash проигнорировала факт. На выдуманном порядке тренер
построил кривой затянутый диалог (4 вопроса про несуществующий стилл, вердикта нет).

**Решение (по итогу обсуждения с Артёмом):** модель НЕ меняем (Pro убивает тариф $7 — ~$0.85
за разбор против ~$0.20 на Flash). Держим Flash, дожимаем детерминированно: не *просим* модель,
а *проверяем за ней* кодом. Философия — как у существующих защит (выдуманная карта, латиница,
CJK): у факта есть объективная истина у парсера → сверяем ответ модели → брак+ретрай при вранье.

**Граница подхода (честно):** кодом закрывается только ФАКТИЧЕСКАЯ зона (порядок, карты, числа,
позиции) — там истина у парсера. Зона СУЖДЕНИЙ (качество совета, логика, тон) кодом не
проверяется — там нет эталона. Наша раздача на 80% про факты.

## Фазы

### Фаза 1 — Сторож порядка хода (главный, лечит баг №2 и половину №3) [x]
- [x] `parser/action-order.ts`: `heroFirstPostflop(snapshot)` — true, если Hero ходит первым на
      каждой постфлоп-улице с действиями; false, если где-то в позиции.
- [x] `parse.ts`: `violatesActionOrder(text)` — узкие regex вокруг ЧЕКА (без \w/\b — на кириллице
      не работают): «…чекнули перед тобой», «до тебя чекнул», «после того как … чекнули, ты …».
- [x] `cleanCoachText`: 5-й параметр `heroFirstPostflop?: boolean`; true + детектор → throw (брак).
- [x] Проброс в `validateHandAnalysis`/`validateNextQuestion`/`validateVerdict`/`validateChatReply`.
- [x] Адаптеры `openrouter.ts` + `anthropic.ts`: передают `heroFirstPostflop(snapshot)`.
- [x] Тесты: parse.test.ts (6 кейсов детектора) + action-order.test.ts (4 кейса включателя).
