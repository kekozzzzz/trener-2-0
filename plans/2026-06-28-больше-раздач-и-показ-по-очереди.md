# Больше раздач, адаптивные критические, показ по очереди

Обсуждение 2026-06-28. Разбор подешевел (DeepSeek) — снимаем старые «дорогие» лимиты.
Решения Артёма: раздач — от числа спорных, потолок ~20; критических — адаптивно, потолок 5;
показ раздач по очереди (вариант 2). Память спотов («такой же спот, как раньше») — ОТДЕЛЬНЫМ
планом после этого (нужна колонка в БД + правка боевого промпта, оба под разрешение).

## 1. Больше раздач на карточку — масштаб от числа спорных, потолок 20

Файл: `features/card/select-hands.ts`. Было: `CARD_TARGET_TOTAL = 10`, `CARD_MAX_STRONG = 5`
(сильные искусственно резались до 5, добивали средними до 10). Стало:
- `CARD_MIN_TOTAL = 10`, `CARD_MAX_TOTAL = 20`.
- Спорные (CRITICAL + STRONG) — главный материал, берём ВСЕ, до потолка 20 (сильные больше не режем).
- target = clamp(числоСпорных, 10, 20). Средними добиваем только до нижней планки (когда спорных < 10).
- Малый турнир → ~10 как раньше; глубокий ран с кучей спорных → до 20.

## 2. Критические — потолок 3 → 5

Файл: `parser/ggpoker/classify.ts`, `MAX_CRITICAL_HANDS = 3 → 5`. Число уже адаптивное
(`min(числоСпорныхПотерь, потолок)`), порог «дороговизны» не вводим — лишняя сложность,
сортировка по размеру потери уже даёт самые дорогие сверху. Фикстура приёмки (2 критические)
не затрагивается. Правило 2 цело: критические по-прежнему ведут сократовский диалог.

## 3. Показ раздач по очереди (вариант 2)

Дедик-экран «Тренер думает» прятал прогрессивный показ. Меняем: на странице турнира во время
разбора показываем обычную страницу + баннер этапов сверху, а раздачи всплывают в списках
по мере готовности; общая картина собирается последней (как и сейчас).
- `analysis-progress.tsx` — теперь и стример: router.refresh() при росте handsReady (новые
  раздачи появляются), не только в конце. Потолок опросов поднять (больше раздач).
- `page.tsx` — убрать выделенный экран `if (processing) return ...`; баннер этапов в обычной
  странице при processing; убрать дублирующий нижний плейсхолдер «Разбираем раздачи турнира».

## Доработка 2026-06-28: описание + карты по каждой раздаче

По просьбе Артёма — короткое описание «что было» и реальные карты в каждой строке списка,
чтобы узнать момент и запомнить руку.
- `parser/hand-summary.ts` — `heroDecisionLabel`: последнее решающее действие Hero
  (олл-ин/рейз/ставка/колл, колл олл-ина отдельно) + улица. Только факты, БЕЗ оценки
  качества руки — оценка это работа тренера (Правило 1). Тест `__tests__/parser/hand-summary.test.ts`.
- `components/poker/hole-cards.tsx` — компактный монохромный показ карт Hero.
- `page.tsx` — карты+описание в строках критических и сильных/средних; новая группа
  «Разбираем сейчас» (pendingHands: отобраны, разбор не готов) — раздачи «в работе»
  с описанием, пока турнир считается.
- Качество руки («плохая/слабая») детерминированно НЕ навешиваем (можно ошибиться, спот
  контекстный). Если хочется словесной оценки в строке — это короткий вердикт от LLM,
  правка боевого промпта (разрешение Артёма), логично сделать вместе с памятью спотов.

Проверка: tsc чист, build зелёный, hand-summary 5/5. Полный набор флакает на изоляции
тестовой БД (queue/acceptance делят базу) — в изоляции всё зелёное, это не регресс. НЕ задеплоено.

Критических подтвердил: ДО потолка, не ровно (slice без нижнего порога) — 1 крупная ошибка → 1 критическая.

Потолок критических поднят 5→7 (запрос Артёма: запас под турниры-катастрофы). Структура цены:
обычная раздача = 1 вызов разбора; критическая = разбор + сократовский диалог (многораундовый,
тратит, только когда игрок отвечает). Некритические открывают ЧАТ (GENERATE_CHAT_REPLY) —
свободный вопрос→ответ, один вызов на вопрос по желанию, НЕ сократовская state-машина.
