# Админ-статистика: вкладка владельца со сводкой по продукту

## Боль

Владельцу негде увидеть картину продукта целиком: сколько человек зарегистрировалось
сегодня/вчера, из каких стран заходят, сколько входов, сколько игроков попробовали
бесплатный разбор и сколько из них купили подписку. Сейчас есть только `/status`
(свои турниры + расходы LLM) и разрозненные данные в базе.

## Решения (согласованы с Артёмом 2026-07-02)

1. **Журнал событий входа** — новая таблица `auth_events`: регистрация, вход по паролю,
   вход по волшебной ссылке, неудачная попытка входа (последнее — предписание
   `architecture/07-безопасность.md` раздел 2, до сих пор не было реализовано).
2. **Страна по IP** — библиотека `geoip-country` (локальный справочник «IP → страна»,
   8 МБ, база обновляется у автора ежедневно; сетевых запросов нет). Храним только
   ISO-код страны («RU»), сам IP-адрес НЕ сохраняем — минимизация ПДн.
3. **«Входы на сайт» = входы в аккаунт** (не анонимные посещения). Посещаемость
   анонимов — потом отдельно (Яндекс.Метрика уже в стеке, но не подключена).
4. Вкладка — страница `/admin`, доступ только `isAdminEmail` (config/admin.ts),
   остальным — 404. Ссылка в шапке видна только владельцу.

## Что показывает /admin

- **Регистрации**: сегодня / вчера / 7 дней / 30 дней / всего + мини-график по дням.
- **Входы**: сегодня / вчера / 7 / 30 + уникальные игроки + график по дням.
- **Страны**: топ стран по входам и регистрациям за 30 дней.
- **Бесплатный разбор**: сколько игроков получили готовый разбор, из них купили
  подписку (конверсия), сколько «попробовали и пока не платят».
- **Подписки**: активные по тарифам, новые/отменённые за 30 дней.
- **Деньги**: платежи (успешные, возвраты) за сегодня / 7 / 30 дней.
- **Турниры**: загрузки за периоды, ошибки разбора, нераспознанные файлы.
- **Диалоги/чат**: отвеченные раунды, сообщения игроков за периоды.
- **Расходы LLM**: сводка из готового `buildCostReport` (24 ч / 30 дней).
- **Очередь**: задачи PENDING / PROCESSING / POISONED / FAILED.

«Сегодня/вчера» считаются по московскому времени (env `ADMIN_TZ_OFFSET_HOURS`, дефолт 3).

## Правила проекта

- Правило 1 не затронуто (никаких покерных чисел, только продуктовые счётчики).
- Правило 3: смещение пояса — в `config/admin.ts` через env.
- Запрет 5: журнал только append, ничего не удаляем.
- ПДн: IP не хранится; страна — не ПДн. Email'ы игроков видит только владелец
  (обычным пользователям страница отдаёт 404 через `notFound()`).

## Риск, проверить при деплое

Прод-трафик идёт через два nginx (КЗ-релей 92.60.75.87 → VM). Если релей не ставит
`X-Forwarded-For`/`X-Real-IP`, все входы получат страну KZ (IP релея) или NULL. При
деплое проверить конфиг релея и при необходимости добавить проброс заголовков. Миграция
на проде применится штатно (instrumentation.ts → `prisma migrate deploy` при старте).
Мой файл миграции содержит также выравнивание `hands.viewed_at` до TIMESTAMP(3)
(старая ручная миграция создала без точности) — безопасно, усекаются микросекунды.
