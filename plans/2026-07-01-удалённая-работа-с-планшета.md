# Удалённая работа с планшета (при выключенном компьютере)

**Дата:** 2026-07-01
**Задача:** Артём уезжает на несколько дней. Хочет с Android-планшета получить тот же функционал, что и на компьютере: менять/добавлять код и деплоить в прод — при выключенном ПК.
**Условие безопасности (от Артёма):** телеграм-ботами, кроме него, не должен пользоваться никто.

---

## Картина целиком

«То же, что на компьютере» складывается из двух частей:

- **Часть A — писать код** → Claude Code в облаке (браузер планшета). Настройки почти не требует, работает уже сейчас.
- **Часть B — деплоить в прод** → новая защищённая команда деплоя телеграм-боту. Это и надо построить.

---

## Часть A. Кодить с планшета (готово почти из коробки)

Claude Code в браузере (claude.ai/code, приложение Claude для Android) запускается **в облаке Anthropic**, берёт проект **из GitHub** (`kekozzzzz/trener-2-0`), а не с диска. ПК может быть выключен.

**Что нужно сделать перед отъездом:**
- [ ] Запушить локальные коммиты на GitHub. Сейчас `master` на **3 коммита впереди** origin (чарты-грейдеры) + не закоммичен профиль оппонента. Иначе в облаке будет старая версия.
- [ ] Проверить, что подписка Артёма включает Claude Code на вебе.
- [ ] Один раз залогиниться с планшета и открыть проект — убедиться, что репозиторий подхватывается.

**Честные границы (это НЕ 100% копия компьютера):**
- В облаке нет твоего `.env` с боевыми секретами — для написания кода и тестов чаще и не нужен.
- Из облака нельзя дотянуться до прод-SSH через релей — поэтому деплой вынесен в Часть B.
- Результат работы в облаке складывается в GitHub как ветка/PR; на прод он попадает только через деплой (Часть B).

## Часть B. Деплой с планшета через телеграм-бота

### Что уже есть (проверено в коде)

Бот **@whygrid_bot** (код в репозитории) уже защищён двумя слоями:

1. **Секрет вебхука** — `app/api/webhooks/telegram/route.ts:10-13`: запрос без секретного токена в заголовке отлетает 401.
2. **Проверка chat_id** — `infrastructure/posting/webhook.ts:31-33`: команду исполняет только Артём. Чужие сообщения бот НЕ исполняет, а пересылает как отзыв (`webhook.ts:86-101`).

То есть команду деплоя мы вставляем в готовый защищённый механизм, а не строим новую дырявую кнопку.

### Фазы

- [ ] **Фаза 1. Разобрать реальную процедуру деплоя.**
      Настоящий прод деплоится бандлом через КЗ-релей (92.60.75.87) с SSH-джампом. Эта процедура на компьютере Артёма, не в репозитории. Задокументировать её по шагам — без этого команду не к чему подключать.

- [ ] **Фаза 2. Серверный скрипт деплоя.**
      Скрипт на сервере (релей/прод-VM), который по сигналу сам: подтягивает свежий `master` с GitHub → ставит зависимости → билд → **прогоняет тесты парసера** → и только если зелено, выкатывает. Красные тесты = деплой отменён (Запрет 4 проекта). Ведёт лог каждого запуска.

- [ ] **Фаза 3. Команда `/deploy` боту.**
      В `handleMessage` (`webhook.ts`) добавить обработку команды `/deploy` — ТОЛЬКО для admin chat_id. Схема: `/deploy` → бот отвечает «Точно выкатываем `<последний коммит>`?» с кнопкой подтверждения → по подтверждению дёргает серверный скрипт из Фазы 2 → присылает результат (успех/ошибка + лог).

- [ ] **Фаза 4. Проверка безопасности всех ботов.**
      - Подтвердить, что `/deploy` недоступен никому, кроме admin chat_id (тест на чужой id → «нет доступа»).
      - Проверить бота-сторожа **@kekoz_bot** на релее (его код НЕ в этом репозитории): убедиться, что он тоже слушается только Артёма. Если нет — закрыть.
      - Секрет вебхука выставлен и не в репозитории.

- [ ] **Фаза 5. Hardening + приёмка.**
      Отдельный проход: подтверждение обязательно, деплой идемпотентен, откат при падении, ничего не деплоится при красных тестах. Приёмка вживую до отъезда.
