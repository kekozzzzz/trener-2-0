# План: Личный кабинет (Мои турниры + Аккаунт)

**Дата:** 2026-06-15
**Автор:** Клод (с Артёмом)
**Статус:** завершён

## Цель

Дать игроку вернуться к уже сделанным разборам (список загруженных турниров) и управлять своим аккаунтом (email, смена пароля, закрытие). Закрыть боль из бэклога: после загрузки нет способа вернуться к прошлому турниру.

## Контекст

Сейчас турниры есть в БД (`tournaments`: `playedAt`, `vpipPercent`, `handsCount`, `resultBuyins`, `styleDiagnosis`, `status`, `deletedAt`), но списка нигде нет — после загрузки попадаешь на `/tournament/[id]` и обратно к старому турниру не вернуться. Навигация (`AuthNav`) для залогиненного: только Тарифы / email / Выйти.

Архитектура уже задаёт замысел:
- `03-база-данных.md`: «список своих турниров — по дате игры, свежие сверху».
- `07-безопасность.md`: кабинет = турниры + подписка + изменить данные входа + закрыть аккаунт.
- `08-структура-кода.md`: маршруты в группе `app/(dashboard)/`, турниры — `app/(dashboard)/tournaments/`.

Решения по объёму (с Артёмом, 2026-06-15):
- **v1 = Мои турниры + Аккаунт** (подписку не трогаем — платежи ещё не подключены).
- **Главная для залогиненных → дашборд** (последние турниры + форма загрузки); гости видят hero как сейчас.

Схему БД менять НЕ нужно: `Player.closedAt` + обнуляемые `email`/`passwordHash` уже есть (мягкое закрытие, запрет 5). «Профиль игрока» (агрегат) — отдельная поздняя фича, в этот план не входит.

Маршруты: список — `/tournaments` (мн. ч., по архитектуре), деталь остаётся на существующем `/tournament/[id]` (рефакторинг путей вне объёма; зафиксировать расхождение в журнале решений).

## Критерии готовности

- [ ] Залогиненный видит на главной последние турниры и попадает в «Мои турниры».
- [ ] Из списка открывается разбор любого турнира; чужие турниры недоступны (IDOR закрыт через `playerId`).
- [ ] Удалённые (`deletedAt`) турниры в списке не показываются.
- [ ] Смена пароля работает; старый пароль перестаёт пускать, новый пускает.
- [ ] Закрытие аккаунта анонимизирует игрока, убивает сессию, турниры остаются в БД (soft).
- [ ] Тесты/tsc/build зелёные, ручной golden path пройден.

## Риски

- **IDOR в списке и деталях** — каждый запрос фильтрует по `playerId` из сессии; добавить тест на чужой турнир.
- **Закрытие аккаунта необратимо анонимизирует** — обязательное подтверждение паролем + явное предупреждение в UI; это soft-операция (запрет 5: без физического DELETE).
- **Закрытый аккаунт с живой сессией** — обязательно отсечь `closedAt` в `getCurrentPlayer`, иначе анонимизированный игрок останется «залогинен».
- **Расхождение маршрутов** (`/tournaments` список vs `/tournament/[id]` деталь) — осознанное, зафиксировать; полный перенос в `(dashboard)` — отдельной задачей.
