# План: критические раздачи по доезду («выиграл, но повезло»)

Дата: 2026-07-04. Запрос Артёма: в критические попадают только спорные ПОТЕРИ —
а руки, где он крупно вложился далеко позади и доехал (KJ против туза на A-K-2,
король ривером), не разбираются вовсе. «Вот такие вот как-то искать надо раздачи».
Широкие входы сюда НЕ берём — они уже покрыты общей картиной (open-leak).

## Идея

Детерминированный детектор доезда (Правило 1, без LLM): раздача дошла до
вскрытия, Hero выиграл, карты соперника ПОКАЗАНЫ (есть в HH) — значит можно
честно перебором посчитать, сколько эквити было у Hero в момент его крупного
постфлоп-вложения. Мало (< трети) — Hero «доехал»: решение стоит диалога,
даже если фишки приехали.

Это селектор кандидатов, не вердикт: окончательную оценку даёт диалог/вердикт
(колл с дро по цене может быть верным — но у такого колла эквити как раз
выше порога; вторая пара без дро против топ-пары ≈ 10-20% — попадёт).

## Фазы

- [x] Фаза 1 — парсеры ВСЕХ румов: вскрытые карты соперников из HH в снимок
  стола (`Seat.shownCards`): общий `parser/shared/shown-cards.ts` (строки
  «ник[:] shows [Xx Yy]» кроют GG/PS/Chico/888/WPN/Winamax) + iPoker XML
  (`pocketCardsByNick`, теги Pocket ≠ «X X»). Обезличивание цело: карты
  цепляются к «Player N», ник в снимок не попадает.
- [x] Фаза 2 — `parser/lucky-win.ts`: `detectHeroLuckyWin(snapshot)`.
  Эквити перебором против вскрытой руки (эвалюатор made-hand, как range-equity).
  Момент: ПОСЛЕДНЕЕ существенное добровольное вложение Hero на постфлопе
  (CALL/RAISE/ALL_IN, сумма ≥ max(5 BB, 10% стартового стека)); борд на улицу
  этого действия. Несколько вскрытых рук — минимум эквити. Порог: < 33%.
- [x] Фаза 3 — отбор (`ggpoker/classify.ts`, общий для всех румов): спорные
  выигранные с доездом → CRITICAL в ОСТАТОК потолка 7 (потери приоритетнее),
  сортировка по размеру выигрыша. Работает только для новых загрузок (старые
  раздачи размечены и лежат в БД).
- [x] Фаза 4 — тесты (эквити на ривере/тёрне, детектор на примере Артёма,
  приоритет потерь в classify), tsc, полный прогон.
