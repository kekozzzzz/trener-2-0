# План: учёт расходов LLM по игрокам + отчёт

**Дата:** 2026-06-21
**Задача:** видеть, кто сколько LLM-запросов сделал и сколько мы на это потратили; отчёт приходит сам в Telegram (ежедневно) + раздел на /status. Главная цель — данные для решения «оставлять ли кэш» на реальной дистанции беты (~50 регистраций, по 2–3 сессии).

## Что уже есть (используем, не строим заново)
- Ежедневный дайджест `infrastructure/jobs/daily-digest.ts` + cron-роут `app/api/cron/daily-digest/route.ts` (9:00, CRON_SECRET). В нём ЗАГОТОВЛЕН блок «Расходы Claude» (отложен — думали, нужен admin-ключ Console).
- Telegram-уведомления `adapters/notify` (`safeNotifyAdmin`).
- Singleton БД `@/infrastructure/db/client` (`prisma`).
- /status (внутренняя страница) — `app/status/*`, `app/api/status/route.ts`.

**Ключ Anthropic Console НЕ нужен:** берём `message.usage` прямо из ответа API на каждый вызов (input/output/cache_creation/cache_read).

## Решения
- Отчёт: Telegram ежедневно + /status (подтвердил Артём 2026-06-21).
- Новая таблица `LlmUsage` (подтверждено).
- Себестоимость — внутренняя оценка, не платёжный леджер → Decimal USD допустим (правило «деньги только integer cents» — про Payment-леджер).
- Ставки модели — в конфиге (правило №3).

## Фазы

### Фаза 1 — схема
- [ ] Модель `LlmUsage`: playerId(FK) · step · model · inputTokens · outputTokens · cacheWriteTokens · cacheReadTokens · costUsd(Decimal 10,6) · createdAt; индексы по playerId и createdAt. Relation на Player.
- [ ] Миграция (в ЛОКАЛЬНУЮ базу; прод — отдельно, как остальные).

### Фаза 2 — стоимость + рекордер
- [ ] `config/llm-pricing.ts`: ставки за 1M токенов по модели (sonnet-4.6: in $3, out $15, cacheWrite $3.75, cacheRead $0.30).
- [ ] `features/usage/llm-usage.ts`: `costFromUsage(usage, model)` + counterfactual «без кэша»; `recordLlmUsage(...)` — пишет строку, НИКОГДА не бросает (расход вторичен, не должен ронять разбор).

### Фаза 3 — захват
- [ ] В `LlmPort` методы — опциональный `meta { playerId }` (step неявен по методу). Fake игнорирует.
- [ ] `anthropic.ts` callClaude отдаёт `message.usage`, методы пишут строку через recordLlmUsage.
- [ ] 5 шагов очереди передают `{ playerId }` (из tournament.playerId).

### Фаза 4 — отчёт
- [ ] `features/usage/cost-report.ts`: агрегат за период — по игроку (запросов, $), итого, и **кэш-нетто** (факт vs «без кэша»). Используется и дайджестом, и /status.

### Фаза 5 — дайджест
- [ ] Заполнить блок «Расходы Claude» в `buildDailyDigest`: всего запросов/$, топ-игроки, строка «кэш сэкономил/стоил $X».

### Фаза 6 — /status
- [ ] Раздел расходов: по игрокам + итого + кэш-нетто.

### Фаза 7 — тесты + журнал

- [ ] tsc + vitest зелёные; запись в журнал решений.
