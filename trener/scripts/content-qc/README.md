# Проверка текста перед публикацией — content-qc

Три скрипта на чистом Python 3 (без зависимостей), взятые из купленного продукта
«Скилл статей» (`Desktop/statejnik/tools/`, лицензия разрешает использование в
своих проектах без ограничений). Из всего продукта взяты только эти три
инструмента — сама методология (16 этапов, авто-поиск тем по Reddit/HN/LinkedIn,
публикация через CMS) для сайта не подошла: у нас нет блога, страницы вроде
`/ggpoker` — это код (JSX + строки в `messages/ru.json` и `messages/en.json`),
а не файлы markdown в CMS.

## Что здесь

| Скрипт | Что ловит |
|---|---|
| `ai-cadence-check.py` | ИИ-почерк: «не X, а Y», длинное тире «—», канцелярит, литобороты |
| `read-aloud-check.py` | Длинные предложения, скопления согласных — читаемость вслух |
| `structure-check.py` | H1, блок источников, CTA-ссылка, внутренние ссылки, alt у картинок |
| `_config.py` | Общий загрузчик config.yaml (не обязателен — без него работают дефолты) |

`ai-cadence-check.py` и `read-aloud-check.py` совпадают с уже действующим
правилом дома для текстов (`.claude` память `feedback_copy_style`: только
короткое тире, без «не X, а Y», без канцелярита) — по сути это тот же чек-лист,
но автоматический и по числам, а не на глаз.

## Windows: обязательный флаг -X utf8

Без него `ai-cadence-check.py` и `read-aloud-check.py` падают на Windows с
`UnicodeEncodeError` (консоль в кодировке cp1251, а в help-тексте есть символ
«→»). Это не баг скрипта — просто виндовая консоль. Запускать так:

```bash
python -X utf8 trener/scripts/content-qc/ai-cadence-check.py черновик.md
python -X utf8 trener/scripts/content-qc/read-aloud-check.py черновик.md
python -X utf8 trener/scripts/content-qc/structure-check.py черновик.md
```

## Как использовать на практике

Наши страницы-гайды (`/ggpoker`, `/how-to-export`, будущие) — это JSX-компонент
плюс строки в двух `messages/*.json`, а не единый markdown-файл. Поэтому порядок:

1. Написать черновик текста будущей страницы как обычный `.md`-файл (просто
   прозу, разделы через `##`) — до того, как резать его на JSX-компонент и
   ключи перевода.
2. Прогнать `ai-cadence-check.py` и `read-aloud-check.py` на этом черновике,
   поправить, что подсветили.
3. `structure-check.py` в таком виде почти всегда будет ругаться на «нет
   источников / нет внутренних ссылок» — он рассчитан на markdown-статью
   с инлайн-ссылками, а у нас ссылки на `/push-fold`, `/analyze` и т.п. живут
   как отдельные JSX `<Link>`, не как текст в теле абзаца. Полезен только если
   в сам черновик руками вписать плейсхолдеры ссылок перед проверкой — иначе
   можно пропускать этот шаг.
4. Только после проверки — разнести текст по JSX-компоненту и обоим
   `messages/*.json` (RU и EN), как в `/ggpoker`.

Проверено на живом тексте `GgpokerGuide` из `messages/ru.json`: ai-cadence —
чисто (0 ИИ-маркеров), read-aloud — поймал одно реально длинное предложение
(34 слова) в `whyMicroBody`, которое стоит разбить.
