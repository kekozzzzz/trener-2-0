# Слежка за новыми моделями

Раз в 3 дня проверяет каталог OpenRouter и пишет Артёму в Telegram, **только если есть о чём**.
Ничего не изменилось — тишина. Настроено 2026-07-16.

## Зачем

Модели выходят быстрее, чем мы успеваем о них узнать: за 40 дней в каталоге прибавилось
31 штука, и про свежий релиз мы узнали случайно, из чужого уведомления, посреди починки
предыдущей модели. Сторож закрывает эту дыру — и заодно прикрывает прод: если боевая
модель пропадёт из каталога или подорожает, разбор ляжет или подорожает молча.

## О чём пишет

| | Что это | Что делать |
|---|---|---|
| 🔴 | Боевая модель пропала из каталога | Откат: `OPENROUTER_MODEL` в `.env.production` на ВМ |
| 💸 | Боевая модель подорожала на 15%+ | Пересчитать себестоимость разбора |
| 🆕 | Вышла модель известной лаборатории, проходит по цене и контексту | Ничего. Обсудить с Клодом за компом |
| 📋 | Крупный релиз, но нам не по деньгам | Ничего, просто знать |

**Это уведомление, а не задача** (решение Артёма 2026-07-16). Сторож сообщает факт и на том
останавливается: ни аудита, ни пробного прогона, ни команды для него в тексте. Менять ли
модель — Артём решает с Клодом за компьютером, глядя на конкретную новинку.

Почему так: любой намёк на «прогони» в сообщении приводит к прогонам по моделям, которые
нам заведомо не нужны. Аудит — штука дорогая по времени и деньгам (baseline в тот же час
+ 2-3 повтора, `memory-bank/feedback_audit_noise_baseline.md`), и затевать его стоит только
осознанно, под конкретную модель, а не по факту её выхода.

## Где живёт

На **релее** (Казахстан, `92.60.75.87`) — там же, где автодеплой и сторож дайджеста.
Прод-ВМ в РФ до `openrouter.ai` и `api.telegram.org` напрямую не достаёт, релей достаёт.

- Код — в репозитории, здесь. Клон на релее (`/root/trener`) автодеплой держит свежим,
  так что **правка фильтра = коммит в master**, лезть на сервер не нужно.
- Таймер: `/etc/systemd/system/model-watch.timer` (`OnUnitActiveSec=3d`, `Persistent=true` —
  если релей был выключен, проверка догонит после включения).
- Снимок прошлой проверки: `/root/.model-watch.json` (только id + цены, не секрет).
- Токен бота: `/root/.claude/channels/telegram/.env`, подхватывается юнитом через
  `EnvironmentFile`. В репозитории токена нет.

## Как менять

Пороги, список лабораторий и боевые модели — в [`config.mjs`](config.mjs). Правишь → пуш в
master → через ~2 минуты релей подтянет, следующая проверка пойдёт по новым правилам.
Пересборку прода правка не вызывает: `ops/` внесён в список «не трогает сборку» у автодеплоя.

**Сменил модель на проде — поправь `prodModel` в config.mjs**, иначе сторож продолжит
стеречь старую.

## Проверить руками

```bash
ssh root@92.60.75.87
cd /root/trener/ops/model-watch
node watch.mjs --dry-run          # печатает отчёт, ничего не шлёт и не трогает снимок

systemctl start model-watch       # прогнать по-настоящему, прямо сейчас
systemctl list-timers model-watch # когда следующая проверка
journalctl -u model-watch -n 30   # что было в прошлые разы
```

## Выключить

```bash
systemctl disable --now model-watch.timer
```

## Известные ограничения

- Следит только за каталогом **OpenRouter**. Модель, которой там нет, мы всё равно не
  подключим (ходим через него), так что это не дыра, а граница по месту.
- Цена берётся общая по модели. У одной модели на OpenRouter бывает до 16 провайдеров с
  разбросом цены в ~4× — точную цену смотреть на странице модели.
- Если каталог придёт огрызком (<50 моделей), сторож молча выходит и **не трогает снимок**:
  иначе следующая проверка сочла бы все 300+ моделей новыми и завалила бы Telegram.
