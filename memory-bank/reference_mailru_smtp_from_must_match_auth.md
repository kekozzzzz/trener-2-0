Обнаружено вживую 2026-09-16 при переключении транзакционных писем на SMTP через ящик поддержки (VK WorkSpace/mail.ru). Пытались слать письма с `MAIL FROM: support@whygrid.app`, авторизуясь по SMTP как `whygrid.app@mail.ru` (технический логин ТОГО ЖЕ ящика — это не два разных ящика, а два адреса одного). Сервер mail.ru ответил на `RCPT TO`:

```
501 sender address must match authenticated user
```

**Вывод:** для mail.ru/VK WorkSpace по протоколу SMTP адрес «от кого» обязан буквально совпадать со строкой, которой вошли по SMTP AUTH — даже если оба адреса технически принадлежат одному и тому же ящику. Это антиспуфинг-защита именно SMTP-relay пути, не про сам ящик как таковой: письма, отправленные тем же человеком через веб-интерфейс (mail.ru/VK-почта в браузере), НЕ подчиняются этому ограничению — там другой механизм отправки. Ограничение всплывает только у ВНЕШНИХ клиентов/скриптов, идущих по SMTP AUTH напрямую.

**Как применять:** если для домена настроен один mail.ru/VK WorkSpace-ящик с кастомным доменным адресом (например `support@whygrid.app`) и технической `<что-то>@mail.ru` учёткой для того же ящика — для программной отправки по SMTP используй именно техническую `@mail.ru`-учётку и как логин, и как адрес «от кого» одновременно. Кастомный доменный адрес для SMTP-отправки не годится, только для приёма и веб-интерфейса.

**Не путать с per-ящик правами приложения-пароля** (полный доступ vs «только отправка») — это отдельная настройка (Безопасность → Пароли для внешних приложений), тут не про неё, ограничение проявляется у любого уровня прав.
