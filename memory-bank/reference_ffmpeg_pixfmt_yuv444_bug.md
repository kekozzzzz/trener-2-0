При сборке видео через ffmpeg с цепочкой `zoompan` (из PNG-скриншотов) + `xfade` + `drawtext`,
итоговый файл кодировался libx264 в `yuv444p` (профиль High 4:4:4 Predictive) вместо обычного
`yuv420p` — Артём не мог открыть готовые файлы («не открываются») ни в одном плеере, хотя
ffprobe показывал файлы валидными.

**Причина:** явный `format=yuv420p` в каждой ветке фильтр-графа (и для видео, и для картинок)
НЕ гарантирует итоговый формат кодировщика — `xfade`/`drawtext` в цепочке могут повышать
точность обратно, и libx264 без явного указания сам выбирает профиль/формат под то, что получил
на входе энкодера.

**Why:** проверено эмпирически в этом проекте — добавление `format=yuv420p` только внутри
фильтр-графа (после `zoompan`) не помогло, файл всё равно вышел `yuv444p`. Помогло только
явное `-pix_fmt yuv420p` как ВЫХОДНАЯ опция ffmpeg (после `-c:v libx264`), это форсирует
конвертацию непосредственно перед энкодером независимо от внутреннего формата графа.

**How to apply:** в любой ffmpeg-команде с `-filter_complex`/`-filter_complex_script`, где
итоговое видео пойдёт зрителю (не только для скриншотов/промежуточных файлов) — всегда
добавлять `-pix_fmt yuv420p` рядом с `-c:v libx264` в конце команды. Не полагаться только на
`format=yuv420p` внутри фильтр-графа. Проверять после сборки: `ffprobe -select_streams v:0
-show_entries stream=pix_fmt,profile -of csv=p=0 файл.mp4` — должно быть `yuv420p`/`High`,
не `yuv444p`/`High 4:4:4 Predictive`.
