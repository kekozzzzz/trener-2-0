**ИНЦИДЕНТ 2026-07-14 (в тот же день, что и деплой детерминизации v2 aed920e).** После выкатки гибрид-reasoning (CRITICAL-разбор + диалог/вердикт на `{effort:"low"}`) на проде посыпались алерты сторожа: задачи `GENERATE_HAND_ANALYSIS` уходили в карантин (POISONED) после 3 попыток с ошибкой `RelayTimeoutError: OpenRouter: таймаут вызова (45000 мс) — релей не ответил`. Артём заметил живьём: загрузил турниры, таймер «тренер думает» рос и не заканчивался.

**ДИАГНОЗ.** Гибрид low на GLM-5.2 делал разбор критической раздачи (тяжёлый промпт фактов-v2 + reasoning-токены) дольше 45с → наш клиентский таймаут `getLlmCallTimeoutMs` (дефолт 45000, config/llm.ts) сдавался первым → 3 попытки → карантин. Замер латентности я делал только на ВЕРДИКТЕ (21-34с), а не на analysis (первый экран, самый большой промпт+ответ) — недоработка перед деплоем.

**ЛЕЧЕНИЕ (по шагам, всё сделано из локальной сессии через КЗ-релей → ВМ jump):**
1. **Пластырь таймаута** (env, без пересборки): на релее nginx `location /openrouter/` добавлены `proxy_read_timeout 120s; proxy_send_timeout 120s;` (был nginx-дефолт 60s; бэкап конфига в /root/anthropic-relay.bak.*); на ВМ в `.env.production` дописан `LLM_CALL_TIMEOUT_MS=90000` + `pm2 restart trener --update-env`. Карантин прекратился для новых задач.
2. **Реанимация застрявших** (одобрено Артёмом — запись в прод-БД): `UPDATE tasks SET status='PENDING', attempt=0, run_after=now() WHERE status='POISONED' AND type='GENERATE_HAND_ANALYSIS'`. Из 4 три разобрались, одна (тяжёлая) снова в карантин даже на 90с → доказало, что таймаутом гибрид не спасти.
3. **Откат reasoning в коде** (2a960f7, [тихо], push=автодеплой сторожем): в `infrastructure/adapters/llm/openrouter.ts` убран `REASONING_LOW` из generateHandAnalysis/generateNextQuestion/generateVerdict — все роли вернулись на env-дефолт off. Механизм гибрида СОХРАНЁН в комментарии (как вернуть с быстрой моделью). Галлюцинации теперь гасит детерминизация Правила 1 v2 (парсер, а не reasoning).

**ГЛАВНЫЙ ВЫВОД (замер с ВМ по боевому маршруту, curl -k к релею, reasoning off):** латентность GLM-5.2 ЛИНЕЙНА по числу выходных токенов, **~45 токенов/сек**. Короткий ответ (119 ток) = 3.6с; длинный разбор (1555 ток) = 35.5с. Реальный analysis-разбор = 35-56с ДАЖЕ на off. **Скорость упирается в ДЛИНУ ОТВЕТА, не в reasoning.** Поэтому:
- **Таймаут оставлен 90с намеренно** (НЕ возвращать на 45с — off-analysis до 56с, вернёт карантин). Пока не сократим длину ответа — 90с это необходимый минимум, а не костыль.
- Настоящие рычаги СКОРОСТИ (боль Артёма «растущий таймер»): (1) **стриминг** ответа игроку (глубину не режем, ожидание в пустоту уходит — рекомендация); (2) **короче разбор** (урезать длину/max_tokens → пропорционально быстрее, но глубина↓); (3) **быстрее модель** (100+ ток/с). Параллелизм (concurrency уже 10, QUEUE_CONCURRENCY=10, connection_limit=15) НЕ лечит латентность ОДНОЙ раздачи — только пропускную.

**ЗАПУЩЕНО ИССЛЕДОВАНИЕ (Workflow, фон):** «больше фактов от парсера против галлюцинаций + лайфхаки других платформ (точность дёшево/быстро)» — внутренний аудит кода + веб-разведка солверов/LLM-покера/инженерии/AI-трекеров → приоритизированный план.
