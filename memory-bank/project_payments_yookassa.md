**Security-проход по платёжному потоку (2026-06-21, НЕ закоммичено):** (1) ИСПРАВЛЕНО — id платежа из тела вебхука уходил в URL `getPayment` без санитизации (инъекция пути/SSRF): добавлена проверка charset в route (`^[A-Za-z0-9_-]{1,64}$`) + `encodeURIComponent` в адаптере + тест на мусорный id. (2) Добавлено предупреждение в лог при расхождении оплаченной суммы с ценой тарифа (защита в глубину, без блокировки — жёсткий отказ отверг бы реальные деньги при смене цены). (3) ИСПРАВЛЕНО — финансовая дыра (бюджет-байпас): при РАННЕЙ смене тарифа/продлении (кнопка «Перейти на этот») `apply-payment` ставил `currentPeriodStart` в БУДУЩЕЕ (= старый nextPaymentAt), а гейт `budget.ts` метрит `since currentPeriodStart` → окно стартовало в будущем → spent=0 → безлимит на остаток периода. Фикс: при продлении активной подписки якорь метра остаётся на начале ТЕКУЩЕГО периода (`currentPeriodStart` не двигаем; сбрасываем на paidAt только для новой/просроченной); nextPaymentAt по-прежнему продлевается от конца. Регресс-тест в apply-payment.test (early renewal: currentPeriodStart не меняется). Остаток для Фазы 4: перекат метра на следующий период при стекинге доплат (сейчас стекинг метрится консервативно в нашу пользу). Мелочи: нет рейт-лимита на startCheckout (спам pending-платежей, не убыток); оплата после закрытия аккаунта → FK-фейл → вебхук 500/повторы.

**Автопродление + даунгрейд + проверка обнуления кредитов (2026-06-22, НЕ закоммичено):**
- **Кредиты обнуляются на новом периоде — подтверждено.** Нигде не хранится «потрачено N»; бюджет = сумма LlmUsage.costUsd В ОКНЕ текущего периода (`spentThisPeriodUsd` since effectivePeriodStart). Окно сдвигается при продлении (currentPeriodStart=дата оплаты) и ленивым перекатом на 30-дн границе. Тест `budget-window.test.ts` доказывает: расход прошлого периода в текущий не считается.
- **Автопродление (Фаза 4):** шаг очереди `RENEW_SUBSCRIPTION` (steps/renew-subscription.ts) — chargeSaved с сохранённой карты, детерминированный idempotenceKey `renew-<sub>-<nextPaymentAt>`, перечитывает платёж и применяет через applySucceededPayment (новый период, метр обнулён). Джоб `runSubscriptionRenewals` (jobs/renew-subscriptions.ts) + cron `/api/cron/renew-subscriptions` (Bearer CRON_SECRET): ставит задачи на просроченные с картой (дедуп по pending-задаче), гасит в EXPIRED отменённые/без карты. Списание делает воркер run-tasks. Решение Артёма: БЕЗ грейса (карта отклонена → EXPIRED сразу; доступ и так режется гейтом в nextPaymentAt).
- **Даунгрейд** теперь реальный: `switchPlan` пишет `scheduledPlanCode` (новое поле БД), применяется при продлении (приоритет над planCode, потом очищается). Апгрейд поверх запланированного даунгрейда — снимает scheduledPlanCode (фикс бага).
- **Управление в /account:** отключить/включить автопродление (`cancelAutoRenew`/`resumeAutoRenew` → CANCELED/ACTIVE), отменить запланированную смену (`cancelScheduledPlan`), показ статуса/даты/запланированного тарифа.
