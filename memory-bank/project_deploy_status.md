## КРИТИЧНЫЕ факты (помнить!)
- **VM 81.26.186.177 недоступна снаружи напрямую** (мобильные РФ, заграница — таймаут). НЕ указывать DNS на неё. Доступ к сайту — только через релей.
- **❗ПРЯМОЙ ВХОД НЕВОЗМОЖЕН, и это НЕ чинится правилом фаервола (диагноз 2026-06-27).** Артём просил «прямой запасной SSH на случай гибели КЗ-релея» — не выйдет. Точная причина: блок в СЕТИ (DPI), не на VM и не в облаке. Доказано: (1) `/dev/tcp` к 22 проходит (TCP-рукопожатие ок), но `ssh` ловит `Connection reset` на стадии баннера, и в `/var/log/auth.log` VM моей прямой попытки НЕТ вообще (дошёл только скан с чужого IP + мой заход через релей 92.60.75.87) → RST вбивают в транзите до sshd; (2) прямой TLS к VM:443 из РФ — таймаут (ClientHello теряется), а к релею:443 — 200/403 нормально. На самой VM всё открыто: ufw inactive, iptables INPUT policy ACCEPT (только DROP :3000), sshd слушает 0.0.0.0:22, hosts.allow/deny пусты, в sshd_config никаких AllowUsers/Match. **Security group Яндекса УЖЕ настежь**: правила Ingress = `Any 0.0.0.0/0` + TCP 22/80/443 `0.0.0.0/0` (+ TCP22 с 192.121.87.204/32) → SG никогда и не был блокером; добавлять туда правило бесполезно. ⚠️ хардening-долг: `Any 0.0.0.0/0` — слишком широко, сузить. **Единственный путь к VM — через релей (jump).** Реальная страховка от «КЗ-релей умер» = ВТОРОЙ независимый jump в другой нейтральной стране (Армения/Сербия), не «прямой вход». Предложено Артёму, не сделано. **Проверка через VPN (2026-06-27):** у Артёма системный VPN hidemy.name (OpenVPN-адаптер), мой трафик через Bash идёт через него — выход был Молдова `192.121.87.234` (та же сеть, что whitelist-правило SG `TCP22 192.121.87.204/32`). Но прямой SSH к VM ВСЁ РАВНО рвётся: `ssh -vv` показал обрыв `Connection reset` РОВНО после `SSH2_MSG_KEXINIT sent` (баннеры обеих сторон прошли, рвут на первом пакете SSH-протокола = подпись DPI), а прямой HTTPS к VM:443 с Молдовы даже TCP не встаёт. Через KZ-релей тот же KEXINIT проходит → фильтрация ПУТЬ-специфична (Молдова→РФ к этому Yandex-IP режется, КЗ→РФ нет). Порт 22 через VPN НЕ зарезан провайдером (до github SSH дошёл). **✅ ЗАПАСНОЙ ПРЯМОЙ ВХОД НАЙДЕН И ПОДТВЕРЖДЁН (2026-06-27):** если переключить системный VPN Артёма на ВЫХОД ЧЕРЕЗ КАЗАХСТАН (проверено на hidemy.name, Алматы `193.39.68.136`), то прямой SSH к VM РАБОТАЕТ без релея — KEXINIT проходит, `Authenticated ... publickey`, вошёл как trener-vm, команды выполняются. Так и обходим «КЗ-релей умер»: Артём ставит VPN на Казахстан, я захожу прямым `ssh -i /tmp/vmkey -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null trener-vm@81.26.186.177` (БЕЗ ProxyCommand-jump). ВАЖНО: Anthropic пускает из РФ-VPN-выходов кроме России/Беларуси (и санкционных); Казахстан для Claude тоже ок, так что я не теряюсь. Молдова/др. страны — для меня ок, но маршрут до VM может резаться (как Молдова). Порядок: VPN→Казахстан, прямой ssh; если KZ-выхода нет — перебрать Армения/Сербия/Турция. - **❗АВТОДЕПЛОЙ НЕ ПРИМЕНЯЕТ МИГРАЦИИ.** Cron гоняет `~/deploy.sh` (в `~/trener-2-0`): fetch master (5 попыток, GitHub:22 из РФ режется), при новом коммите ff-merge → `cd trener` → `npm install` → `prisma generate` → `npm run build` → `pm2 restart trener`. Миграции БД он НЕ трогает. Значит push в master = код САМ уедет на прод, а колонок не будет → новый код упадёт на отсутствующем поле. **Миграцию надо применить вручную ДО/сразу:** на VM `cd ~/trener-2-0/trener`, `export DATABASE_URL="$(grep -m1 '^DATABASE_URL=' .env.production | cut -d= -f2- | tr -d "\"'")"` (Prisma CLI не читает `.env.production`, только `.env`), затем применить миграцию. Прод-база = `trener_prod` на localhost:5432. **2026-06-26: `npx prisma migrate deploy` отработал ЧИСТО** (`17 migrations found`, применил 1 новую, без ресета) — он forward-only и production-safe, ничего не дропает; история на проде в синхроне. Так что `migrate deploy` — предпочтительно (пишет в `_prisma_migrations`, не плодит дрейф). Запасной путь `npx prisma db execute --file <миграция.sql>` — только если migrate deploy ругнётся на дрейф. ⚠️ ГРАБЛИ: значение в `.env.production` ОБЁРНУТО в кавычки (`DATABASE_URL="postgres..."`) — Prisma CLI кавычки НЕ снимает (в отличие от Next), извлекать так: `cut -d= -f2- | tr -d "\"'"` или `sed 's/^\"//;s/\"$//'`, иначе P1012 «Environment variable not found». 2026-06-25 так сделали `add_player_characteristic` (db execute), 2026-06-26 — `add_renewal_reminder_sent_at` (migrate deploy).
- **❗deploy.sh запускается по cron и при недоступном GitHub (из РФ режется) копится пачкой** — 2026-06-25 насчитали **149 зависших процессов** (каждый сидел в retry `git fetch`). ## КАК ЗАЙТИ НА VM (рабочий способ)
КЗ-релей (92.60.75.87, мой ключ там root) как jump к прямому IP (КЗ→РФ маршрут рабочий). Ключ в `/tmp/vmkey` (кириллица в $HOME ломает ProxyCommand); host key меняется после ребута → отключить проверку:
```
cp ~/.ssh/id_ed25519 /tmp/vmkey; chmod 600 /tmp/vmkey
PJ='ssh -i /tmp/vmkey -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -W %h:%p root@92.60.75.87'
ssh -i /tmp/vmkey -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null -o ProxyCommand="$PJ" trener-vm@81.26.186.177
```
На релей напрямую: `ssh -i /tmp/vmkey -o StrictHostKeyChecking=no -o UserKnownHostsFile=/dev/null root@92.60.75.87`. [[project_llm_connectivity_block]]
