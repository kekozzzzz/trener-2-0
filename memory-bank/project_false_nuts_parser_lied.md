## 🔑 ПРИЧИНА: парсер сам себе противоречил, модели шли за ним
`madeHandNutStatus` мерил натсовость **ВНУТРИ своей категории**: стрит сравнивал только со
стритами, флеш — только с флешами. Что руку бьёт фулл/каре/флеш/стрит-флеш — не смотрел вообще.
Итог: в одном снимке рядом стояли «Твой стрит **НАТСОВЫЙ**» и «тебя бьют 60 из 990 (36 флеши)».
**Модели не выдумывали натс — им его продиктовали.** Потому и сломались ВСЕ ТРИ разом (это и был
диагностический признак: одинаковая поломка у разных моделей ⇒ причина в наших данных).
Ложится на [[project_gemini_stream_breaks]] «ошибаются там, где факт ЕСТЬ, но надо ПРИМЕНИТЬ» —
здесь даже применять нечего, факт **прямо врал**.

## Что починено (`parser/made-hand.ts`, `facts.ts`, `range-buckets.ts`)
1. **Судья натсовости = перепись колоды** (`fullDeckOdds.losesTo`), единственный, кто видит фулл,
   каре и стрит-флеш разом. Слово «НАТСОВЫЙ» печатается ⟺ `losesTo === 0`; иначе «НЕ натс: тебя
   бьют <категории>». Нет переписи → про натс молчим (не врём в обе стороны).
   ⚠️Грабля: `if (beatenCount <= 0)` при undefined даёт false → отнимало натс у ЧЕСТНОГО натса.
   Только строгое `if (!(beatenCount > 0))`. Поймано пробой, tsc бы пропустил при опц. параметре.
2. **Фулл-хаус/каре/стрит-флеш не получали НИ ОДНОЙ строки** про натсовость (падали в `null`) —
   вакуум модель заполняла сама (#32: «на тёрне с фулл-хаусом у тебя натсовая рука» при 67 бьющих).
   Теперь печатаем только ОТРИЦАНИЕ (при `losesTo===0` молчим — рядом уже есть «бьют 0 из N»).
3. 🔴**`CAT_RU` в range-buckets не содержал категорию 9 (стрит-флеши)**, а фильтр разбивки молча
   выбрасывает то, чего нет в словаре → **самая страшная угроза исчезала из фактов**, сумма
   категорий не сходилась с `losesTo`. Живой баг: борд 7h6h5h, соперник 9h8h = стрит-флеш.
4. **Оговорка «на этой улице»** для флопа/тёрна: `losesTo===0` там = «сейчас», а не «навсегда».
5. `import type { DeckOdds }` (только тип — рантайм-цикла нет: range-buckets импортирует made-hand).
Тесты: 45 в made-hand.test.ts, включая ОБЕ реальные раздачи корпуса (#1 A6s, #32 ATo) и #8.
Тесты зовут функцию через `fullDeckOdds` — тем же входом, что бой, иначе разойдутся с продом.

## ⛔ СТОРОЖ НА СЛОВО «НАТС» — НЕЛЬЗЯ (замер по корпусу 150 разборов)
На 32 срабатывания по 3 моделям — **3 реальных брака, 91% ложных**. У GLM точность regex = **0%**
(говорит «натс» 6 раз, все 6 верно). Сторож бракует именно ХОРОШИЕ разборы → 3 ретрая → карантин →
игрок 10 мин видит «готовим следующий шаг». Законные употребления: отрицание («сет не натсовый»),
про соперника («блокируешь натсовый флеш»), абстрактно («коллировать не только с натсами»), и
ВЕРНЫЙ натс при «бьют 0 из N». Ловить можно только ПРОТИВОРЕЧИЕ (натс при losesTo>0), но после
починки причины базовая ставка ≈0 — сторож не нужен. См. [[project_prompt_holes_fixed]].

## 🔑 ТОТ ЖЕ ПОЧЕРК — ещё два класса, вылечены так же (17.07, регресс+аудит)
**«ДВЕ ПАРЫ, СТАРШАЯ ПАРА ОБЩАЯ» (#5, #13) — самый дорогой класс.** Правило «любая карманка
старше твоей младшей пары бьёт тебя» было ВЕРНЫМ, но абстрактным → модель не применяла. На 96o
(борд 4-5-7-6-7) тренер: «ты бьёшь 88 или 99» и ПОТРЕБОВАЛ колла; игрок сам назвал 88/99 верно —
**тренер переубедил его враньём**. Лечение: парсер перечисляет ВСЕ три источника угрозы прямым
текстом — (1) одна карта ранга общей пары = ТРИПС, (2) одна карта борда между парами = старшие
две пары (вторая уже на борде), (3) карманные пары поимённо. 🔴**Одиночные карты борда опаснее
карманок**, и про них факта не было вовсе — из-за этого тренер звал «валет или десятку» руками,
которые Hero бьёт. #5 в бою: «фолд излишне осторожен, коллируй» → «фолд был ВЕРНЫМ решением».
⚠️Чинил в ТРИ захода: (1) список карманок — вылечил #5, не #13; (2) написал ПРОСЬБУ «не зови её
слабее» — не сработала (грабля проекта, наступил сам); (3) факт про одиночные карты + падежи.
**«СОВЕТ ПОСЛЕ ОЛЛ-ИНА» (#43).** Тренер советовал «фолд, сохраняющий стек» игроку, чей стек уже
в банке. Факт в facts.ts: «весь твой стек уже в банке, решений у тебя НЕТ». В бою: 21 раз, ушло.
⚠️Ранги ТОЛЬКО по-русски + творительный падеж (INS_SG): «TT/JJ» модель скопирует эхом → латинский
сторож забракует ВЕСЬ разбор (горели на VPIP: 7 браков из 15).
