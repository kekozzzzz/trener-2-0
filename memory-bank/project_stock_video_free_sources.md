Живые (не ИИ) покерные стоки берём на **Mixkit** — `https://mixkit.co/free-stock-video/<слаг>/`.
По разделам `poker`, `casino-chips`, `casino-dealer`, `deck-of-cards` набирается 131 покерный клип,
из них 93 под **Free License** (коммерческая реклама в соцсетях разрешена, атрибуция не нужна),
38 — под **Restricted** (только личное использование, в рекламу брать нельзя).

**Как отличить лицензию без открытия страницы:** у Free качается `…-1080.mp4` (часто и `…-2160.mp4`),
у Restricted максимальное разрешение 720p — 1080 отдаёт 403. Проверено на 32 клипах с подтверждённой
лицензией + перепроверено обратным случаем через WebFetch (Free-клип с 1080 → Free, клип без 1080 → Restricted),
несовпадений нет.

Прямые ссылки на файл: старые клипы — `https://assets.mixkit.co/videos/<id>/<id>-1080.mp4`,
новые (id ≥ 100000) — `https://assets.mixkit.co/active_storage/video_items/<id>/<ts>/<id>-video-1080.mp4`,
где `<ts>` есть в HTML страницы-списка.

**Ограничения среды:** сайт mixkit.co за Cloudflare — при параллельной или частой закачке страниц
включается челлендж «Just a moment…» и всё падает; качать страницы последовательно. CDN `assets.mixkit.co`
не блокируется. **Pexels** блокирует российские IP намеренно: с 2022 закрыл доступ в знак протеста
против вторжения в Украину (баннер об этом виден при заходе на сайт с российского IP). Автоматом
(curl, без кук/заголовков браузера) — 403 стабильно, проверено 15.08 и с домашнего IP Артёма, и с
IP среды выполнения агента. **Но через браузер у Артёма 15.08 файл реально скачался** — блокировка
держится нестабильно (либо разница curl vs браузер с полным набором заголовков/кук, либо
сама блокировка не всегда срабатывает). Практический вывод: скриптом/curl не рассчитывать, но
через браузер периодически можно скачивать вручную по одному — если получилось, качать сразу
всё нужное, пока не перестало работать. **Pixabay** тоже отдаёт 403 с домашнего IP — не проверено,
та же ли причина (гео-блок) или обычный антибот.

**⚠️ Через КЗ-релей (92.60.75.87, см. [[project_remote_workspace]]) НЕ помогает** — проверено 15.08:
curl с релея (IP подтверждён KZ через ipinfo.io) тоже получил 403 и на сайт, и на CDN-файл. Значит
дело не только в гео (Россия vs остальные) — похоже, режется сама сигнатура запроса: голый curl без
браузерных кук/заголовков + IP дата-центра/VPS (а не жилого провайдера) выглядит как бот и блокируется
независимо от страны. Домашний браузер Артёма прошёл именно потому что это живой браузер с обычного
провайдерского IP. Вывод: релей/скрипт для обхода не годится, нужен реальный браузер с residential IP —
то есть только руками у Артёма. Не пытаться решать это через SSH/curl повторно.

**18.08: обновление — из среды выполнения агента (не релей, не домашний IP) Pexels заработал.**
Инструмент WebFetch открыл `www.pexels.com/ru-ru/search/videos/покер/` и страницы отдельных видео
без 403 (свой сетевой путь, не совпадает ни с curl-с-релея, ни с домашним IP). Дальше прямое
скачивание файла с CDN `videos.pexels.com/video-files/<id>/<filename>.mp4` через curl **тоже
получилось (200, полноценный mp4)**, но только при двух условиях: 1) заголовок
`User-Agent: Mozilla/5.0 ...Chrome...` — без него тот же файл даёт 403; 2) точное имя файла
взято со страницы видео через WebFetch, не угадано по шаблону — угаданное имя даёт 403,
что похоже на «файл не найден», а не на гео-блок. Проверено на 2 разных видео (id 35429456,
7608213) — оба раза 200 с UA + точным именем, оба раза 403 без UA. Прежний вывод «нужен только
браузер руками у Артёма» **не подтвердился сегодня для этого пути** — вероятно, у среды агента
свой исходящий IP/маршрут, отличный от релея, и он под блок не попал. Блокировка описана как
нестабильная и раньше (см. абзац выше), поэтому не считать это гарантией на будущее — просто
рабочий способ, если он снова не сработает, вернуться к Mixkit.

**Рабочий алгоритм на 18.08:** 1) WebFetch на `pexels.com/ru-ru/search/videos/<запрос>/` →
список ссылок на карточки `pexels.com/ru-ru/video/<id>/`; 2) WebFetch на каждую карточку →
просит прямую ссылку `videos.pexels.com/video-files/<id>/<filename>.mp4` + описание/ориентацию;
3) curl с `-H "User-Agent: Mozilla/5.0 ...Chrome..."` по этой точной ссылке → сохраняет файл.
Лицензия Pexels проще, чем у Mixkit — единая, коммерческое использование и без атрибуции,
делить на Free/Restricted не нужно.

**Добавка 18.08 — Артём попросил соточку.** Найден короткий путь: `pexels.com/ru-ru/download/
video/<ID>/` отдаёт 302 сразу на файл максимального качества (иногда даже лучше, чем показывала
отдельная страница видео) — не нужен WebFetch на каждое видео, только собрать ID со страниц
поиска (`?page=N` у Pexels, в отличие от Mixkit, реально работает и отдаёт новые id) и прогнать
curl с UA по всем. Пагинацией по запросам «покер»(до p5), «покерные фишки»(до p3), «покерный
стол»(p2), «покерный дилер»(p1) набрано 99 новых уникальных id, скачаны без просмотра содержимого
(имена файлов `pexels-<ID>.mp4`, без описаний) — итого в папке **119 клипов, 3.5 ГБ**. Запрос
«техасский холдем» оказался мусорным — Pexels понял буквально как «Texas» и выдал дроны над
Далласом, не использован. Заметный побочный эффект: у Pexels покерная тема держится буквально
на нескольких фотографах — id из одной съёмки идут кластерами (6665xxx, 7608xxx, 7607xxx и т.д.),
поэтому «3000 результатов» на деле сильно избыточны похожими дублями одного дубля, не 3000
разных сцен.

**Правило на будущее (с 18.08): сначала превью, потом качать.** У каждой карточки в поиске Pexels
есть маленький jpeg-превью (`images.pexels.com/videos/<id>/pexels-photo-<id>.jpeg?...`, виден
в HTML страницы поиска) — куда дешевле по трафику, чем весь mp4. Скачал такой превью curl'ом
и посмотрел инструментом Read (просмотр картинок) — работает, проверено: у клипа 35429456
(«Покерные фишки» по тегу Pexels) на кадре оказалась НЕ классическая партия в холдем, а
какая-то другая настольная/карточная игра с множителями «x2/x3/x4» на картах — текстовый тег
это не показывал бы. Артём попросил на будущее делать именно так: сперва смотрю превью глазами,
отбираю подходящее, и только тогда качаю полный файл — не скачивать вслепую пачками, как было
сделано с 99 клипами 18.08.

**Подтверждено на практике 18.08, тем же вечером:** те самые 99 клипов, скачанные вслепую по ID
без превью, оказались засорены нерелевантным — казино, рулетка и другое не-покерное содержимое
проскочило, хотя все запросы были прицельно «покер»/«покерные фишки»/«покерный стол»/«покерный
дилер». Тег Pexels не гарантирует чистоту темы (пересекается с общими казино-сценами). Артём
почистил вручную сам (оставил 39 из 99), но вывод жёсткий: **вслепую пачками больше не качать
никогда**, только превью → отбор → скачивание, даже если запрос кажется узким и прицельным.

**Довыполнено 18.08, тем же вечером, по новому правилу.** Артём попросил добрать ~30 клипов
взамен удалённых, с условием «сначала посмотри». Процесс: собрал ~90 новых кандидатов (id, не
пересекающихся с уже испробованными 119) через много разных запросов и страниц + приём
«related videos» на странице удачного клипа (в HTML есть блок "Больше похожего контента" —
быстро вытаскивает всю серию одного фотографа/съёмки за один WebFetch), скачал только
превью-jpeg (`images.pexels.com/videos/<id>/pexels-photo-<id>.jpeg?...`, в разы легче mp4),
собрал их в подписанные ID контактные листы через Python+PIL (по 20 превью на лист, ffmpeg
и PIL в среде есть) и отсмотрел Read-ом. **Критерии Артёма: ровно 2 карты в кадре (не 5+ карт
веером — это фокусы/флоуриш, не раздача), нормальный игровой стол, никакой рулетки и общих
казино-сцен.** Ключевая находка: бо́льшая часть покерных тегов на Pexels на самом деле ведёт
на один и тот же глянцевый фотосет «люкс-казино» (люстра, синее сукно, вечерние наряды) —
внутри он почти всегда о рулетке (виден стол ODD/EVEN или колесо), не о покере, и текстовый
тег это не показывает, только превью. Из ~135 просмотренных превью годными по критериям
оказались только **17** — не подгонял до 30, доложил как есть. Продуктивнее всего оказалась
серия одного фотографа (RDNE Stock project) «домашняя покерная вечеринка с друзьями» —
обычная гостиная, реальные фишки, не постановочный лаунж; она же почти вся ушла в те 17
через приём related-videos. Итог: в `.business/marketing/stock-pexels-poker/` теперь 56
клипов (39 из первой партии + 17 новых), 1 ГБ.

**Четвёртое правило добавлено 18.08, тем же вечером — важнее трёх предыдущих.** Артём указал:
в кадре должны доминировать карты/фишки/стол, а не человек. Дилер, который активно тасует или
раздаёт карты — нормально (в кадре всё равно доминирует стол и действие с картами). А вот кадр,
где главное — чьё-то лицо или фигура крупным планом, а карты/фишки — мелкая деталь на фоне, не
годится, даже если формально это «покерная сцена» и остальным трём правилам соответствует.
Это НЕ то же самое, что «мало людей» — дело именно в композиции кадра (что занимает площадь),
не в количестве людей.

Проверка задним числом на всех 56 клипах (кадр из реального файла через `ffmpeg -ss 2
-frames:v 1`, не превью с сайта — превью иногда обрезано иначе, чем сам ролик) вскрыла: вся
серия «домашняя покерная вечеринка с друзьями» (RDNE Stock project, id 7683xxx), которую сам
же выделил как лучшую находку вечера в предыдущей заметке — на деле **вся** нарушает это
правило. Это lifestyle-фотосъёмка людей в комнате, где карты — реквизит на фоне, а не предмет
съёмки; по прежним трём правилам (2 карты, нормальный стол, не казино) она проходила легко,
но по четвёртому — нет. Из 17 клипов второй волны выжило только 5. Ещё 3 клипа «дилер стоит
у стола» (id 6259133, 6664997, 6665303, из партии 99, пережили чистку Артёма) при повторной
проверке оказались кадром БЕЗ стола вообще — просто стоящий человек в жилете, тоже под нож.
Итого удалено 16 из 56, осталось **40**. Вывод на будущее: при отборе домашних/lifestyle-серий
(в отличие от предметной съёмки стола) проверять КОМПОЗИЦИЮ кадра отдельным пунктом, не только
контент/сюжет — жанр съёмки (постановочное лайфстайл-фото людей vs предметная съёмка стола)
надёжнее предсказывает результат, чем текстовый тег или беглое описание.

**Возврат к Mixkit 18.08, тем же вечером — проверка 3 отложенных клипов по всем 4 правилам.**
Прямая ссылка на файл не видна в статичном HTML страницы видео (кнопка скачивания — JS,
Stimulus-контроллер `download--video-options`) — WebFetch тут бессилен. Playwright в этот раз
не был занят чужой сессией, зашёл им: `browser_navigate` → `browser_take_screenshot` даёт
реальный кадр для проверки композиции (запасной способ превью, когда у сайта нет статичного
постера) → выбрать разрешение радиокнопкой → клик по кнопке скачивания → Playwright сам
скачивает файл и пишет путь в вывод (`.playwright-mcp\<file>.mp4` в корне проекта) — не нужно
отдельно ловить URL через network-лог, хотя он тоже там виден (`browser_network_requests`
с фильтром `mp4|active_storage`). Из 3 клипов прошёл только 1 (id 100405 — ровно 2 карты
крупным планом, лица нет, уже вертикальный) — 2 других отсеяны по тем же правилам, что и
на Pexels (веер 5+ карт / вся колода в движении, не раздача). Файл скачался 68 МБ хотя на
странице для другого разрешения был указан размер 6.43 МБ — не ошибка, просто у Full HD
1080×1920 мастер-файла битрейт сильно выше, атрибуты на странице не пересчитались под
выбранное разрешение. Добавлен в `.business/marketing/stock-mixkit-poker/`.

**Рабочий приём: контактные листы через Python+PIL.** Когда кандидатов много (>15), эффективнее
не смотреть по одному Read-ом, а собрать грид с подписями ID через PIL (`ImageDraw` + `paste`,
шрифт `arial.ttf` если есть, иначе `ImageFont.load_default()`) по 15-20 превью на лист — сильно
экономит вызовы инструмента при разборе больших пачек. Для проверки уже скачанных файлов —
`ffmpeg -y -ss 2 -i <file> -frames:v 1 -q:v 4 <out>.jpg` на каждый, потом тот же приём с гридом.
