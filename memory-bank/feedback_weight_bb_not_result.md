В `.business/marketing/calendar-2weeks-texts.md` у каждой раздачи в шапке указан «вес решения N ВВ»
(`weightBb`) — это внутренняя метрика тренера для ранжирования/отбора раздач под контент
(см. [[project_decision_critical_hands]]), она НЕ равна реальному выигрышу или потере фишек в
раздаче. Иногда отличается в разы (пример ниже — 180 против 52).

**Why:** 2026-08-06, при добавлении названия YouTube для дня 3 (блеф 9♠A♦) взял цифру «180,1 ВВ»
из шапки источника и написал в заголовке «180 ВВ на одном блефе», решив, что это размер выигрыша.
Артём переспросил «какие были 180 блендов? И что выиграл 50 блендов?» — поймал нестыковку. Пересчёт
из реального HH-файла (`GG20260309-1615...txt`): блайнд на тот момент 100 фишек, Hero вложил 5036,
забрал 10292, чистый выигрыш 5241 фишка = 52,4 ВВ. Разница с «весом решения» (180,1) — почти
четырёхкратная. В самих текстах постов (Instagram/Telegram/описание YouTube) для дня 3 цифра не
использовалась вообще — ошибка была только в заголовке, который я добавил позже отдельным заходом,
уже не сверяясь с HH-файлом заново.

**How to apply:**
- «Вес решения» из шапки каждого дня — только для внутренней сортировки/выбора раздачи под контент,
  никогда не для текста поста/заголовка/подписи, адресованного игроку.
- Если в тексте нужна цифра выигрыша/потери в ВВ — считать по реальному HH-файлу: чипрезультат
  раздачи (сумма, которую унёс/потерял герой за вычетом вложенного) делить на размер большого
  блайнда НА ТОТ МОМЕНТ турнира (уровень блайндов растёт, брать актуальный, не стартовый).
  См. уже сделанные корректные примеры в файле: день 4 «40 ВВ» и день 5 «155 ВВ» — эти цифры взяты
  из реального вложения/итога, а не из «веса решения» (469,6 и 352,7 соответственно).
- Правило действует при ЛЮБОЙ правке текста для этого календаря, включая точечные («допиши только
  заголовок») — сверка с HH-файлом не одноразовая на этапе написания текста, а при каждой новой
  цифре, которая попадает в публикуемый текст.
