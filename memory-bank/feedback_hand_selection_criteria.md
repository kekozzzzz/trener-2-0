При выборе раздач для маркетингового контента (Reels, карусели, любые будущие ролики) — отбирать
такие, которые сам тренер выбрал бы для разбора пользователю (critical hands / decision-weight
логика продукта, [[project_decision_critical_hands]]), а не просто топ по весу из сырого скана
архива (`hand-scan/candidates.md`).

**Why:** 2026-08-03, при пересборке дней 4/5/7 календаря Reels — раздача дня 5 (AT, чоп) была
выбрана из канала BIG_CALL_WON просто по месту в топе веса. После починки текста под реальный
HH-файл Артём всё равно забраковал её: «дележка вообще не интересна», сравнил с эталоном Reel 1
(флеш-дро, −14 ВВ) — там чёткий вывод и боль, а у чопа «ты всё сделал классно, но не за что
зацепиться». Заменили на другую раздачу из того же канала (TQ, +18582 фишек, чистая победа без
дележа) — она сама по себе интереснее сюжетно.

**How to apply:**
- Раскладка по каналам (BIG_FOLD/WON_BLUFF/MISSED_VALUE/FOLD_INVEST/BIG_CALL_WON/
  WON_VS_NARROW_RANGE) — это только предфильтр по типу решения, не готовый плейлист.
- Внутри канала выбирать не по первому месту в списке, а по тому, есть ли у раздачи чёткий
  сюжет: понятная боль/выигрыш, однозначный вывод, к которому зритель может «прицепиться» —
  так же, как продуктовый движок критических раздач ранжирует по decision-weight, а не по
  сырому чипрезультату.
- Дележи (chop), раздачи без явного вывода («ты всё сделал правильно, и что?») — низкий
  приоритет для контента, даже если чипвес большой.
- Перед тем как писать текст под раздачу — сверять с реальным HH-файлом (уже было правило,
  [[feedback_new_fact_check_negative_case]]), но ЭТОГО не хватает: нужно ещё до траты времени
  на текст спросить себя «тренер бы это показал пользователю как важный момент?».
