Большая фича: тренер помнит историю игрока по всем турнирам/дням, ловит повторяющиеся споты
(«такой же спот, как тогда»), тычет в несогласованные решения, обновляет профиль в Аккаунте.
План: plans/2026-06-28-память-спотов.md.

**Железное условие (Правило 1):** похожесть считает ПАРСЕР детерминированно (отпечаток спота),
LLM только проговаривает уже найденные РЕАЛЬНЫЕ раздачи. Метку «один-в-один / похожее» ставим
по числу совпавших признаков, не модель — иначе выдумает совпадения.

**Отпечаток (решено с Артёмом):** позиция + роль префлопа + глубина стека (SHORT≤15/MID/DEEP>35bb)
+ улица + текстура борда + как Hero попал (собрал/пара/дро/ПРОМАХ). Пример «три-флеш-доска без
попадания» = MONOTONE+WHIFF. Совпадение градуируем по штукам.

**Память 2.0 — ГОТОВА В КОДЕ 2026-07-05 (план plans/2026-07-05-память-тренера-2.md), НЕ задеплоена**
(правка боевого промпта — на прод по команде Артёма). Причина: Артём разбирал раздачи и память ни
разу не сработала (окно 200 раздач ≈ 1-2 турнира; постфлоп-доезды не набирали 5/6; подача «если
естественно» — тренер молчал). Сделано:
- Окно = последние 100 турниров (config/memory.ts), запрос двухфазный: лёгкая выборка id+spot →
  скоринг в памяти → детали только для топ-3.
- Второй канал «ТА ЖЕ ОШИБКА»: features/memory/spot-marks.ts — метки при парсинге в тот же JSON

  LUCKY_WIN (доезд, улица+эквити). Совпадение метки проходит БЕЗ порога отпечатка → SAME_MISTAKE.
- PriorSpot: + mistake (человеческая подпись), + verdict (вердикт ТОГО прошлого разбора, обрезан
  по слову, 300 симв.), when = всегда дата + турнир.

  Замысел Артёма: «тренер реально помнит тебя как игрока» — доверие, вау-эффект.
