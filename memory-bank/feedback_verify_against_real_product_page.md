При сборке `/example` (публичная страница-пример полного разбора, `plans/2026-08-17-публичный-пример-разбора.md`) взял
визуальный стиль иллюстративной превьюшки с главной страницы (`ProductWindow` с путём-строкой, цветные
чат-пузырьки `ChatLine`, уголки `CornerMarks`) для показа стола/диалога/вердикта — решил, что раз
компонент уже есть на сайте, можно переиспользовать. Артём поймал глазами: «Оно же так не будет по
факту» — оказалось, реальная страница разбора (`app/tournament/[id]/hands/[handId]/page.tsx`) вообще не
использует `ProductWindow` и чат-пузыри: стол там голый (другой `baseWidth`), вопрос — обычный текст с
меткой «Вопрос N», ответ — простая рамка `border-border`, вердикт — заголовок `<h2>` + рамка
`border-primary`, без уголков и цветных лейблов.

**Why:** design-system.md прямо запрещает «рисовать на витрине то, чего нет в продукте» (правки
2026-08-09), но это правило легко нарушить неосознанно — не соврав фактами, а просто взяв «похожий»
компонент, который на деле живёт в другом контексте (маркетинговая иллюстрация формы продукта на
главной, не сам продукт). Компонент существует и выглядит уместно — это не значит, что он используется
там, где выдаёшь его за настоящий экран.

**How to apply:**
- Перед вёрсткой любой страницы с обещанием «настоящий экран / как в продукте» — сначала прочитать код
  РЕАЛЬНОЙ продуктовой страницы (не лендинга, не showcase-секции), скопировать оттуда классы/структуру
  один в один, а не собирать по памяти или по аналогии с похожим местом на сайте.
- Маркетинговые компоненты (`ProductWindow`, `ChatLine`, `CornerMarks` на главной) — это витрина ФОРМЫ
  продукта, помечены как иллюстрация (design-system.md §4.1 п.13). Использовать их можно только там же,
  на маркетинговых страницах — не как замену настоящему UI при показе «вот как оно реально устроено».
