**Что это.** Раньше, если игрок в диалоге не отмечал диапазон соперника на сетке (отвечал текстом), тренер либо молчал про диапазон, либо (баг) брал факт «эквити против ОДНОЙ вскрывшейся руки» (`preflopAllInEquityLine`, parser/facts.ts) и заговаривал вокруг него языком диапазона — «спектр тебя доминирует», хотя диапазон никто не считал. Игроку это читалось так, будто он обязан был знать точную руку соперника (жалоба Артёма 26.07 на раздачу 179eec8d: KQo олл-ин против CO, вскрылась AA, вердикт сказал «эквити 12.7%, диапазон доминирует»).

**Проверка матчапа (важно, не перепроверять):** 12.7-12.9% для KQo vs AA — ПРАВИЛЬНОЕ число, не баг. Проверено полным перебором всех C(48,5) досок движком проекта И внешним источником cardfight.com (86.92%/12.68% win + tie). Я сначала ошибочно предположил ~24% по памяти — неверно.

**Решение (разбор с Артёмом 26.07):** подставлять вместо пропущенной разметки НАШ эталонный диапазон 3-бета для позиции соперника, с поправкой на тип конкретного соперника (NIT/FISH/LAG), если он известен УВЕРЕННО (`confidence: "solid"`, иначе не гадаем). Это «эталон для нас» (расчёт), не «эталон для игрока» — нельзя подавать как «ты обязан был это знать».

**Область — сознательно узкая:** только спот «Hero открылся одним рейзом → ровно один соперник сделал 3-бет → Hero ответил ОЛЛ-ИНОМ» (детектор `detectHeroOpenFacedThreeBet`, parser/vs-open-3bet-faced.ts). Колл вместо олл-ина, сквиз, лимп впереди, 3-бет от BB (свой чарт защиты) — факта нет, как и раньше. Постфлоп-диапазоны сюда не входят вообще.

**Важное архитектурное уточнение решения 2026-07-03** ([[project_range_engine]]): «эквити только постфлоп, префлоп не считаем — приближения противоречат идее» — это НЕ универсальный запрет, а про ПРОИЗВОЛЬНЫЕ постфлоп-линии (там ещё есть решения впереди, прикидка искажает дальнейшую игру). На закрытом префлоп-олл-ине (деньги уже все в банке, дальше нечего играть) честная Монте-Карло оценка эквити против диапазона — легитимный факт, Артём это прямо подтвердил («тут же преф-олл-ин уже пошли, выставляемся — тут как раз можно посчитать»). Новая функция `equityVsRangePreflop` (parser/cooler.ts): совместное сэмплирование (villain-комбо + борд на каждой итерации, не вложенный перебор) — 40k прогонов, тот же порядок точности, что у `equityVsHandPreflop`.

**Реализация:**
- `parser/vs-open-3bet-faced.ts` — детектор споты, зеркало `vs-open.ts`.
- `config/poker/vs-open-chart.ts` — `referenceThreeBetRange(pos, opponentType?, confidence?)`: NIT(solid) → только велью; FISH/LAG(solid) → база+`withTolerance` (тот же инструмент, что у грейдера спью-3-бета); иначе — база велью+блеф.
- `parser/cooler.ts` — `equityVsRangePreflop`.
- `infrastructure/adapters/llm/types.ts` — поле `estimated: boolean` в `RangeRead`.
- `infrastructure/queue/steps/range-facts.ts` — фолбэк в `buildRangeReads`, когда `extractRangeNotation` не дала кодов.
- `config/prompts/hand-analysis.ts` (`renderRangeReads`) + `config/prompts/verdict.ts` — явная маркировка ОЦЕНКА в тексте промпта, запрет смешивать с фактом о вскрывшейся руке в одной фразе. Формулировку одобрил Артём 26.07 («доверяю больше тебе»).

План: `plans/2026-07-26-эталонный-3бет-диапазон.md` (завершён). 1325 тестов зелёные, tsc/build чисты, вручную проверено на раздаче 179eec8d.

**Бэклог (не в этом плане, сознательно):** та же идея для других префлоп-спотов, где уже есть эталонные чарты (защита BB, изоляция, сквиз, ресстил) — отдельный план, не смешивать.
