**НЕДОДЕЛКА после ревизии памяти 2026-07-16.** Состав файлов и индекс у двух копий сведены
и идентичны. Но **тело 15 записей различается**: в одних полнее локальная копия, в других —
репозиторная (облачные сессии с планшета дописывали своё, и до компа это не доехало, и
наоборот).

**Почему это опасно:** Клод за компом и Клод на планшете помнят РАЗНОЕ по одной теме. До
ревизии облачный вообще не знал 21 записи — включая боевую модель и правило «не деплоить во
время разбора». Сейчас не знает деталей по 15.

**⛔ Нельзя копировать скопом ни в какую сторону — потеряются факты.** Проверено: полнее то
одна сторона, то другая. Свести можно только руками, читая обе версии и делая ОБЪЕДИНЕНИЕ
фактов (не выбор «кто длиннее»).

**⚠️ Список живой — сверять скриптом, а не верить этому файлу.** Пока шла ревизия 16.07,
параллельная сессия дописала ещё одну запись, и список тут же вырос с 15 до 16. Пока правило
«правь ОБЕ копии» ([[feedback_memory_sync]]) не вошло в привычку, расхождения будут прибывать.

**Метод (по одной записи за раз):**
1. Прочитать ОБЕ версии целиком.
2. Собрать объединение фактов. Конфликт («задеплоено» vs «не задеплоено») — **проверить по
   реальности** (`git merge-base --is-ancestor <sha> origin/master`, ssh на прод, grep по коду),
   а не выбирать на глаз: 16.07 пять записей врали, и все вскрылись только проверкой.
3. По ходу применить [[feedback_memory_sync]]: статусы/даты/коммиты — в тело файла, в индекс
   только суть. Явно протухшее — удалить, сначала убрав ссылки на него из других записей.
4. Записать одинаковый результат в ОБЕ копии, сверить `cmp`.
5. Свериться скриптом: расхождений 0, сирот 0, висячих `[[связей]]` 0.

**Свериться — рабочий скрипт (запускать из корня репо, он же даёт актуальный список):**
```bash
node -e "
const fs=require('fs');
const L='C:/Users/Артем/.claude/projects/c--Users-------Desktop--------2-0/memory', R='memory-bank';
const a=fs.readdirSync(L).filter(f=>f.endsWith('.md')), b=fs.readdirSync(R).filter(f=>f.endsWith('.md'));
const diff=b.filter(f=>{try{return fs.readFileSync(L+'/'+f,'utf8')!==fs.readFileSync(R+'/'+f,'utf8')}catch{return true}});
const idx=fs.readFileSync(R+'/MEMORY.md','utf8');
const refs=new Set([...idx.matchAll(/\]\(([a-z_0-9]+\.md)\)/g)].map(m=>m[1]));
const orph=b.filter(f=>f!=='MEMORY.md'&&!refs.has(f));
const names=new Set(b.map(f=>f.replace(/\.md\$/,'')));
let bad=[]; for(const f of b) for(const m of fs.readFileSync(R+'/'+f,'utf8').matchAll(/\[\[([a-z_0-9-]+)\]\]/g)) if(!names.has(m[1])) bad.push(f+'→'+m[1]);
console.log('файлов:',a.length,'/',b.length);
console.log('расходятся:',diff.length,diff);
console.log('сироты (невидимы для сессий):',orph);
console.log('висячие связи:',bad);
"
```
**Норма:** файлов поровну, расхождений 0, сирот 0 (кроме намеренного архива в конце индекса),
висячих связей 0 (кроме `red-lines-risks` — заготовка на будущую запись).
16.07 этими проверками нашлись 4 сироты (одна — живое ограничение GipsyTeam, способное
стоить бана) и 37 битых связей (разнобой дефис/подчёркивание в именах — чинится заменой
`-`→`_` с проверкой, что такой файл есть).
