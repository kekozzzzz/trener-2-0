Артём прислал 4 референсных видео и попросил разобрать их предельно плотно (15-20 кадров/сек,
контактными листами) + звук через [[project_audio_listening_capability]], найти всё, что мы
сейчас не делаем, и потом реализовать все находки в реальном коде, переделав
[[project_reel_your_stakes]].

**Важное уточнение по ходу (не ошибка метода, ошибка атрибуции):** все 4 референса оказались
НАШИМИ ЖЕ роликами (IMG_2446=reel-anchoring, IMG_2787=reel-your-hands, IMG_2888=decision-weight
свежий экспорт, IMG_2489=более ранняя версия decision-weight), с ручной докруткой Артёма поверх
нашего экспорта. Прямое сравнение хука IMG_2888 с нашим `reel-decision-weight-remotion-v18.mp4`
на том же таймкоде показало ПОЛНОЕ совпадение размера/положения текста «Ты/фолдишь» — то есть
для хука decision-weight Артём почти ничего визуально не поменял, только звук.

**Одна находка ОТКЛОНЕНА и не должна попадать в списки снова**: чёрно-белое видео в начале
IMG_2787 — Артём прямо сказал, что видеоряд не трогали, я сам собирал его в прошлой сессии;
чб — просто свойство конкретного стокового клипа, не осознанный приём «чб=проблема,
цвет=решение». Не предлагать это как технику.

**14 валидных приёмов и их реализация** (все — переиспользуемые компоненты/пропы в
`remotion-reels/src/components/`, не разовые хаки под один ролик):

1. Копящийся текст (строки остаются друг под другом) → `BuildUp.tsx` (новый компонент).
2. Растущее слово, к концу вылезает за края кадра → `PhraseBeat` `anim="grow"`.
3. Полая обводка без заливки (третий geometric-голос) → `PhraseBeat` `anim="outline"`.
4. Тихая концовка без героя/нажима → `PhraseBeat` поддерживает heroIndex=undefined (раньше без
   hero текст вообще не рисовался — это был реальный пробел, найден и закрыт).
5. Белый элегантный курсив для переходных слов (не героев) → `PhraseBeat`
   `heroStyle="elegant"` + новый шрифт `fontElegant` (Playfair Display italic, fonts.ts).
6. Печать по буквам → `PhraseBeat` `anim="type"` (прогресс по первым 70% длительности фразы).
7. Глитч/цветная интерференция → `Glitch.tsx` (новый компонент, стилизованные полосы со
   сдвигом, не настоящий RGB channel-split исходного видео — технически проще, визуально
   похоже).
8. Анимированная рука-курсор у CTA → `PointerIcon.tsx` (новый компонент).
9. Рамка-«кнопка» вокруг текста → `PhraseBeat` проп `boxed`.
10. Тик на КАЖДОМ появлении текста → `sfx/real/tick-real.mp3` (новый, Freesound CC0, id 448081,
    0.032с) + массив `TICK_AT`, покрывающий каждую фразу. Самая надёжная находка — подтверждена
    в 4/4 референсах независимо.
11. Звук по СМЫСЛУ слова, не по содержанию клипа → отдельный массив `WORD_SFX` в YourStakes.tsx
    (пример: звук колоды на слове "раздачу", не привязан к тому, что видно в кадре).
12. «Тихий» одно-слово-минимализм для проходных фраз → покрыто пунктом 4 (тихая фраза).
13. Текст переживает жёсткий видео-склейка без re-sync → не требовало кода, уже так работает
    архитектурно (тайминг фраз независим от таймингов клипов).
14. Три курсивных голоса + жирный impact + outline + elegant = теперь ПЯТЬ типографических
    голосов у PhraseBeat, не два («шрифтов будто только 2» — жалоба Артёма от того же дня,
    закрыта с запасом).

**Технический пробел, найденный и закрытый по ходу**: `PhraseBeat` до этой правки требовал
heroIndex для рендера ЛЮБОГО текста в layout center/split — без героя ничего не рисовалось.
Добавлена отдельная ветка для полностью «тихой» фразы (весь текст одной строкой обычным телом,
без иерархии hero/pre/post).

**v5 итог**: `generated/reel-your-stakes-remotion-v5.mp4` (26.5с). Все 14 приёмов проверены
кадрами после ПЕРВОГО рендера — сработало без единой правки (в отличие от decision-weight,
которому потребовалось 18 итераций на куда меньший набор изменений) — эффект переиспользования
уже откалиброванных компонентов и того, что находки были предварительно проверены на
референсах, а не придуманы на глаз.

**How to apply дальше**: все 5 новых файлов/пропов — стандартный инструментарий для будущих
роликов, не только для этого. `TICK_AT`-паттерн (тик на каждой фразе) — переносить по умолчанию
на все новые ролики этого уровня продакшена. При новых референсах — ПЕРВЫМ делом проверять,
не наш ли это ролик (сравнить текст озвучки с `generated/reel-*.txt`/`*-narration.txt`), прежде
чем разбирать как чужой опыт.

**2026-09-04, тот же день — реальная ошибка анализа, найдена и исправлена по фидбеку Артёма:**
приём №7 ("глитч/интерференция") был ПРИДУМАН мной, а не реально увиден в референсе. Первый
разбор IMG_2787 шёл на 15fps — на этой плотности статичное полупрозрачное фоновое слово
(та же находка №2, просто другое слово в другом ролике) выглядело как "нечёткая рябь", и я
ошибочно классифицировал это как отдельный мигающий эффект и реализовал `Glitch.tsx` со
случайным покадровым джиттером полос. Артём поймал результат сразу: "6-7 прямоугольников
мигают, может эпилепсию вызвать" — методологически важная поимка, не просто вкусовщина.
Пересмотр ТОГО ЖЕ фрагмента на 30fps (15 кадров подряд отсмотрены по одному) показал: эффект
абсолютно статичен, ни одного сдвига между кадрами. `Glitch.tsx` выведен из употребления
(файл оставлен в дереве — может пригодиться для реально нужного глитч-эффекта в будущем),
заменён на `GhostWord.tsx` — статичный вариант находки №2, переиспользуемый.

**Урок про плотность разбора референсов**: Артём (со ссылкой на собственное исследование)
сообщил, что анимации в подобных роликах обычно монтируются на 60 или 120 fps. Для КОНТЕНТНОГО
разбора (что где написано, какие приёмы есть) 15fps достаточно. Для ПРОВЕРКИ ХАРАКТЕРА
ДВИЖЕНИЯ (плавное/дискретное, есть ли джиттер, куда и как двигается элемент) — обязательно
пересматривать конкретный узкий момент на 30-60fps (источники этого проекта — 120fps нативно,
60fps = каждый второй кадр, этого достаточно). Дешёвая проверка: если находка описывает
ДВИЖЕНИЕ (мигает/дрожит/скользит/жмёт) — сначала смотреть плотно, потом писать код, не наоборот.

**Курсор-указатель**: пересмотр IMG_2446 на 60fps (96 кадров, 1.6с) показал, что курсор в
референсе не столько "жмёт" на кнопку рывком, сколько ДОЛГО СТОИТ статично (пока строится
текст "«разбор»" по буквам), а затем МЕДЛЕННО СДВИГАЕТСЯ влево-вниз — больше похоже на
артефакт записи экрана телефона (точка касания), чем на спроектированную анимацию "нажатия".
Артём тем не менее прямо попросил "должен нажимать на кнопку, которую ты специально сделал" —
явное указание к реализации, не обязательно копия референса 1-в-1. `PointerIcon.tsx` получил
асимметричный цикл движения вниз-вверх (не просто пульсация масштаба на месте).
