БУДУЩАЯ ФИЧА (идея Артёма 2026-07-01, «научить парсер подстраиваться под дураков»): тренер учитывает ТИП оппонента, чтобы правильно ставить его на диапазон — чем рыбнее, тем шире опен/3-бет; бывает перекос «широкий опен + узкий 3-бет» (лузо-пассив: открывает всё, 3-бетит только премиум). Сейчас парсер оппонентов НЕ профилирует (только метрики Hero + факты спота + стеки оппонентов для SPR); диапазон злодея отдан ИИ/клику по сетке.

## Деление по Правилу 1
Парсер ТИПИЗИРУЕТ оппонента (детерминированно: частоты + ярлык архетипа), тренер (ИИ) ПОДСТРАИВАЕТ совет/диапазон под ярлык. Парсер не стратег, ИИ не выдумывает статы.

## Три источника сигнала (иерархия приоритета: сильное перебивает слабое)
1. **Явный ридс игрока в диалоге** — САМЫЙ сильный. Тренер спрашивает «что знал про оппонента?»; игрок говорит «отбитый, лез отовсюду» → ИИ перестраивает диапазон. Чистая работа ИИ (качественный ридс), Правило 1 не трогает. ⚠️ ГАРД (та же мина, что с дельтой [[project_personal_chart_memory]]): ридс не должен стать ОТМАЗКОЙ — «он фиш» не оправдывает автоматически любой лузовый колл, сократовский вопрос не выключаем.
2. **Приор парсера со вскрытий/частот** — средний. Вскрытий мало (1-2 на оппонента за турнир) → это не «процент», а разовый ТЕЛЛ: показал 92o в опене → «может лезть с мусором». Мягкий приор, не приговор («ориентироваться, не знать точно»). Частоты (VPIP/PFR) типизируются только на длинных соседях; 3-бет почти никогда не набирает выборку.
3. **Общий дефолт** — если сигналов нет.

## Ключевые ограничения (проверено 2026-07-01)
- **НЕ ПОКАЗЫВАТЬ игроку** тип/статы оппонента. Два довода: (а) показ меток = HUD, GG это ЗАПРЕЩАЕТ и банит (пост-разбор своих рук ок, как PokerTracker; показ меток на оппонентов — нет); (б) сократовская душа — не суём «вот дурак, эксплуатируй», тренер держит приор в уме и строит вопросы. Внутренний приор, не экранный ярлык.
- **Выборка на оппонента в МТТ крошечная** (десятки рук за турнир, столы ломаются): VPIP/PFR — грубо на длинных соседях, 3-бет — почти нет. Жёстко гейтить, мало рук → «тип не определён», не гадать.
- **GG: псевдонимы стабильны ВНУТРИ турнира** (110 раздач → 29 id, за человеком следить можно), но НЕ кросс-турнирно (в след. турнире другой хеш, GG режет). Профиль живёт в рамках текущего турнира. PS/Winamax/888 — ники стабильны, теоретически можно копить между турнирами (др. модель данных).
- Карты оппонента видим только на вскрытии → «какой был диапазон» в основном вывод из действий, не факт.

## Реализация (черновик, крупная фича)
Парсер по каждому оппоненту в турнире: частоты (опен/лимп/3-бет/фолд-на-3-бет) + разовые теллы со вскрытий → архетип (тайт/лузо × пассив/агро, + рыба/рег) при достатке выборки, иначе «не определён». Отдаётся тренеру ФАКТОМ (внутренним), тренер двигает диапазон + может спросить ридс у игрока. Рядом с [[project_opponent_range_grid]]. План plans/2026-07-01-профиль-оппонента.md.
