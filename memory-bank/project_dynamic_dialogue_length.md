2026-06-27: переработана схема длины диалога. Было — фикс ~5 раундов, вердикт по
счётчику в `submitAnswer` ДО прочтения ответа («заранее написанный вердикт»). Стало —
длину задаёт ИИ по смыслу ответа: флаг `complete` в `NextQuestionResult`, решает шаг
`GENERATE_DIALOGUE_QUESTION` (он и так идёт после ответа). Понял с первого → 1 раунд;
надо копать → до 12. `DIALOGUE_ROUNDS_PER_HAND` (env, имя не менял) переосмыслен как
ПОТОЛОК, дефолт 12; функция `getDialogueRoundsPerHand`→`getDialogueMaxRounds`.

Правило 2 цело: вердикт только из `ANSWER_RECEIVED` (страж состояния), снята лишь
проверка «ровно N-й раунд» в `GENERATE_VERDICT`. Идемпотентность done-пути — по
`dialogue.verdict`. Fake-адаптер завершает диалог на слове «понял» (дев-сигнал).
