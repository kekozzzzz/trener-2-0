Фича 2026-07-04 (запрос Артёма: «в критические берутся только потери, а где повезло — не разбираются»; план plans/2026-07-04-критические-по-доезду.md). ЗАДЕПЛОЕНО LIVE 2026-07-04 (4ad25b8, /health ok).

Как устроено (Правило 1, без LLM):
- Парсеры ВСЕХ румов вытаскивают вскрытые на шоудауне карты соперников в снимок (`Seat.shownCards`): общий `parser/shared/shown-cards.ts` (строки «ник[:] shows [Xx Yy]» — GG/PS/Chico/888/WPN/Winamax) + iPoker XML (`pocketCardsByNick`, Pocket ≠ «X X»). Обезличивание цело: карты цепляются к «Player N».
- `parser/lucky-win.ts` `detectHeroLuckyWin`: последнее существенное постфлоп-вложение Hero (≥ max(5 BB, 10% старт-стека)) → эквити честным перебором против вскрытой руки (эвалюатор made-hand) на борде той улицы; < 33% и раздача выиграна = доезд. Префлоп сознательно не считаем. Несколько вскрытых — минимум эквити.
- Отбор (`ggpoker/classify.ts`, общий всем румам): доезды добирают ОСТАТОК потолка критических (7) после потерь; сортировка по выигрышу. Широкие входы НЕ сюда — они в общей картине (решение Артёма).

Работает только для НОВЫХ загрузок (старые раздачи размечены в БД). Живая проверка на реальном GG-файле: 110 раздач, 30 со вскрытием, 0 доездов в том турнире (детектор строгий) — ждём подтверждения на файле с реальным доездом. 10 тестов (__tests__/parser/lucky-win.test.ts).
