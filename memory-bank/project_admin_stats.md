Вкладка «Статистика» (/admin) — только владельцу (isAdminEmail, остальным 404):
регистрации/входы по дням и периодам (сутки по МСК, env ADMIN_TZ_OFFSET_HOURS деф.3),
страны за 30 дней, пробник+конверсия, подписки, деньги, загрузки, активность,
расходы ИИ (переиспользован buildCostReport), очередь. Собрано и проверено локально
2026-07-02 (миграция 20260702123840_add_auth_events, 568 тестов, build ок), задеплоено.

Журнал auth_events (append-only): REGISTER / LOGIN_PASSWORD / LOGIN_MAGIC / LOGIN_FAILED,
пишется во всех 4 точках входа, ошибки глушит (вход не ломает). Хранится только ISO-код
страны через локальный `geoip-country` (пакет в serverExternalPackages — базу нельзя
бандлить); IP НЕ хранится. Регистрации в статистике считаются по Player.createdAt
(полная история), входы — только с деплоя журнала.

**При деплое проверить:** (1) проброс X-Forwarded-For/X-Real-IP на КЗ-релее
(92.60.75.87) — иначе страны у всех NULL/KZ (clientIp в rate-limit.ts берёт первый
XFF); (2) миграция применится сама (instrumentation.ts → migrate deploy), в ней ещё
выравнивание hands.viewed_at до TIMESTAMP(3) — безопасно.

⚠️ Системная особенность репо: prisma migrate dev при КАЖДОЙ новой миграции суёт в
сгенерированный SQL «починку» ручных partial-индексов (WHERE deleted_at IS NULL,
Prisma DSL их не умеет) — файл миграции ЧИСТИТЬ руками перед применением. Локальные
журналы миграций trener_dev/trener_test были в рассинхроне (колонки мимо миграций,
failed-запись с 17.06) — выровнены 2026-07-02 через migrate resolve без потери данных;
migrate reset запрещён deny-листом. [[project_deploy_procedure]] [[project_i18n_english]]

**2026-08-18 — владелец исключён из «Входы» и «Заходы на сайт».** Артём попросил, чтобы
его собственные заходы на сайт (проверка/тестирование под своим аккаунтом) не раздували
эти два счётчика на /admin — до этого оба считали вообще любого залогиненного/анонимного
без исключений (в отличие от регистраций/денег/подписок, которые уже фильтровались через
`getExcludedTestPlayerIds`, [[project_owner_comp_access]]).

- `features/admin/stats.ts` — «Входы» (`authEvent`, kind LOGIN_PASSWORD/LOGIN_MAGIC):
  добавлен `adminIds` (Player.email из `getAdminEmails()`), объединён с тестовыми ID в
  `notAdminOrTestPlayer`. Применяется и к общему счётчику (`db.authEvent.count`), и к
  30-дневной выборке — там фильтр JS-стороной (`isExcludedPlayer`), не через Prisma
  `notIn` в самом запросе, потому что `AuthEvent.playerId` нулевой у неудачных попыток
  по несуществующему email, а SQL `NOT IN` с NULL в списке молча роняет такие строки.
  Сработало и ЗАДНИМ ЧИСЛОМ — у входов playerId был всегда, так что прошлые входы
  владельца тоже перестали учитываться.
- `app/api/track-visit/route.ts` — «Заходы на сайт» (`SiteVisit`): перед записью строки
  теперь читает сессию (`getSession`) и проверяет `isAdminEmail` — если это владелец,
  строка не пишется. Работает ТОЛЬКО вперёд: у `SiteVisit` вообще нет поля `playerId`
  (анонимный маячок), поэтому старые визиты владельца, уже накопленные в счётчике,
  задним числом почистить нельзя без правки схемы БД — её не трогал без отдельного «да»
  (правило проекта, «Спроси разрешения, прежде чем... изменить схему БД»).
